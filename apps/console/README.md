# @repracer/console — консоль продавца на стенде

Интерфейс шагов 11–12 [Р-67…Р-73, [ADR-0010](../../docs/adr/0010-seller-console-on-stand.md), [ADR-0011](../../docs/adr/0011-explanation-stops-roles.md)]. Каналы не подключены. Данные берутся из сценариев стенда [tests/contract/fixtures](../../tests/contract/fixtures/). Все данные и пользователи синтетические.

## Запуск

```sh
STAND_IDENTITY=simulator npm run stand -w @repracer/console   # сервер стенда с имитатором поставщика identity: http://127.0.0.1:4318/api/session (STAND_PORT)
STAND_IDENTITY=simulator REPRACER_PG_URL=postgres://svc_app@…/repracer_eu npm run stand -w @repracer/console   # то же на PostgreSQL
STAND_IDENTITY=oidc OIDC_ISSUER=https://… OIDC_AUDIENCE=… OIDC_JWKS_URL=https://… npm run stand -w @repracer/console   # настоящий поставщик (не прогонялось, OQ-141)
# Без STAND_IDENTITY, при неполных OIDC_* или при OIDC_* рядом с имитатором сервер не запускается (находка 6 ревью шага 14)
npm run dev -w @repracer/console     # интерфейс: http://127.0.0.1:5173, /api проксируется на стенд
npm test -w @repracer/console        # вход, роли, API на двух языках, серверный рендер, остановки с аудитом, включение, тайм-аут
```

Перезапуск сервера на памяти возвращает миры к состоянию после сценариев. На PostgreSQL каждый запуск засевает новые тенанты.

## Вход и язык

- **Вход [Р-78].** Паролей и сессий у нас нет: вход, MFA, сброс пароля и приглашения — у поставщика identity ([ADR-0013](../../docs/adr/0013-external-identity-provider.md)). Каждый запрос несёт токен поставщика в `Authorization: Bearer`; сервер проверяет подпись, издателя, получателя и сроки ([packages/identity](../../packages/identity/)). Недействительный токен — ответ 401, как без токена. Консоль держит токен только в памяти страницы.
- **Учётные записи стенда.** Поставщика заменяет локальный имитатор: кнопки «Войти как …» выдают токен синтетического пользователя роли (`owner@`, `admin@`, `operator@`, `pricing-manager@`, `viewer@stand.repracer.test`). Ключ имитатора создаётся в памяти при запуске; имитатор включается только явным `STAND_IDENTITY=simulator`.
- **Сессия.** Cookie `repracer_session` (`HttpOnly; SameSite=Strict`) живёт 12 часов. В хранилище — только SHA-256 токена; выход закрывает сессию.
- **Роли.** Роль не хранится в сессии: членство в мире читается из хранилища входа при каждом запросе, на PostgreSQL — из `tenant_data.membership`. Мир без членства пользователю не виден.
- **MFA** — у поставщика; второй фактор входа читается из `amr` токена [Р-88]. Снятие остановки тенанта без него — 403 `MFA_REQUIRED` (сервер, хранилище и БД). Имитатор выдаёт токены с `pwd` и `otp`.
- **Автор действия** — пользователь токена: хранилище (на PostgreSQL — триггеры 0048) принимает остановку, возобновление и снятие только от членства этого пользователя.
- **Права [OQ-129].** Проверяет хранилище пути решения, на PostgreSQL — БД. Сервер дублирует проверку, чтобы ответить 403 до вызова.

  | Действие | Кто может |
  |---|---|
  | Остановить цены | Владелец, администратор, оператор, менеджер цен |
  | Возобновить остановку тенанта | Владелец, администратор |
  | Возобновить остановку аккаунта или витрины | Владелец, администратор, оператор, менеджер цен |
  | Снять системную остановку | Владелец, администратор, оператор, менеджер цен |
  | Включить репрайсинг | Владелец, администратор, оператор, менеджер цен |
  | Превью стратегии | Все роли |
  | Сохранить стратегию, изменить границы (шаг 21) | Владелец, администратор, менеджер цен (MANAGE_PRICING; на PostgreSQL проверяет БД) |
  | Применить правку границ больше одного предложения | То же и второй фактор [Р-88]; на PostgreSQL — страж 0078 |
  | Смотреть экраны | Все роли, включая менеджера остатков и наблюдателя |
- **Язык** — немецкий или английский, хранится в cookie `repracer_locale`. Тексты — словарь `@repracer/console-model` [Р-72].

## Экраны

| Экран | Модель (`@repracer/console-model`) | Что показывает |
|---|---|---|
| Товары | `productList` | Единица записи и текущая цена. **Действующий пол** с разбором «min_price и минимальная маржа», max_price, стратегия. Статусы: включено (остановлено человеком или системой), применяется, последнее изменение, следующая проверка. Кнопка включения репрайсинга: сначала предупреждения, затем «всё равно включить» |
| Почему эта цена | `decisionTrace` | Семь шагов одного решения из слепка объяснения [Р-68], развёрнутого справочниками [Р-75]: снимок, проверка входов, якоря, стратегия, Price Gate, запись, подтверждение канала. Значения канала вне слепка помечены. У решения без изменения цены — код причины и пробел «не хранится» [Р-74] |
| Остановленные изменения | `rejectedView` | Опасные изменения (дальше 10 % от границы) отдельно от скорректированных [Р-73]; остановки человеком, проверка входов, системные остановки |
| Границы | `boundsView` | Действующий пол, min_price, пол по марже, max_price; разбивка цены до цента: налог, комиссии, себестоимость с курсом ЕЦБ |
| Стратегии (шаг 21) | `strategiesView`, `parseStrategyDraft`, `strategyPreviewView` | Стратегии в работе. Черновик → **превью на выбранных офферах до сохранения**: стратегия и Price Gate на последнем принятом снимке, без фиксации и записи в канал (цена сейчас, предложение, после Gate, опасное ли). Сохранение новой версии и назначение — только с токеном показанного превью: сервер пересчитывает превью, изменился итог — 409 |
| Лента цен (шаг 21) | `priceFeed` | Каждая запись цены в канал: было → стало, статус канала, источник (стратегия, ручная цена), причина. Пробел: `price_history` и суточная свёртка консолью не читаются |
| Опасные изменения (шаг 21) | `dangerousReport` | «Границы остановили N опасных изменений» за 1, 7, 30 дней [Р-73]: сумма расстояний до границы по валютам, худшее, по офферам и границам. Длиннее 30 дней — помечается неполным [Р-28] |
| Границы: массовая правка (шаг 21) | `parseBoundsEditRequest`, `expandBoundsEdit`, `boundsDiffView` | Выбор офферов и правка min/max (задать сумму или изменить на б. п.) → **экран различий обязателен**: до и после как вычислит база (откатываемая транзакция), текущая цена вне новых границ, сдвиг больше 10 %, пол по марже выше min_price, правка без эффекта из-за уровня товара. Применение — только с токеном экрана; устаревший экран — 409 |
| Остановка | `stopView`, `planStop` | Два раздела [Р-69]. **Остановка человеком** — все цены: тенант, аккаунты, витрины, в два нажатия с заметкой. **Системные остановки витрин** — только цены по конкурентам, снятие с заметкой. **Журнал аудита**: кто, в какой роли, что и где остановил или возобновил [Р-76] |

Каждый экран выводит блок «каких данных нет для этого экрана» — это пробелы, которые остались после шага 13.

Любой запрос ждёт стенд не дольше 8 секунд. Потом экран показывает ошибку с кнопкой повтора — бесконечного спиннера нет.
