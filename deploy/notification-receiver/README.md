# Развёртывание приёмника уведомлений Amazon [OQ-190, шаг 23]

Процесс `services/notification-receiver` читает очередь SQS приложения: проверяет целостность тела, разбирает конверт, отбрасывает чужое
приложение и неподдерживаемые типы, находит тенанта и аккаунт функцией базы [Р-31, 0083], отсекает повторы по `NotificationId` и доставляет
уведомление в путь решения. Тишина очереди и опоздание доставки — алерты.

**Живой очереди и подписки нет** (OQ-167): развёртывание готово заранее, проверено живым прогоном шага 27 на модели очереди
([docs/evidence/step27-live-background.md](../../docs/evidence/step27-live-background.md)).

## Запуск

```
cp deploy/notification-receiver/receiver.env.example deploy/notification-receiver/receiver.env   # заполнить
docker compose -f deploy/notification-receiver/compose.yaml --env-file deploy/notification-receiver/receiver.env up -d
```

## Что даёт развёртывание

| Требование | Как |
|---|---|
| Одна очередь — один экземпляр | `replicas: 1`: повторы отсекает журнал, но второй процесс удваивает вызовы канала на тех же уведомлениях |
| Одна очередь — один регион | `REPRACER_AMAZON_REGION`; регион очереди сверяется с адресом (SigV4 подписывается регионом очереди) |
| Перезапуск при падении | `restart: unless-stopped`; `/healthz` — 503, если круг опроса не начинался дольше трёх минут (пустая очередь при этом здорова: долгий опрос 20 с) |
| Конфигурация | переменные окружения (`receiver.env`), секреты — файлами: адрес очереди содержит номер аккаунта AWS |
| Метрики | `http://127.0.0.1:9466/metrics`: круги опроса, принятые уведомления, ошибки очереди |

## Секреты

| Файл | Что |
|---|---|
| `app_pg_url` | адрес базы для роли `svc_app` (доставка снимка в путь решения, журнал уведомлений) |
| `inbound_pg_url` | адрес базы для роли `svc_inbound` (маршрут продавца функцией базы — только идентификаторы) |
| `sqs_queue_url` | адрес очереди: `https://sqs.<регион>.amazonaws.com/<аккаунт>/<очередь>` |
| `aws_access_key_id`, `aws_secret_access_key` | ключи AWS для SigV4 |
| `aws_session_token` | временные учётные данные (AssumeRole); файла нет — читаются постоянные ключи |
| `channels/<credentials_ref>` | учётные данные приложения Amazon (LWA) |

## Чего здесь нет

- **Записи в канал**: этот процесс цену не отправляет. Уведомление рождает решение и ждущую запись, а отправляет её диспетчер
  (`deploy/worker`) — так порядок записей держит брокер [Р-64, Р-24].
- **Очереди недоставленных сообщений**: её заводит развёртывание AWS; приёмник рассчитывает на `maxReceiveCount` = 5 (политика приёмника).
- **Подписки на уведомления**: создаётся в SP-API у продавца; до живого аккаунта не проверялась (OQ-167).
