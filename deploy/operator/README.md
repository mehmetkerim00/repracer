# Развёртывание панели оператора [Р-165]

```
docker compose -f deploy/operator/compose.yaml --env-file deploy/operator/operator.env up -d
```

Панель **не публична**: её порт слушает только `127.0.0.1`, обратного прокси у неё нет, домена нет. Оператор открывает её
через туннель:

```
ssh -L 4327:127.0.0.1:4327 <сервер>     # затем http://127.0.0.1:4327
```

Ограничение доступа на уровне сети (firewall, список адресов) — свойство сервера, а не этого файла; в репозитории оно не
описано и ничем не проверяется (OQ-227).

## Файлы секретов в `REPRACER_SECRETS_DIR`

| Файл | Что внутри | Когда нужен |
|---|---|---|
| `operator_pg_url` | `postgres://svc_operator:<пароль>@<хост>:5432/<база>` | всегда |
| `mail_api_key` | ключ провайдера почты | только если задан `REPRACER_MAIL_API_URL` |
| `operator_heartbeat_url` | адрес отметки внешнего контроля [Р-127] | только если `REPRACER_OPERATOR_HEARTBEAT` не `off` |

Без переменных провайдера почты письмо приглашения СОБИРАЕТСЯ и никуда не уходит (сухой режим, OQ-224) — это видно в
журнале строкой `MAIL_DRY_RUN`, а не тишиной.

## В промышленном профиле

`deploy/production/compose.yaml` берёт этот сервис через `extends` и НЕ ставит его за прокси: в `Caddyfile` панели нет.
Смоук развёртываний (`scripts/deploy-smoke.sh`) проверяет обе половины — `/healthz` на порту 9471 отвечает, а через
публичный прокси адреса панели не отвечают.
