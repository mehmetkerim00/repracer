# Развёртывание пути решения за брокером [OQ-190, Р-64, Р-34]

Процесс `services/pricing-worker` делает три вещи:

1. **Отправляет ждущие записи** — диспетчер записей [Р-64]: событие `scope.write.v1` о ждущей записи, обход-страховка раз в
   `REPRACER_WORKER_SWEEP_MS`, подтверждение неизвестного итога обратным чтением.
2. **Обрабатывает снимки конкурентов** из `raw.competitor-snapshot.v1` — путь решения о цене.
3. **Ретранслирует outbox** в брокер [Р-34] — активен тот экземпляр, который взял advisory lock.

Почему это отдельное развёртывание: у планировщика диспетчера нет намеренно (живой прогон шага 27,
[docs/evidence/step27-live-background.md](../../docs/evidence/step27-live-background.md)). Без этого процесса ждущая запись доходит до
канала только обходом-страховкой — позже и мимо порядка брокера.

## Запуск

```
cp deploy/worker/worker.env.example deploy/worker/worker.env   # заполнить
docker compose -f deploy/worker/compose.yaml --env-file deploy/worker/worker.env up -d
```

## Что даёт развёртывание

| Требование | Как |
|---|---|
| Несколько экземпляров | продукт это допускает: порядок внутри единицы записи держат ключ партиции `write_scope_id` [Р-24], одна запись в полёте в базе и последовательные вызовы диспетчера в процессе. Но в этом файле `replicas: 1` — порт метрик публикуется фиксированно; для второго экземпляра нужна копия файла с другим портом |
| Ретранслятор — один | запускается во всех экземплярах, работает тот, кто взял advisory lock [Р-34]; экземпляр без файла `relay_pg_url` ретранслятор не запускает |
| Перезапуск при падении | `restart: unless-stopped`; `/healthz` — 503, если ни обход, ни сообщение не случались дольше трёх обходов (не меньше 2 минут) |
| Остановка без потери записей | `stop_grace_period: 60s`: диспетчер доживает круг, потребители закрываются, смещения не перескакивают |
| Конфигурация | переменные окружения (`worker.env`), секреты — файлами из `REPRACER_SECRETS_DIR` |
| Метрики | `http://127.0.0.1:9465/metrics`: обработанные сообщения по темам, обходы, время работы. Идентификаторов тенантов в метриках нет |

## Секреты

| Файл | Что |
|---|---|
| `app_pg_url` | адрес базы для роли `svc_app` (транзакции тенанта: решение, запись, история) |
| `dispatcher_pg_url` | адрес базы для роли `svc_dispatcher` (обход ждущих записей всех тенантов — только идентификаторы) |
| `relay_pg_url` | адрес базы для роли `svc_relay` (чтение outbox всех тенантов); файла нет — экземпляр без ретранслятора |
| `channels/<credentials_ref>` | учётные данные аккаунта канала: JSON-объект строк; имя файла — `credentials_ref` аккаунта, в котором `:` заменено на `_` |

## Чего здесь нет

- **Брокера и базы**: их развёртывание — вне этого файла; `infra/local` поднимает Redpanda и ClickHouse для проверок.
- **Канала eBay**: адаптера нет до снимка спецификации [Р-112]; сообщение по такому аккаунту — отравленное, с CRITICAL-алертом.
- **Внешней отметки**: у планировщика она есть [Р-127], у этого процесса — нет: его молчание видно по ждущим записям и алертам обхода
  (проверить в среде развёртывания, нужен ли отдельный контроль).
