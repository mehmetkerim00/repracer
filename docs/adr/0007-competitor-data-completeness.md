# ADR-0007: Полнота конкурентных данных по каналам и каталог стратегий

- **Статус:** Accepted
- **Дата:** 2026-09-14
- **Решения:** Р-36 (источник конкурентов Kaufland), Р-39 (стратегия объявляет требуемую полноту), Р-38 (окно бэктеста ≤ 18 месяцев)
- **Реализация:** `CompetitorSnapshot.completeness` в порте ([packages/channel-port](../../packages/channel-port/src/messages.ts)); столбцы `completeness`, `completeness_n` в `channel_data.competitor_state` (миграция 0027) и в ClickHouse (`schemas/clickhouse/030_step6.sql`); разбор источников Kaufland — [packages/kaufland-adapter](../../packages/kaufland-adapter/src/competitors.ts)
- **Связанные документы:** [ADR-0006](0006-channel-port.md), [channel-capabilities.md](../channel-capabilities.md), OQ-38

## Контекст

«Данные о конкурентах» у каналов — разные вещи. Одна стратегия цены хочет знать только победителя Buy Box, другая — самую
низкую цену рынка, третья — своё место среди первых N предложений с учётом доставки. Источник, который отдаёт топ-10 по
рангу Buy Box, не отвечает на вопрос «кто самый дешёвый»: ранг учитывает не только цену. Источник, который отдаёт только
минимальную цену, не показывает, выигрываем ли мы Buy Box.

Если стратегия молча работает на неполных данных, она выставляет неверную цену, и Price Gate этого не заметит: пол цены
соблюдён, но решение принято по неверной картине рынка. Поэтому полнота данных — такое же свойство канала, как лимит
запросов, и проверяется при включении стратегии, а не при расчёте.

## Решение

### 1. Каждый снимок объявляет свою полноту

`CompetitorSnapshot.completeness` — обязательное поле порта:

| Вид | Значение | Пример |
|---|---|---|
| `TOP_N(n)` | Первые n предложений по порядку, который задаёт канал (обычно ранг Buy Box). Предложения за пределами n неизвестны | Kaufland `buy_box_changed`, `GET /buybox` — n = 10 |
| `CHEAPEST_ONLY` | Только минимальные цены (по состояниям); ни ранга, ни победителя | Kaufland `competitors-comparer` |
| `FULL` | Все предложения товара на витрине | Пока ни у одного источника |

Полнота пишется в `competitor_state` (горячая проекция, вход стратегии) и в `competitor_snapshot` (ClickHouse). Бэктест
и симулятор видят, на каких данных принималось решение; окно бэктеста ограничено 18 месяцами [Р-38].

### 2. Каждая стратегия объявляет требуемую полноту [Р-39]

Стратегия описывает требования, а не источник:

| Требование | Смысл |
|---|---|
| `kind` | Минимальный вид полноты: `TOP_N` с `minN` или `CHEAPEST_ONLY`, или `FULL` |
| `needsBuyboxWinner` | Нужна цена и признак победителя Buy Box |
| `needsOwnRank` | Нужен ранг собственного предложения |
| `needsShipping` | Сравнение по цене с доставкой |
| `conditions` | Какие состояния товара нужны (`new`, `used`, …) |
| `maxStalenessSeconds` | Насколько старым может быть снимок в момент решения |

Доступность стратегии на канале и витрине вычисляется из заявленных источников канала (описание адаптера) и требований
стратегии. Недоступная стратегия **не включается**: интерфейс показывает, какого требования канал не обеспечивает
(«Kaufland показывает только 10 первых предложений по рангу Buy Box; самая низкая цена рынка может быть за их пределами»).
Решение фиксируется сейчас; реализация — позже.

### 3. Последствия для классов стратегий

Каталог стратегий ещё не утверждён; ниже — классы, на которых проверяется правило.

| Класс стратегии | Требования | Kaufland (Release 1.0) | Причина |
|---|---|---|---|
| Фиксированная цена / только пол и потолок | нет | ✅ | Конкуренты не нужны |
| Сравняться с победителем Buy Box / опередить на шаг | `TOP_N ≥ 1`, `needsBuyboxWinner`, `needsShipping` | ✅ `new`; ⚠ `used` — только опросом `/buybox` | `buy_box_changed` — только `new` |
| Держать место не ниже K | `TOP_N ≥ K`, `needsOwnRank` | ✅ при K ≤ 10 | Топ-10 |
| Следовать подсказке канала (`target_price`) | источник с подсказкой | ⚠ только в push при `lost`/`changed` | В `GET /buybox` подсказки нет; вход стратегии, а не решение — Price Gate не меняется |
| Самая низкая цена рынка минус шаг | `CHEAPEST_ONLY` или `FULL`, `maxStalenessSeconds` мал | ❌ в реальном времени; ⚠ с устаревшими данными отчёта | Топ-10 по рангу не гарантирует минимум; `competitors-comparer` асинхронный и по Р-36 — только сверка |
| Самая низкая цена среди предложений с доставкой ≤ N дней | `TOP_N`, сроки доставки у предложений | ⚠ в пределах топ-10 | Сроки есть в обоих основных источниках |

### 4. Изоляция и AUP

Псевдонимы продавцов (`sellerRef`) и цены конкурентов — данные канала одного тенанта. Никаких справочников продавцов,
объединённых между тенантами, и никаких выводов «по рынку» из снимков разных тенантов (INV-07, Р-23).

## Последствия

- Стратегия, которой нужен `CHEAPEST_ONLY`/`FULL` в реальном времени, на Kaufland недоступна. Это ограничение продукта,
  которое показывается пользователю, а не обходится опросом отчёта.
- Если поддержка ответит, что `buy_box_changed` недоступен для подписки через API (K-18), основным источником Kaufland
  остаётся опрос `GET /buybox`, и допустимая частота опроса (K-10, K-04) определяет, для скольких unit стратегии с
  конкурентами укладываются в p95 < 2 мин (Р-8). Классы стратегий в таблице не меняются, меняется `maxStalenessSeconds`.
- Если `price` в `GET /buybox` окажется в центах (K-17), меняется только разбор в адаптере (правило KFL_C06); полнота прежняя.
- eBay и Otto: пока источник не определён (OQ-38), стратегии с конкурентами на этих каналах недоступны.
- Описание источников канала становится частью `ChannelDescriptor` вместе с полнотой; до реализации — таблица выше.

## Отклонённые варианты

- **Стратегия сама решает, хватает ли ей данных, при каждом расчёте.** Ошибка обнаруживается слишком поздно и тихо:
  стратегия считает цену по тем данным, что есть.
- **Дополнять топ-10 минимальной ценой из `competitors-comparer`.** Смешивает данные разной свежести в одном снимке;
  по Р-36 отчёт — только для сверки.
- **Единый уровень «есть конкуренты / нет».** Не отличает стратегии «победитель Buy Box» и «минимум рынка», хотя
  для второй топ-10 недостаточно.
