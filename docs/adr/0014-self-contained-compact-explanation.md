# ADR-0014: Самодостаточное и меньшее объяснение, код причины NO_OP в аналитике

Статус: Accepted (шаг 14, 2026-09-15). Решения владельца — Р-79, Р-80, Р-81, Р-82. Уточняет [ADR-0012](0012-explanation-dictionary-audit-identity.md): формат слепка `r74.1` заменён `r80.1`. **Шаг 15:** сжатие в секциях (п. 2) отменено Р-86 (0054); Parquet — экспорт ClickHouse, Р-87; из слепка и ядра убраны производные от цены конкурента, Р-85 ([ADR-0015](0015-dispatch-floor-recheck-ci-invitations.md)).

## Контекст

После шага 13 оставалось четыре проблемы:

- **Объяснение ядра не самодостаточно.** Слепок ссылается на версию стратегии и на справочник правил [Р-75]. Стратегии тенанта удаляются при его закрытии, а архив ядра их не содержал. Объяснение из архива после закрытия тенанта развернуть было нечем.
- **Ядро intent осталось большим** (OQ-131). Справочники сняли 8 %. Остальное — данные самого решения, и часть из них слепок повторял за столбцами строки.
- **NO_OP после 7 дней необъясним** (OQ-136). Почасовой агрегат ClickHouse хранил правило стратегии, но не код причины.
- **Обоснование Р-74 было неверным.** В нём сказано, что слепок NO_OP раздувал вечное ядро. На деле NO_OP в ядро не попадал никогда (Р-27).

## Решение

1. **Слепок `r80.1` не повторяет столбцы строки** [Р-80].
   - Итог, причина и границы Gate, отклонение, профиль Gate и набор правил, стратегия и версия, правило, триггер, предложенная цена — только в столбцах.
   - В слепке остаётся:
     - снимок (источник);
     - итог проверки входов без набора;
     - текущая цена и границы на момент стратегии;
     - причина и цепочка расчёта;
     - непрошедшая проверка Gate, минимальная маржа, курс;
     - остановки.
   - Разворачивает `expandExplanation(слепок, столбцы строки, справочники)`. Без профиля Gate порядок проверок неизвестен и не подставляется из кода (находка 8).
   - **Решению нужны столбцы intent:** горячий intent живёт 3 дня, решение — 30. Столбцы `pricing_strategy_id`, `pricing_strategy_version`, `rule_code`, `trigger_type`, `proposed_amount_minor` заполняет триггер из intent. Приложение их не задаёт.
   - Копию столбца в слепке отклоняет CHECK `*_explanation_no_column_copies` (0049). Цена NO_OP в списке решений берётся из столбца (находка 15).
2. **Сжатие значения в секциях** [Р-80].
   - jsonb решения и ядра — lz4 с хранением MAIN во всех секциях.
   - Листовые секции получают `toast_tuple_target` из `retention_policy.leaf_toast_tuple_target`; `ensure_partitions` ставит его новым секциям.
   - Настройки проверяет правило 40 (0050).
   - **Ограничение:** PostgreSQL сжимает значение, только если строка длиннее порога TOAST (~2 КБ, задан при сборке); `toast_tuple_target` порог не снижает. Сжимаются только длинные строки — см. «Последствия».
3. **Самодостаточный архив ядра** [Р-79].
   - `exportCoreArchive` (`@repracer/analytics-export`) выгружает месячную секцию ядра: один архив на тенанта, ключ с префиксом тенанта [Р-23].
   - В архиве — строки ядра и ровно те версии стратегий и наборы правил, на которые они ссылаются.
   - Перед отметкой экспорт читается обратно, и каждое объяснение разворачивается только по архиву. Пробел хотя бы у одной строки или расхождение числа строк — экспорт не подтверждается, секция не удаляется.
   - CHECK `partition_export_core_archive_self_contained` (0049): подтверждённый экспорт ядра в ARCHIVE без признака «справочники в архиве» база не примет.
   - Формат — JSON в gzip (`core-archive.r79.1`); Parquet — OQ-137.
4. **Код причины NO_OP в аналитике** [Р-81].
   - `price_intent_noop.no_change_reason`; ключ почасового агрегата `(tenant_id, write_scope_id, hour, no_change_reason, rule_code, trigger_type)` (`060_step14.sql`).
   - Выгрузка берёт код из решения, а без кода строку не выгружает. Проверка 6 в `099_verify.sql`.
   - Агрегат пересоздаётся: слой ClickHouse не развёрнут (OQ-114). На развёрнутом слое агрегат старше 7 дней без кода восстановить нельзя.
5. **Р-74 остаётся, обоснование исправлено** [Р-82]: решение принято ради горячего буфера решений, а не ради вечного ядра.

## Последствия

Замер — [step14-explanation-size.md](../benchmarks/step14-explanation-size.md), реалистичный генератор (находка 7):

| | До | После |
|---|---|---|
| Ядро, таблица с индексами на строку | 2 085 Б | **1 559 Б (−25 %)** |
| Строка ядра CHANGED | 1 732 Б | 1 259 Б (−27 %) |
| Слепок ядра, сырой | 1 352 / 1 498 Б | 879 / 961 Б (−35 %) |
| Архив ядра, gzip на строку | 195 Б | 166 Б (−15 %) |
| Решение, таблица с индексами на строку | 1 683 Б | 1 726 Б (**+2,6 %**) |

- **Сжатие в секциях почти ничего не дало.** Типичная строка после первого способа короче порога TOAST, а строки REJECTED_BY_GATE, которые раньше сжимались, стали короче порога и сжиматься перестали. Решение — OQ-140: принять (вечная копия — сжатый архив), сжатие файловой системы или сжатие в приложении ценой проверок jsonb в БД.
- **Буфер решений вырос.** Столбцы intent у каждого решения — цена развёртывания слепка без intent.
- **Архив тенанта крупнее на справочники** — версии стратегий тенанта и наборы правил (килобайты на архив).
- **Проверки БД сильнее:** копия столбца в слепке, NO_OP со ссылкой на снимок и подтверждение архива без справочников отклоняются базой. Поведение проверяет `step14.pg.test.ts`, не только каталог.
