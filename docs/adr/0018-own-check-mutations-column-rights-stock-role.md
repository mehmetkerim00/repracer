# ADR-0018: Мутация ловится своей проверкой, права по столбцам, роль остатков, строка в каждой неизменяемой таблице

Статус: принято (шаг 18). Уточняет ADR-0017 (разделы 2–4).

## Контекст

Ревью шага 17 показало, что мутационная проверка и защиты шага 17 слабее заявленного:

- мутация засчитывалась пойманной, если падала ЛЮБАЯ проверка строки каталога; проверки тестов принимали «любой упавший тест файла»,
  а причина сверялась с текстом, включавшим название теста — поэтому совпадения бывали ложными;
- 104 вызова `expect_fail` в смоук-тестах были без причины; часть из них отклоняла ДРУГАЯ защита, чем называла метка
  (например, три проверки границ при включении движка отклонялись ограничением «движок без стратегии»);
- страж административной записи не различал столбцы: UPDATE `write_scope` (режим, стратегия) и `pricing_halt` (срок проверки)
  проходил без человека и без аудита; страж проверял членство, но не роль — согласие на необратимую миграцию eBay записывал оператор;
- путь решения имел права на целые таблицы `pricing_halt` и `divergence_case` и мог подделывать действия человека;
- две параллельные транзакции приёма приглашений создавали две действующие привязки одного поставщика;
- виды значений проверялись только у параметров причин, не у полей слепка.

## Решение

### 1. Своя проверка мутации [Р-99]

Каталог — по мутациям: у каждой мутации свой список проверок. Проверка теста называет тест И причину — сообщение утверждения;
проверка схемы называет причину. Раннер сверяет причину только с текстом провала и различает три исхода: поймана своей
проверкой; упала только соседняя проверка (непойманная); не упало ничего. Утверждения тестов получили сообщения, чтобы провал
опознавал себя: «Missing expected rejection» без сообщения не отличает одно утверждение от другого.

### 2. Причина отказа обязательна [Р-94]

`pg_temp.expect_fail` без причины — провал; причина — шаблон текста отказа, SQLSTATE не принимается (42501 дают и защитные
триггеры, и отсутствие права). Проверки, которые отклоняла чужая защита, переписаны так, чтобы отказывала названная; дубли удалены.

### 3. Права по столбцам и роль участника [Р-100]

- `security.admin_only_writes()` возвращает административные столбцы; у UPDATE триггер стража получает их аргументами и
  срабатывает, только если изменён административный столбец.
- Каждая таблица с административной записью объявляет действие (`security.admin_write_action`): MANAGE_PRICING, MANAGE_CATALOG,
  MANAGE_TENANT, ENABLE_REPRICING, RELEASE_CHANNEL_HALT, GIVE_MIGRATION_CONSENT или собственный страж. Страж проверяет роль
  участника по матрице `security.pricing_permission` (совпадает с `PRICING_PERMISSIONS` в коде). Таблица без действия —
  отказ (fail-closed), проверка схемы это требует.
- Путь решения вставляет в `pricing_halt` и `divergence_case` только рабочие столбцы; меняет статус единицы записи только
  ACTIVE → BLOCKED.

### 4. Согласие на миграцию eBay [Р-101]

Только владелец, только от своего имени (пользователь сессии = автор), только со вторым фактором сессии. Страж согласия
срабатывает раньше общего стража роли — иначе его причины были бы недостижимы.

### 5. Роль остатков [Р-102]

`repracer_stock` (`svc_stock`): свой список разрешённого — чтение товара, источника и распределения остатка; запись пула,
движений и резерваций. Ни цен, ни аудита, ни членства в других ролях; проверка схемы сверяет права в обе стороны.

### 6. Строка в каждой неизменяемой таблице [Р-103]

`tests/db/smoke_append_only.sql` в откатываемой транзакции даёт строку каждой пустой append-only таблице и проверяет попытку
изменения всех 32; таблица без строки — красная сборка.

### 7. Прочее

- Гонка приёма приглашений: проверка «одна действующая привязка» берёт транзакционную рекомендательную блокировку по
  (пользователь, поставщик).
- Срок проверки остановки переносит участник с правом снятия, со вторым фактором; перенос попадает в аудит.
- Строки платформенного тенанта административный сервис не пишет.
- Виды значений — у каждого скалярного поля слепка (`security.explanation_field_kinds()` = `EXPLANATION_FIELD_KINDS`).
- Привязки входа и отзывы живут время жизни пользователя; удаляются вместе и только у отключённого.
- Недостижимая ветка стража автоматического снятия удалена (OQ-154).

## Последствия

- Цифры мутационной проверки до шага 18 («не поймана 1 из 83») недействительны; действующие — в
  `docs/evidence/step18-mutation-first.md` (первый прогон по Р-99) и `docs/evidence/step18-mutation-after.md` (итог шага).
- Стенд и тесты меняют статус единицы записи, границы и согласия только от участника с нужной ролью.
- Синхронизация остатка пишет от своей роли без пользователя сессии; административная запись в те же таблицы — от человека.
- Не сделано: первый прогон CI (у токена gh нет права `workflow`, OQ-146).
