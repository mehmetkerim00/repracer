# ADR-0020: Брокер и ClickHouse в CI, снимки спецификаций каналов, новая защита — в каталоге при создании

Статус: принято (шаг 20). Возврат к каналам после линии безопасности [Р-110].

## Контекст

Три утверждения проекта ни разу не проверялись поведением:

- **порядок записей за брокером [Р-24]** — тест есть с шага 10, но ни разу не обработал ни одного сообщения;
- **DDL ClickHouse и выгрузка из PostgreSQL [Р-20]** — написаны на шагах 4–14, ни разу не применялись;
- **объём ClickHouse «50–100 ГБ на клиента»** — оценка шага 4 без замера.

Кроме того:

- строки Amazon и eBay в матрице возможностей заполнялись «по памяти» с пометкой (проверить); снимков их спецификаций не было;
- риск 12б (элемент согласия eBay) стоял в принятых, хотя миграция необратима [Р-109];
- правило «новая защита — строка каталога мутаций» [Р-95] ничем не проверялось.

## Решение

### 1. Инфраструктура — в CI, а не на рабочей машине

Локально Docker образы не скачивает (OQ-114), поэтому брокер и ClickHouse поднимаются в GitHub Actions.

- **Задание `test`:**
  - Redpanda и ClickHouse в контейнерах;
  - DDL `schemas/clickhouse` применяется, и `099_verify.sql` обязан вернуть 0 строк;
  - логины ролей `repracer_ingest` и `repracer_retention` — синтетические;
  - тест выгрузки `clickhouse-export.pg.test.ts` и тест порядка за брокером входят в сборку без пропусков [Р-84].
- **Задание `clickhouse-compression`:** замер сжатия, итог — артефакт `compression.json` ([замер](../benchmarks/step20-clickhouse-compression.md)).

Первые прогоны нашли пять дефектов, которые годами лежали в непроверенном коде:

1. схема журнала теста порядка создавалась в чужой базе ([доказательство](../evidence/step20-broker-order.md));
2. смещения группы потребителей переносились между прогонами;
3. в `050_step10.sql` неверный порядок `CODEC`/`DEFAULT`;
4. `apply-clickhouse.mjs` не применял `060_step14.sql`;
5. генератор замера сжатия был старше схемы.

### 2. Порядок за брокером — с сопоставлением повторных доставок

Отклонение `OUT_OF_ORDER` допустимо только для повторной доставки уже обработанного снимка (at-least-once после перебалансировки).
Тест сопоставляет каждое отклонение с повторной доставкой. Он также требует, чтобы каждое опубликованное сообщение было обработано и
ни одно не ушло в «отравленные». Негативный контроль без ключа партиции обязан найти перестановки.

### 3. Снимки спецификаций

- **Amazon SP-API:** официальный репозиторий моделей, закреплённый коммит, SHA-256 каждого файла; страницы документации — адрес и
  SHA-256 загруженного текста, без копирования (как у Kaufland).
- **eBay:** документация отвечает 403 на автоматическую загрузку и с рабочей машины, и с раннера GitHub. Официальный программный путь
  требует ключей разработчика eBay. Сторонние копии спецификацией не считаются. Снимок не сохранён, причина записана
  (`vendor/ebay/sell-inventory-api/NOT-SNAPSHOTTED.md`), значения eBay остаются (проверить).

По снимку Amazon два вывода закреплены в матрице возможностей:

- **Цена и остаток — только `patchListingsItem`:** фид `JSON_LISTINGS_FEED` не гарантирует порядок обработки сообщений [Р-24]
  (OQ-32 закрыт).
- **Лимит двухуровневый:** 5 rps на продавца и 500 rps на приложение. Ограничитель адаптера Amazon должен считать оба уровня.

### 4. Новая защита — в каталоге при создании [Р-108]

`scripts/db/check-catalog-coverage.mjs` в CI сравнивает защиты схемы (триггеры и CHECK-ограничения) с каталогом мутаций и
базовым списком непокрытых на конец шага 19. Базовый список не растёт: новая защита без строки каталога — красная сборка.

### 5. Р-109

Элемент согласия eBay проверяется по предполётной проверке по существу (0074):

- вердикт согласия совпадает с вердиктом проверки;
- проверка — последняя для листинга и не старше 24 часов;
- принятые потери поимённо равны потерям проверки.

Мутационная проверка — строка `Р-109`.

## Последствия

- Локальная сборка без ClickHouse и брокера красная на двух тестах: выгрузка и порядок [Р-84]. Полная сборка — только в CI.
- Стоимость ClickHouse на клиента по замеру — около 10,6–11,4 € в месяц, у верхней границы оценки шага 4. Больше всего места
  занимает `price_intent`.
- Подключение Amazon упирается в вопросы A-01…A-08, eBay — в отсутствие снимка (E-01) и вопросы E-02…E-06 (channel-capabilities §9).
