# ADR-0023: Недоверие каналу, приёмник уведомлений Amazon, ценообразование канала при обнаружении, консоль стратегий

Статус: принято (шаг 23). Решения владельца — Р-118…Р-120.

## Контекст

Шаг 22 ввёл сверку базы цены [Р-116] и поставил её остановку в `pricing_halt` — таблицу системной остановки, которая по Р-51
держит только цены из данных конкурентов. Защиты 0080 расширили её до всех цен, и это противоречие стало OQ-162. Автоматическое
снятие остановки выборкой [Р-52] на Amazon не работало (OQ-164). Идентичность оффера Amazon строилась в двух местах по-разному
(OQ-165). Доступность стратегии [Р-39] проверял только сервер консоли (OQ-166). Чужой репрайсер обнаруживался только при записи
цены (OQ-163). Приёмника уведомлений Amazon не было: адаптер разбирал тело, но не было кода, который читает очередь. Экран стратегий,
массовая правка границ и лента цен шага 21 остались неполными (пункт C шага 21).

## Решение

### 1. Три вида остановки — три таблицы

| | Остановка человеком | Системная остановка витрины | Недоверие каналу |
|---|---|---|---|
| Решение | Р-69, Р-70 | Р-51, Р-52, Р-119 | Р-118 |
| Таблица | `tenant_data.price_stop` | `channel_data.pricing_halt` | `channel_data.channel_distrust` |
| Причина | заметка человека | испорченные входные данные (массовый сдвиг) | канал меняет наши числа (`PRICE_BASIS_MISMATCH`) |
| Держит | все цены | только цены из данных конкурентов | все цены и порог цены канала (PRICE и CHANNEL_MIN_PRICE) |
| Ставит | владелец или оператор | путь решения | путь решения и диспетчер |
| Снимает | человек с заметкой; тенант — владелец со вторым фактором | выборка, где канал её даёт; иначе человек со вторым фактором | только владелец или администратор, от своего имени, со вторым фактором и заметкой |
| Gate | `PRICE_STOP` | `CHANNEL_HALT` | `CHANNEL_DISTRUST` |
| Причина решения | `PRICING_STOPPED` | `CHANNEL_HALTED` | `CHANNEL_DISTRUSTED` |

Отдельная таблица, а не причина в `pricing_halt`: у недоверия другие права на снятие, другие защиты записи и другой ответ на выборку.
Одна таблица с условиями по причине — это защиты вида «если причина такая-то», которые снимаются одной мутацией (0080 это показал).
Защиты 0080 удалены миграцией 0082, а не оставлены рядом (Р-104). Миграция отказывает, если в базе уже есть остановки
`CHANNEL_PRICE_BASIS_MISMATCH`: переносить их молча нельзя.

Снятие недоверия — административная запись (Р-97): право UPDATE только на столбцы снятия, страж пользователя сессии и второго
фактора, аудит `pricing.distrust_released` с ролью и заметкой — как у снятия остановки человеком. Первая редакция писала только
общий `admin_change.update`; тест консоли на PostgreSQL это нашёл, триггер аудита исправлен в той же миграции.

### 2. Свойство канала вместо пробела [Р-119]

`ChannelDescriptor.haltRelease` (`SAMPLE` / `MANUAL_ONLY`) и справочник `platform.channel_behaviour` описывают канал. Функция базы
`review_halt_by_sample` отвечает `MANUAL_ONLY` и не ставит проверку. Справочники без CHECK значений: их равенство описаниям каналов
сверяет тест `channel-reference.pg.test.ts` — одна проверка вместо двух расходящихся.

### 3. Стратегия и ценообразование канала в базе [Р-39, Р-120, OQ-166]

- `platform.competitor_source` — полнота и свежесть источников конкурентов канала; `channel_data.strategy_unmet(channel, params)` —
  те же требования, что `strategyAvailability` в коде (сверяет тот же тест).
- `channel_data.offer_channel_pricing` — наблюдения правила Automate Pricing и границ канала: при обнаружении оффера
  (`pipeline.discoverOffers`), при чтении перед записью и при обратном чтении. Append-only, 18 месяцев.
- Триггер `write_scope_strategy_guard` отклоняет назначение недоступной стратегии и назначение офферу, у которого последнее наблюдение
  показывает ценообразование канала. Проверка наблюдения — только при изменении стратегии существующей единицы: единица создаётся до
  первого обнаружения.

### 4. Одна идентичность оффера [OQ-165]

`offerIdentityOf(keys)` в `channel-port` строит `OfferIdentity` из ключей `offer_mapping` для пути решения, очереди записей и хранилища
в памяти. Адаптер Amazon принимает только `externalSku`.

### 5. Приёмник уведомлений — пакет `packages/amazon-notifications`

- **Транспорт.** SQS по протоколу AWS JSON и подпись SigV4 без SDK AWS — новая зависимость не вводится (Р-33). Подпись проверена
  эталоном по алгоритму страницы IAM, протокол — очередью в памяти с тем же JSON (`@repracer/amazon-notifications/testing`).
- **Почему SQS, а не EventBridge.** `ANY_OFFER_CHANGED` и `PRICING_HEALTH` документация доставляет только через SQS.
- **Интерфейс настоящий, окружение — стенд.** `createNotificationReceiver({ sqs, router, ledger, sink, … })`: те же вызовы пойдут в
  AWS, когда появятся очередь и учётные данные.
- **Маршрут продавца.** Очередь одна на приложение и регион. Межтенантный поиск аккаунта по `SellerId` — только функцией
  `security.resolve_amazon_seller` (0083) у роли без входа `repracer_inbound_router`, которая видит ключевые столбцы подключённых
  аккаунтов Amazon; вызывает роль приёмника. Функция отдаёт идентификаторы и ничего больше; данные тенанта не пересекают границу.
- **Дедупликация.** Журнал `channel_data.inbound_notification` на тенанта, 30 дней (дольше предельного хранения сообщения в очереди).
  Сообщение удаляется только после записи журнала.
- **Порядок.** Пачка сортируется по `EventTime`; между пачками — правило ядра «новее — побеждает».
- **Потеря.** Тишина, опоздание, повторы с растущей паузой, отказ после `maxReceiveCount`. Пропуск отдельного уведомления не
  обнаружить — принятый риск 21.
- **`PRICING_HEALTH`.** Событие порта `PRICING_HEALTH`, состояние оффера `channel_data.offer_pricing_health` (18 месяцев), WARNING
  `OFFER_PRICING_HEALTH`. В решение о цене не входит: порог конкурентной цены — данные канала, стратегия его не использует.

### 6. Консоль — остаток пункта C шага 21

- **Экран остановок:** таблица трёх видов, раздел недоверия со снятием; у системной остановки Amazon — «только человек».
- **Товары:** статус «удерживается: недоверие каналу», колонка «канал сообщает» (Automate Pricing, границы канала, `PRICING_HEALTH` с
  порогом).
- **Стратегии:**
  - все стратегии тенанта с именами и новой версией любой из них;
  - список офферов с ценообразованием канала до назначения;
  - такие офферы не выбираются;
  - сохранение недоступно, пока превью показывает причину;
  - подтверждение отдельным диалогом;
  - при изменившихся офферах превью строится заново;
  - суммы и проценты вводятся как люди их пишут.
- **Правка границ:** только с правом `MANAGE_PRICING`, сумма и процент вместо центов и базисных пунктов, «выбрать всё», в отказе
  CONFLICT — текущие границы оффера.
- **Лента цен:** фильтры по статусу, офферу и периоду и страницы считает сервер; неверный параметр — 400.
- **Мир стенда Amazon** `amazon/pipeline/console-channel-trust`: действующее недоверие, оффер с Automate Pricing, `PRICING_HEALTH`.

## Последствия

- Защиты 0082 и 0083 в каталоге мутаций (строки «Р-118», «Р-39/OQ-166, Р-120», «Шаг 23 A»), каждая ловится своей проверкой.
- Проверка схемы перенесена в 0084.
- Не сделано и записано:
  - живая очередь и задержки (OQ-167);
  - значения `issueType` (OQ-168);
  - назначение существующей версии и снятие стратегии (OQ-169);
  - автор версии в консоли (OQ-170);
  - журнал в транзакции решения (OQ-171);
  - частота обхода офферов (OQ-163).
