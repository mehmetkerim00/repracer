# ADR-0044: адаптер eBay по песочнице

Статус: принято (шаг 39). Решения: [Р-162…Р-164](../decisions.md). Закрыты OQ-235, E-03 (песочницей), E-08, E-10, E-11.

## Контекст

С шага 20 адаптер eBay был заблокирован [Р-112]: документация eBay отвечает 403 на любую загрузку без браузера, и снимка
спецификации нет. К шагу 39 появились ключи песочницы и тестовый продавец — то есть настоящий канал, но не боевой.

## Решение

1. Адаптер `packages/ebay-adapter` написан по фактам песочницы, каждый помечен [песочница] [Р-162]; всё неподтверждённое
   — консервативные правила EBAY_C01…C12 с вопросами E-02…E-17.
2. Запись — `bulk_update_price_quantity` по `offerId`, до 25 запросов; валюта и два знака проверяются адаптером (песочница
   принимала чужую валюту и молча округляла вверх); количество 0 — исход неизвестен до обратного чтения (ошибка при
   применённой записи).
3. Подтверждение цены — живой листинг (Browse API), а не `GET offer`: предложение — наша запись, и правку листинга мимо
   него оно не видит. Browse отдаёт цену покупателя, включая НДС, который собирает eBay, — расхождение на ставку НДС по
   Р-116 означает недоверие витрине.
4. Бюджет правок — на каждую попытку, с худшей границей суток [Р-163]; миграция — только по согласию и после
   предполётного чекера [Р-164].
5. После обмена кода продавца называет Commerce Identity API (`apiz.`); scope `commerce.identity.readonly` обязателен в
   конфигурации. Если назвать не удалось, а аккаунт eBay у тенанта уже есть, подключение отказывает `IDENTITY_UNKNOWN` —
   второй аккаунт не создаётся.

## Последствия

- [док] у eBay нет ни одной ячейки: снимок ждёт загрузки владельцем в браузере (E-01).
- Сценарии пути решения eBay (хранилище в памяти, PostgreSQL) не сделаны; каталог из обнаружения eBay по-прежнему
  не пишется (0134).
- Для боевых ключей нужны Growth Check (OQ-35) и Marketplace Account Deletion (OQ-30, E-18).
