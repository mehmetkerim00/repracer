# ADR-0045: eBay в пути решения — сценарии, каталог, заказы

Статус: принято (шаг 47). Решения: [Р-186, Р-187](../decisions.md). Новые вопросы: E-19, E-20.

## Контекст

Шаг 39 написал адаптер eBay по песочнице, но путь решения eBay не знал: хранилище в памяти канал не принимало, сценариев
пути решения не было, обнаружение eBay каталог не писало (0134 возвращала 0), заказы не читались. Находки песочницы
(три знака цены округляются молча, чужая валюта принимается, количество 0 отвечает ошибкой при применённой записи, цена
покупателя с НДС сверху) жили только в адаптере.

## Решение

1. **Находки песочницы — поведение канала в адаптере и стенде** [Р-186]. У наблюдения порта появилось поле `buyerPrice`:
   цена покупателя eBay идёт туда и в сверку Р-116 не попадает; цена продавца — живая цена Browse без НДС сверху. Налоговая
   база EBAY_DE остаётся `CONSERVATIVE` с вопросом E-17; первое расхождение «НДС сверху» — алерт
   `EBAY_BUYER_PRICE_VAT_ON_TOP` с режимом аккаунта.
2. **Модель eBay в симуляторе** [Р-187] (`tests/contract/src/simulator/ebay-channel.ts`) отвечает кодами песочницы и 207 на
   смешанный пакет; E-02, E-04, E-06, E-12, E-13, E-15, E-16, E-17 — параметры модели с умолчанием «как песочница».
3. **Сценарии пути решения eBay** — десять `pipeline-*` на памяти и те же на PostgreSQL: обязательный набор Kaufland и
   Amazon (границы, отсутствие `max_price`, налоговые режимы и пол маржи, остановки, очередь записей) плюс бюджет правок
   среди дня и немигрированный листинг. У eBay нет данных конкурентов: стратегию по ним отклоняет база (`NO_COMPETITOR_SOURCE`
   [Р-39]), остановка витрины — только ручная (`MANUAL_ONLY` [Р-119]).
4. **Каталог из обнаружения eBay** (0140): каждый листинг становится предложением со статусом записи — под Inventory API
   (`NOT_REQUIRED`) с единицей записи в режиме OFF, немигрированный (`MIGRATION_REQUIRED`) и аукцион
   (`INELIGIBLE`) — без единицы. Листинг без SKU каталогизируется по номеру листинга. Повторное обнаружение мигрированного
   листинга завершает прежнее сопоставление и заводит действующее. Обнаружение — две фазы: Inventory API и Trading
   GetMyeBaySelling (EBAY_C16).
5. **Заказы** — Fulfillment API по времени изменения заказа, белый список полей без данных покупателя (EBAY_C17), партиями
   по странице; строки заказа становятся резервациями тем же конвейером, что у Kaufland и Amazon [Р-25].
6. **Пересчёт по расписанию** (`scheduled-recompute`) — фиксированные и маржинальные цены раньше не пересчитывал никто;
   теперь единица без решения за сутки, не больше 1000 за заход.

## Последствия

- Граница суток EBAY_DE — `TO_VERIFY`, и база отказывает даже теневой записи с бюджетом правок: прогон пилота
  подтверждает её в своей базе. Как быть с тенью — решение владельца (ревью шага 47).
- [док] у eBay по-прежнему ни одной ячейки: файлов E-01 нет.
- Заказы проверены только синтетически: согласия с `sell.fulfillment.readonly` и заказа тестового покупателя нет.
