# ADR-0047: правило повтора записи канала, единицы записи Amazon, бюджет правок после обновления, количество «управляет канал»

Статус: принято (шаги 51–52). Решения: [Р-193, Р-194, Р-195](../decisions.md).

## Контекст

eBay Application Growth Check требует не больше двух повторов записи и только после сбоев инфраструктуры. Общая политика диспетчера повторяла запись любого канала до четырёх раз после любой временной ошибки.

Для Amazon нужно было закрепить единицы записи, а количество FBA показать продавцу, не касаясь его записью.

Записи, упёршиеся в бюджет правок, нигде не отправлялись заново: количество застревало до следующего изменения остатка.

## Решение

1. **Правило повтора записи — данные канала** (`ChannelDescriptor.writeRetry`), применяет ядро: диспетчер и своя отправка пути решения [ADR-0006].
   - Правило говорит только об ОТВЕТАХ канала (есть `httpStatus`). Ошибка без ответа — таймаут, обрыв, отказ нашего бюджета — повторяется в пределах попыток.
   - Правило канала ужесточает общую политику и не ослабляет её.
   - eBay: три попытки; из ответов повторяются 5xx и отказ формы пакета EBAY_C18 (значение не оценено, Р-189).
2. **Amazon** [Р-194]:
   - цена — аккаунт + витрина + SKU (селектор `marketplace_id`);
   - количество FBM — аккаунт + регион эндпоинта SP-API + SKU (у `fulfillment_availability` селектора витрины нет);
   - граница общего количества для UK и витрин Europe вне ЕС — вопрос A-24.
3. **Бюджет правок** [Р-195]. Исчерпанная запись завершается с причиной. Цена — WARNING, количество — CRITICAL. Когда бюджет обновился — прошли сутки витрины или время, названное каналом, — пересчёт остатков создаёт её снова. Работа чтения заказов пересчитывает такие товары и без новых заказов.
4. **Количество «управляет канал»** (0144) — append-only наблюдение предложения CHANNEL:
   - страж: только у CHANNEL-предложения;
   - пишет функция роли каталога;
   - экран остатков показывает его только для чтения [Р-6].

## Последствия

- Отвергнутая каналом или упёршаяся в бюджет версия количества не считается «уже созданной»: пересчёт может отправить то же значение снова. Это новая версия по новому решению, а не повтор вызова.
- Наблюдения FBA хранятся 18 месяцев, хотя экрану нужно последнее значение. Проекция «последнее значение» — в отложенном (ревью шага 52, находка 7).
