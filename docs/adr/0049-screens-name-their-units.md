# ADR-0049: экран называет свои единицы, база отвечает о каталоге фактами

Статус: принято (шаг 67, OQ-248).

## Контекст

До шага 66 каждый экран консоли строил мир из каталога ЦЕЛИКОМ (`readConsoleState`): на 50 000 предложений — 41,5 МБ памяти сервера
и 4,4–6,4 с на каждый запрос, хотя экран показывает 50 строк. Шаг 66 перевёл товары, индекс границ, остатки и тень. Остались
стратегии, поиск предложения, комплаенс, остановка, карточка границ, решения и «почему эта цена», лента, отклонённые и опасные
изменения — и маршруты записи, строившие каталог целиком до разбора запроса.

Каждый из этих экранов знает о каталоге целиком немногое: сколько в нём предложений, первые 200 для выбора, какие подходят под поиск,
сколько предложений у каждой стратегии и какие первые, сколько включённых цен и ждущих записей у каждой цели остановки, какие предложения
с ценообразованием канала, какая единица первой подходит под ключ отклонённого снимка.

## Решение

1. **Экран называет единицы, которые покажет** — страницу, найденные, примеры, единицы отчёта, — и мир строится только из них
   (`readConsoleState` со списком).
2. **То, что экран знает о каталоге целиком, спрашивается у базы фактами** (`consoleCatalogFacts`) и страницей (`consoleCatalogPage`).
   Каждый факт — правило экрана, переписанное запросом. Представления берут факты из мира (`catalogFacts`, `catalogPage`), а без них
   считают по каталогу целиком. Так хранилище в памяти (миры сценариев) работает по-прежнему.
3. **Два правила одного и того же держит тест равенства** (`console-screens-targeted.pg.test.ts`). На каждом мире стенда, поднятом на
   PostgreSQL, каждый экран отвечает одинаково через обычный сервер и через сервер, строящий экраны из каталога целиком
   (`fullCatalogScreens`). Счётчики путей утверждают, что пути действительно разные.
4. **Маршрут записи получает мир, который читает:**
   - остановка и снятия — без каталога, с влиянием по аккаунту и витрине;
   - маршруты «только тенант» — без каталога;
   - маршруты одного предложения — его единицу.

   Каталог целиком строят только массовые операции, которым он нужен по смыслу: «весь каталог», стратегии, план границ, план импорта,
   включение набора. Это остаток OQ-248.
5. **Запросы по каталогу не зависят от статистики:**
   - каталог целиком (страница с итогами, факты) — хеш-соединения;
   - мир страницы — каждая таблица каталога ограничена своим списком.

   Квадратичный план на свежем каталоге держат тест со стёртой статистикой и прогон гостя демо.

## Последствия

- Экраны на 50 000 — доли секунды и десятки килобайт (замер масштаба шага 67); каталог в память сервера на экран не грузится.
- Новое правило экрана о каталоге целиком — новый факт в базе и строка в тесте равенства. Без строки тест не узнает, что правила разошлись.
- Отложено:
  - поиск берёт имя канала по коду канала единицы, а экран — по аккаунту: у предложения отключённого аккаунта подписи разойдутся;
  - регистр в поиске зависит от локали базы;
  - лишние чтения на запрос (мир дважды у решений и ленты с фильтром, агрегат состояний у страницы стратегий и комплаенса).
