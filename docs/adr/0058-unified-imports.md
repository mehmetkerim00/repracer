# ADR-0058: единые импорты — шаблон, примерка на сервере, применение ровно примерки, журнал

Статус: принято (шаг 99, Р-224, Р-225). Уточняет Р-134 (шаг 28): файл с ошибочными строками больше не применяется частично.

## Контекст

Клиент заводит данные по сотням товаров файлом и сравнивает нас с «Import/Export» других репрайсеров. До шага было два импорта
с разным поведением: себестоимость (Costs & floors) — разбор и предпросмотр в браузере, применение заданием, несопоставленные строки
пропускались списком; остатки (Inventory) — файл сразу в задание, без примерки. Не было ни шаблонов, ни импорта границ, ни
назначения стратегий файлом, ни истории.

Два свойства прежнего пути опасны на объёме:

1. **Частичное применение молча.** Из 10 000 строк с 15 % ошибок шаг 28 применял 8 571 и показывал остальное примерами. Продавец,
   не дочитавший список, считает, что файл лёг весь.
2. **Предпросмотр устаревает.** Между предпросмотром и нажатием «Apply» данные могли измениться (другой человек, другой импорт,
   обнаружение офферов) — и применялся не тот план, который человек видел.

## Решение

1. **Один путь на четыре вида** (`ImportKind`: `COSTS`, `STOCK`, `BOUNDS`, `STRATEGY`). Схема колонок, разбор ячеек, сопоставление
   и проверка строк — `packages/console-model/src/imports.ts`; на сервере и в браузере — один и тот же код.
2. **Шаблон — задание `IMPORT_TEMPLATE`.** Файл собирает единственный путь выгрузки [Р-145]: обработчик объявляет заголовок, строки,
   строки-комментарии и лист справки, байты делает исполнитель. CSV — заголовки EN, строка `#`-примера, пояснение строками `#`
   на языке пространства; XLSX — книга без новой зависимости (`packages/bulk-jobs/src/xlsx.ts`: zip `node:zlib`, ячейки текстом —
   ведущие нули и знаки формул не теряются), лист данных первым, справка — вторым листом. Шаблон предзаполнен текущими данными.
3. **Примерка — задание `IMPORT_CHECK`.** Файл сохраняется в параметрах задания; примерка строит план против текущих данных
   (изменится / без изменений / ошибка по каждой строке), пишет строку журнала `CHECKED` и отчёт ошибок файлом. Отпечаток плана
   (`token`) — хеш изменений вместе с текущими значениями, на которые они опираются.
4. **Apply — прежние виды применения** (`COST_IMPORT`, `STOCK_IMPORT`, `BOUNDS_EDIT`, `STRATEGY_ASSIGN`) с параметрами
   `{checkJobId, checkToken}`. Консоль отказывает до создания задания, если у примерки есть ошибки (`HAS_ERRORS`) или менять нечего
   (`NOTHING_TO_APPLY`). Задание пересчитывает план по сохранённому файлу против текущего мира: другой отпечаток — `DATA_CHANGED`,
   ничего не пишется. Хранилище получает каждую строку с ожидаемыми значениями и сверяет их в транзакции записи (между пересчётом и
   записью тоже может пройти время) — расхождение откатывает всё. Строка журнала `APPLIED` — в той же транзакции, что запись данных.
5. **Журнал `tenant_data.import_run`** — только на добавление. Строку пишет задание, которое сейчас идёт и назвало себя базе
   (`app.bulk_job_id`), и только своего вида: примерка — `CHECKED` своего вида импорта, применение — `APPLIED` или `REFUSED`
   и только со ссылкой на примерку. Автора и длительность ставит база по заданию (`clock_timestamp() − created_at`), не вызывающий.
   «Применено» — без отклонённых строк; строки складываются в число строк файла; одна строка на задание.
6. **Повтор задания** после падения процесса видит строку `APPLIED` своего задания и не применяет второй раз; пересчёт остатков после
   импорта остатков делается снова (повтор шага 97.2 в новой форме — тест `stock-import-retry`).
7. **Права.** Шаблон — `VIEW_PRICING` (отмена своего — им же); примерка — право вида импорта (остатки — `MANAGE_CATALOG`, остальное —
   `MANAGE_PRICING`), задание ничего не меняет [Р-143] и второго фактора не требует; отмена чужой примерки — `MANAGE_PRICING`.
   Применение себестоимости и границ — со вторым фактором [Р-135]; минимальная маржа больше одного предложения одной транзакцией без
   второго фактора — отказ базы (новый страж `zh_guardrail_mass_edit_requires_mfa`).
8. **Границы и стратегии файлом** [Р-225]: min price, max price, min margin % предложения; стратегия — по имени. Ошибки строк — те же
   правила, что у правки границ и превью стратегий.

## Последствия

- Поведение для продавца меняется: файл с ошибкой не применяется, пока ошибка не исправлена. Отчёт ошибок называет каждую строку.
- Время применения видно («N rows applied in X s»). 10 000 строк себестоимости применяются ~27–30 с на машине разработчика: стоимость —
  построчные триггеры `cost_profile` (аудит и стражи на каждую строку), а не путь импорта; в отложенном.
- Прежний разбор себестоимости в браузере (`CostImport.tsx`, `console-model/src/cost-import.ts`) больше не используется экраном;
  разбор файлов (`@repracer/cost-import`) остаётся общим.
- Миграции 0193 (виды заданий, журнал, страж маржи), 0194 (проверка схемы v52).
