# Потеря записей за записью в полёте — до и после диспетчера (шаг 10, Р-64)

Статус: 2026-09-14. Тест — [packages/pricing-store-pg/test/write-queue.pg.test.ts](../../packages/pricing-store-pg/test/write-queue.pg.test.ts),
PostgreSQL 16.13, одноразовый кластер со всеми миграциями. Данные синтетические.

## Нагрузка

- **Решения.** 40 единиц записи цены (Kaufland `de`), по 6 решений на каждую, итого 240 изменений цены.
  - i-е событие по единице приходит через i·15 мс плюс случайная доля интервала и не ждёт предыдущих: вебхуки и опрос независимы.
  - Каждое следующее решение дороже на 50 центов.
- **Путь решения** после фиксации сам отправляет запись, если единица свободна (как `pipeline.dispatchCommitted` шага 9).
- **Канал-заглушка** отвечает за 20–80 мс. Это быстрее типичного PATCH канала — оценка, не замер.
- **Что считается:**
  - записи, оставшиеся `PENDING`, когда всё затихло;
  - единицы, до канала которых не дошла последняя решённая цена;
  - получение каналом старой версии после новой;
  - вытеснения без записанной причины.

## До исправления (код и схема шага 9, миграции 0001–0035)

| Прогон | Отправлено оценкой | Встало в очередь | Осталось PENDING | Единиц без последней цены | Нарушений порядка | SUPERSEDED без причины |
|---|---|---|---|---|---|---|
| 1 | 45 | 195 | 35 | **35 из 40** | 0 | 160 |
| 2 | 77 | 163 | 22 | **22 из 40** | 0 | 141 |
| 3 | 76 | 164 | 19 | **19 из 40** | 0 | 145 |
| 4 | 78 | 162 | 20 | **20 из 40** | 0 | 142 |
| 5 | 67 | 173 | 21 | **21 из 40** | 0 | 152 |

**У 48–88 % единиц последняя решённая цена не дошла до канала.** В канале осталась одна из более ранних цен. Порядок при этом не нарушался: старую версию после новой не пропускает БД.

Когда решения по единице шли строго друг за другом, дефект проявлялся редко. Канал отвечал за 3–25 мс, и в одном из трёх прогонов потерялось 1 из 240 изменений.

В базе после замера шага 9 (окно из журнала) тоже осталась одна запись `PENDING` без записи в полёте: 1 из 452 одобренных изменений.

## После исправления (миграция 0036, `@repracer/write-dispatcher`)

Три прогона, каждый в трёх режимах:

| Режим | Застряло PENDING | Единиц без последней цены | Нарушений порядка | Без причины | Отправил диспетчер | Нашёл обход |
|---|---|---|---|---|---|---|
| Контроль: диспетчера нет | 33 / 22 / 26 | 33 / 22 / 26 | 0 | 0 | 0 | — |
| Передача диспетчеру после итога записи | **0 / 0 / 0** | **0 / 0 / 0** | 0 | 0 | 37 / 38 / 43 | **0 / 0 / 0** |
| События «потеряны», только обход | **0 / 0 / 0** | **0 / 0 / 0** | 0 | 0 | 37 / 37 / 38 | 37 / 37 / 38 |

- **Контроль.** Без диспетчера дефект остаётся, но теперь каждая застрявшая запись объявлена событием `scope.write.v1` (единиц с ждущей записью без события — 0), а каждое вытеснение хранит причину.
- **Передача в процессе** доводит очередь до конца без помощи обхода.
- **Обход в одиночку** восстанавливает всё, если события не дошли.

## Оговорки

- Один процесс и одна машина; порядок при нескольких экземплярах за брокером проверяет `services/pricing-worker/test/order-behind-broker.test.ts`. Этот тест **не прогонялся**: стенд Redpanda не поднят (OQ-114).
- Параметры повторов и сверки диспетчера — допущение до замеров задержек каналов (OQ-115).
