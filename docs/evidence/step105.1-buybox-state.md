# Шаг 105.1: доставка и продавец Buy Box в проекции снимка — доказательство

Решение владельца после шага 105 [Р-230]: хранить доставку и продавца Buy Box в снимке (`competitor_state`) — миграция и строки каталога
мутаций. Доставку Buy Box Amazon (`Summary.BuyBoxPrices`) писать честно; где канал не назвал — честное отсутствие. Проверки: на PostgreSQL
цена Buy Box Amazon перестаёт быть вечным «shipping not named»; разрыв на Offers считается от landed-цены — там, где держатель назван (ответ
владельца). Амазону разрыва нет: держатель не назван (A-29).

## Что сделано

- **0203** — `competitor_state.buybox_shipping_minor` и `buybox_seller_ref`, четыре ограничения формы: доставка не отрицательна; доставка
  только при цене Buy Box; продавец только у чужого держателя (у нашего Buy Box продавец — мы, у неизвестного держателя его нет, Р-221);
  продавец — 1–200 знаков (как у отрезков держателя, 0188). Страж изменяемых столбцов проекции дополнен, как в 0042. **0204** — копия
  проверки схемы v57 (правил шаг не добавил).
- **Запись снимка** пишет только названное каналом: доставку — в валюте цены Buy Box, продавца — только у чужого держателя.
- **Чтение снимка** (`STATE_JSON` → `toSnapshot`) отдаёт их одним путём контексту решения, странице Competition и колонкам Offers.
- **Запрос выборки Offers** повторяет правило экрана `buyboxFacts`: цена Buy Box — с доставкой, если канал её назвал; цена победителя с
  доставкой — доставка Buy Box, а без неё — строка держателя по признаку держателя или по продавцу Buy Box.

## Найдено

- **Пересчёт по сохранённому снимку решал иначе, чем путь снимка.** Путь снимка решает по ПРИШЕДШЕМУ снимку — в нём доставка Buy Box
  Amazon была и до шага. Пересчёт без нового снимка (плановый, лестница [Р-208, Р-212], переоценка после входов пола [Р-211]) читает
  ПРОЕКЦИЮ, где доставки не было, — и «Beat the lowest» с ориентиром Buy Box и сравнением с доставкой на Amazon получал
  `NOT_EVALUATED / COMPETITOR_REQUIREMENT_NOT_MET (unmet: SHIPPING)`, хотя хранилище в памяти тот же пересчёт решало ориентиром 19,49 €.
- **Мой первый вариант теста решения был красным не по той причине.** На старом коде он краснел, но из-за порядка тестов (аккаунт в тени:
  повтор того же снимка — законное «без изменения»), а не из-за кода; проверка с убранной правкой хранилища показала, что путь снимка решал
  верно и без шага. Тест переписан на плановый пересчёт по проекции. Второй вариант брал ручной триггер — путь решения ручного намерения не
  создаёт [Р-107], фиксация отказывала алертом; теперь триггер — `SCHEDULE`, как у работы планировщика. Ещё раньше числа были неудачные:
  самая низкая цена с доставкой совпадала с landed-ценой Buy Box, и ориентир «самая низкая» дал бы ту же цену — числа разведены.
