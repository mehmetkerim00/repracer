## Что найдено при работе

- **Первая схема приоритета была неправдой для первого дня.** Давность чтения с весом 24 даёт верный устоявшийся темп, но после старта собирает остальные предложения в одну волну. В первом цикле живого прогона 360 из 1 000 не перечитались за полный круг и ещё 20 минут. Теперь в каждом окне у остальных своя доля мест: `r = max(1, round(20·R / (24·C + R)))`, не больше 19. С первого окна обе цифры — верхние границы: ⌈C / (20 − r)⌉ и ⌈R / r⌉ окон.
- **Дыра NULL в ограничении формы.** `fallback_reason IN (...)` при NULL даёт NULL, и CHECK пропускал строку поиска без причины. Это нашёл тест формы; ограничение теперь проверяет `IS NOT NULL` явно.
- **Дубль ограничения.** `discovery_catalog_source_known` полностью покрыто формой строки: неизвестный источник не проходит форму. Удалено (Р-104), а не оставлено исключением.
- **Поиск по SKU тоже бывает короче страницы.** При коротких страницах модели (параметр `paging`, шаг 52) первая редакция пропускала токен продолжения и теряла SKU порции. Теперь курсор документа несёт токен страницы внутри порции.
- **Пауза пути решения на стенде была настоящей.** Ожидание отчёта (`notBefore`) в сценариях стенда шло бы реальным временем. Теперь путь решения стенда спит виртуально, как адаптер.
- **Старые сценарии.** Первый вызов обнаружения раньше сразу отдавал предложения поиска.
  - Записанные фикстуры теперь начинают обнаружение с отчёта (`listingsReportExchanges`).
  - Проверка тел по модели знает Reports из снимка 2026-09-16; путь к документу — не операция SP-API.
  - Тесты разбора поиска отвечают на запрос отчёта не по модели и идут резервом.
  - Тест предела поиска шага 106 проверяет резерв и записку «может быть неполным».
