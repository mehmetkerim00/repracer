# Шаг 118: выключение автоцены одного предложения — «вот этот SKU не трогай»

Решение владельца по докладу 117, обязательный шаг MVP (P1-07), [Р-242]:

- владелец или менеджер выключает автоцену одного предложения и включает обратно — симметрично включению;
- второго фактора нет (Р-225), записка — по желанию, событие аудита «кто и когда» — обязательно;
- выключенное предложение движок не оценивает вовсе и повторов не пишет;
- на Offers статус виден и фильтруется, в выгрузке — прежняя колонка статуса;
- тексты на четырёх языках, живой прогон «консоль как браузер», красное сначала.

Решение — [ADR-0072](../adr/0072-offer-pricing-switch.md).

## Что сделано

| Где | Что |
|---|---|
| База (0222) | Журнал `tenant_data.offer_pricing_switch` только на добавление: выключил / включил, членство, время базы, записка 1–500 знаков. Страж: членство — человека сессии; выключить — только ENGINE; включить — только OFF. Общие страж и аудит административной записи, закрытие тенанта уносит журнал. Р-12 больше не держит переходы между ENGINE и OFF. |
| Проверка схемы (0223, v66) | Копия 0221: журнал объявлен действием `ENABLE_REPRICING`, правила проверки знают таблицу. |
| Хранилище | `setPricingMode(…, note)` пишет строку журнала той же транзакцией, что режим; без членства человека режим не меняется. Состояние консоли несёт последнюю строку журнала (`pricingSwitch`) с именем человека. Хранилище в памяти — так же. |
| Путь решения | `disableRepricing`: выключить можно только включённое, записка обрезается. |
| Консоль | `POST scopes/<id>/disable` — право `ENABLE_REPRICING`; 409 `NOT_ENABLED` словами; 400 `NOTE_TOO_LONG`. Фильтр `pricing=ON|OFF` у экрана Offers и обеих выгрузок; в листе «About this export» — `repricing`. |
| Экран Offers | Кнопка «Turn off» у включённых, окно с запиской. Пилюля «Off» и под ней «Turned off by Jamie Lee, <время в поясе пространства>», записка — в подсказке. Фильтр «Repricing: Any / On / Off». EN, DE, ES, FR. |

**Что стало с записями в очереди.** До шага Р-12 не давал сменить режим, пока у единицы есть незавершённые записи: «не трогай» ждало бы очереди.
Теперь режим меняется сразу. Запись, ждавшая отправки или повтора, в канал не уходит. Её отклоняет прежний страж отправки (0008, сейчас 0128:
«pricing_mode changed to OFF»), диспетчер завершает её причиной `WRITE_PRICING_MODE_CHANGED`. Запись, уже ушедшая в канал, доходит до своего итога.

**Найдено при работе.** Первая редакция миграции добавила свой страж отправки «цена уходит только при ENGINE». Он дублировал прежний: та же
проверка есть в `channel_write_before_update` с шага 8. Мой страж удалён (Р-104). Прежняя ветка до шага была почти недостижима, теперь она держит
«цена выключенного не уходит», и у неё своя строка каталога мутаций.

## Живой прогон через консоль как браузер

`apps/console/test/offer-pricing-switch-live.pg.test.ts` — американское демо на PostgreSQL, тот же посев, что у стенда показа. Настоящий
HTTP-сервер консоли, вход стенда.

1. Менеджер входит **одним паролем** (`amr: pwd`, без второго фактора).
2. «Repricing: On» — у каждой строки есть «Turn off».
3. Менеджер выключает предложение с запиской — 200. Второй раз — 409 «Repricing is not on for this offer — there is nothing to turn off.»
4. «Repricing: Off» — найдено на одно больше. Строка: «Off», «Turned off by Jamie Lee, …», подсказка «… Note: Supplier price talks — hold this one».
   «Turn off» нет, «Enable» есть. В «Repricing: On» предложения нет. Неизвестное значение фильтра — 400.
5. Выгрузка Offers CSV с фильтром «Off» — задание исполнителя. Файл скачан тем же кодом, что у страницы (`fetchFile`, Р-142). Предложение в файле,
   колонка `repricing` — только `OFF`.
6. Пока прогон шёл, у выключенного предложения не прибавилось ни решений, ни повторов «без изменения».
7. Владелец включает обратно прежней «Enable», и предложение снова в «Repricing: On».
8. Журнал: OFF с запиской, ON без записки. Аудит — два события человека, оба без второго фактора.

Гость демо: кнопки «Turn off» нет, маршрут — 403 `FORBIDDEN` (`guest-demo-live.pg.test.ts`).

## Движок не оценивает выключенное

`packages/pricing-store-pg/test/offer-pricing-switch-step118.pg.test.ts`, последний тест. Три пересчёта по расписанию и три снимка с конкурентом:

| Предложение | Решений | Повторов «без изменения» |
|---|---|---|
| Включено, цена на цели (контроль) | 1 | 2 |
| Выключено, цена на цели | 0 | нет строки |
| Включено, конкурент (контроль) | ≥ 1 | — |
| Выключено, конкурент | 0 | нет строки |

## Красное сначала

| Тест | На старом коде |
|---|---|
| Живой прогон через HTTP | Красный: фильтра «Repricing» нет, «найдено» не считается (`matched` — null) |
| Тест базы: журнал, аудит, экран | Красный: строк журнала нет |
| Тест базы: стражи журнала, запись в полёте, движок не оценивает | Зелёные и на старом исходнике — исключение |

Исключение объясняется так. Эти три теста проверяют слой базы, а миграция 0222 уже применена к шаблону. «Движок не оценивает» верно и до шага:
путь решения пропускает режим не ENGINE (`SCOPE_NOT_ENGINE`), тест это закрепляет. Их зубы — мутации строки «шаг 118 (выключение автоцены)»:
**13 из 13** пойманы своей проверкой. Среди них:

- снятое исключение Р-12 — красный тест «turning off with a write in flight is accepted» (`unfinished writes`);
- выключенная ветка стража отправки — запись выключенного предложения ушла в канал;
- исключение Р-12 на всё — красный смоук перехода в Smart Pricing.

## Что пришлось поправить в прежних тестах

- Смоук Р-12 ждал отказа при выключении с записью в полёте. Теперь две проверки: переход в Smart Pricing при записи в полёте — отказ с прежней причиной;
  выключение — принято.
- Браузерный смоук шага 105 сверял ряд фильтров Offers поимённо и выбирал фильтр держателя вторым по счёту. В ряду теперь «Repricing»; держателя
  смоук ищет по значению `NO_DATA`, а не по номеру.
- Тест равенства «база = правило экрана» на всех мирах стенда получил фильтр «Repricing» (On, Off и вместе с держателем и сортировкой).
  Встречены оба значения.
