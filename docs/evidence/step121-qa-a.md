# Шаг 121: подготовка QA-A без сервера

Задание владельца: сделать из чек-листа фазы 1 плана запуска всё, что не требует сервера (VPS покупается позже).

1. Видимая версия сборки: SHA и дата сборки в консоли, тот же SHA — в `/healthz`.
2. Сброс тестовых данных одной командой. Сброс отказывается работать, если база НЕ закрыта стражем P0-09.
3. Профиль развёртывания QA-A:
   - стенд, PostgreSQL, исполнитель заданий и Cloudflare Tunnel;
   - секреты — заглушками;
   - пошаговый README для свежего Ubuntu 24.04.
4. P1-04 — уже сделан шагом 120 (`fdda164`).

Решение — [ADR-0074](../adr/0074-qa-a-profile.md).

## Что сделано

| Где | Что |
|---|---|
| Версия сборки | Её задаёт развёртывание: `REPRACER_BUILD_SHA` — коммит, 7–40 шестнадцатеричных знаков, `-dirty` при правках; `REPRACER_BUILD_AT` — время сборки. Кривая версия — отказ при старте. Её называют: `/healthz` каждого процесса (общий `serveHealth`, строка `build <sha> <время>`), новый `/healthz` стенда и консоли (JSON, раньше раздачи файлов страницы), `/api/session`. Подвал каждой страницы — `Build <sha> · <время>`, полный SHA в подсказке; EN, DE, ES, FR |
| Стенд | `STAND_HOST` — слушать не только loopback (туннель — в соседнем контейнере). `STAND_STATIC_DIR` — собранный интерфейс отдаёт сам стенд: одна точка для туннеля, без `vite preview` и его отказа чужому заголовку Host. Р-127: стенд не на loopback отмечается во внешнем сервисе или выключает отметку явно (`REPRACER_STAND_HEARTBEAT=off`) |
| `scripts/qa-reset.sh` | Сброс базы QA на основе `demo-prepare.sh` → `scripts/db/prepare.sh`: миграции, роли, смоук. Порядок: (1) отказ базе без стража P0-09 — проверка функцией самой базы, `SET` в сессии её не подделает; (2) несуществующая база создаётся только с `--first-time`, и он отказывает существующей; (3) пересоздание; (4) регион US; (5) страж ставится снова и проверяется ДО подключения стенда |
| `deploy/qa/` | `compose.yaml` (PostgreSQL, стенд, исполнитель заданий, `cloudflared`; портов наружу нет), обёртка `compose.sh`, `deploy.sh` (версия → зависимости и сборка тем же образом Node → `build.env` → сброс → проверка), `reset.sh` (проверка стража ДО остановки чего-либо), `smoke.sh`, `ssh-gate.sh` (журналы, сброс и версия для Мердана без оболочки), образцы `qa.env.example` и `tunnel.env.example`, README |

Учтены находки репетиции QA-A (план исполнения, §2.4):

- `demo-prepare.sh` исполнитель заданий не запускает — здесь он свой сервис;
- вход закрывает Cloudflare Access cookie, а не Basic Auth (консоль ходит в API с `Authorization: Bearer`);
- `REPRACER_DEMO_ONLY=on`.

- размер сервера;

- One-time PIN — отдельное включение в организации Zero Trust;
