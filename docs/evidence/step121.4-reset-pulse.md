# Шаг 121.4: пульс показа журнала сброса

Решение владельца по докладу 121.3: пока идёт `reset`, печатать «идёт, N с» каждые 30 секунд, чтобы соединение не молчало и промежуточные
звенья его не резали. На сервер — со следующей выкладкой, отдельно не переразвёртывать.

## Повод

Проверка шага 121.3 на сервере: повторный `ssh … reset` закрылся с кодом 255 посреди работы. Сервер соединение не рвал: в журнале sshd
ничего нет, памяти хватило. Пока стенд поднимается, журнал минутами не растёт, и молчащее соединение закрыло промежуточное звено на стороне
клиента (VPN). Сброс доработал сам (шаг 121.3), но показ оборвался.

## Что сделано

`deploy/qa/detach.sh`: пока работа жива, показ раз в `QA_DETACH_PULSE_SECONDS` секунд (по умолчанию 30) печатает
`== <имя>: идёт, N с`.

- N — секунды от начала работы: время начала записывается в замок, поэтому повторный вызов называет то же время.
- Пульс — только в показе, журнал работы (`deploy/qa/state/<имя>.log`) не трогается.
- Интервал вне 1–9999 с — отказ при запуске, до любой работы.

README QA (§8, §9): пульс и совет `ssh -o ServerAliveInterval=30`.
