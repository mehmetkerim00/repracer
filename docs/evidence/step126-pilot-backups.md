# Шаг 126: копии базы пилота — вне сервера и с проверенным восстановлением [Р-249]

Решение владельца по докладу шага 124: «Копии базы — да, в составе deploy/pilot до запуска, пилот без них не стартует… суточный шифрованный дамп
существующим сервисом backup (gpg pg_dump) + хранение ВНЕ сервера. Цель выгрузки сделай настраиваемой; место выберем при развёртывании из
бесплатных (Cloudflare R2 free tier или ежедневная выгрузка на машину оператора). Ничего не покупаем. Восстановление — часть комплекта… Копия без
проверенного восстановления копией не считается. ClickHouse в пилоте не копируем… честной строкой».

## Что сделано

- **Копия** — сервис `backup` в `deploy/pilot/compose.yaml`: тот же образ и тот же скрипт, что у промышленного профиля
  (`deploy/production/backup-loop.sh`: `pg_dump` и роли кластера → `gpg` открытым ключом, 7 суток, отметка `BACKUP_FAILED`). Описан в compose
  пилота напрямую: через `extends` compose читает расширяемый файл целиком и требовал бы переменные прокси промышленного профиля. Строка
  подключения копии — `backup_pg_url` (суперпользователь: `pg_dump` под FORCE RLS), её делает `secrets.sh`.
- **Вынос с сервера, цель — `REPRACER_BACKUP_OFFSITE`**, без значения выкладки нет:
  - `r2` — сервис `backup-offsite` (`deploy/pilot/offsite-r2.ts`, профиль compose `r2`, его включает `compose.sh`): каждая готовая копия (есть
    файл сумм) — PutObject с подписанным хэшем тела, затем HeadObject; отметка `.offsite` — только когда длина в бакете сошлась; в бакете —
    7 суток (ListObjectsV2 страницами, DeleteObject по времени в имени); провал — алерт `BACKUP_OFFSITE_FAILED` и отметка файлом. Подпись —
    прежний SigV4 (`packages/amazon-notifications/src/sigv4.ts`) с хэшем тела снаружи: для S3 он — значение `x-amz-content-sha256`.
    Факты R2 — снимок [vendor/cloudflare/r2/2026-11-14](../../vendor/cloudflare/r2/2026-11-14/SOURCE.md).
  - `pull` — `deploy/pilot/pull-backups.sh` на машине оператора: по SSH забирает готовые копии, которых нет, сверяет SHA-256 до приёма,
    держит 7 суток, оставляет на сервере отметку `OFFSITE_PULLED`.
- **Проверка восстановления** — `deploy/pilot/restore-check.sh` на сервере: одноразовый контейнер образа базы без сети, закрытый ключ —
  со стандартного ввода, временный PostgreSQL, восстановление тем же `deploy/production/restore.sh`, затем регион, страж боевых записей [Р-247],
  журнал миграций и числа (`restore-check-inner.sh`); отметка `.restore-checked` рядом с копией.
- **Пилот без копий не выкладывается** — `deploy.sh` первой строкой после настроек спрашивает `backup-state.sh --ready`: выбрана цель, есть
  открытый ключ (и он не закрытый), закрытого ключа в каталоге секретов сервера нет, есть строка подключения копии, у R2 — адрес бакета и ключи,
  каталог копий есть и доступен на запись. `push-secrets.sh` не отправляет каталог, в котором лежит закрытый ключ.
- **Смоук** — сервис `backup` работает, ждёт первую копию (у R2 — и её вынос) до 5 минут, затем `backup-state.sh`: копия не старше 26 ч, вынесена
  (`.offsite` или `OFFSITE_PULLED` не старше 26 ч), у одной из ХРАНИМЫХ копий есть отметка проверки восстановления (отметка удалённой копии в
  счёт не идёт), отметок провала нет. Первая выкладка поэтому кончается красной строкой про копии — README, §5 и §8.
- **Ключ копий** — `deploy/pilot/backup-key.sh`, когда у владельца нет GnuPG: пара рождается в памяти одноразового контейнера на сервере,
  открытый — в каталог секретов, закрытый — в стандартный вывод (по SSH владельцу); `--public` — открытый из закрытого для нового сервера.
- **README** `deploy/pilot`, §8 «Копии базы» — три части, команды, ежедневный запуск выноса, беда, и строка «ClickHouse в пилоте не
  копируется» с тем, что теряется и что нет. `docs/data-retention.md` — срок копий вне сервера. Решение — Р-249.

  «копия потеряла страж боевых записей (Р-247)»). С настоящим gpg — CI.
- Модель бакета R2 в тесте требует подпись SigV4 с регионом `auto` и сервисом `s3` и сверяет `x-amz-content-sha256` с телом, как S3; настоящий
  R2 проверит первая выкладка (отметка `.offsite` — только после HeadObject).

## Без сервера не проверено

`backup-key.sh` и `restore-check.sh` — контейнерами Docker (у машины разработчика образы Docker Hub не скачиваются, OQ-114), сервис `backup` и
`backup-offsite` в compose, `smoke.sh` — первой выкладкой, как прочие скрипты пилота шага 124. Миграций нет.
