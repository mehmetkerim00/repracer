# Шаг 127: рамки Amazon без прочитанных значений — теневые решения с пометкой «цена удержана» (П1) [Р-250]

Решение владельца по аудиту авторизации Amazon 2026-11-14: «П1 (M) — SKU с рамками Min/Max: теневые решения считать и показывать с честной
пометкой «запись будет удержана: на SKU стоят рамки Amazon»; сама блокировка записи остаётся как есть». Порядок владельца: П6 (шаг 125) →
копии базы (шаг 126) → П1. Решение — [ADR-0077](../adr/0077-unread-channel-bounds-shadow-decisions.md).

## Что сделано

- **База (0230):** `channel_data.offer_channel_pricing_active` — ценообразование канала только у Automate Pricing; за ней — стражи назначения
  стратегии и включения движка (0085) и стратегия по умолчанию (0199). Страж привязки (`offer_mapping_channel_pricing_guard`) — то же правило
  своей выборкой; форма `IF pricing IS NOT NULL THEN` сохранена — её мутирует строка каталога шага 23.
- **Двойник в памяти** (`memory-store.ts`) — то же правило; **алерт обнаружения** `OFFERS_WITH_CHANNEL_PRICING` — только о предложениях с
  Automate Pricing (его текст говорит «наш движок для них не работает»); сценарий `amazon/pipeline/discovery-channel-pricing` пересобран построителем.
- **Модель консоли:** `channelPricingBlocks` — только Automate Pricing (как база), `channelBoundsUnread` — рамки без значений (пометка);
  `noteBlocksPricing` — какие пометки мешают включить движок и назначить стратегию (Offers, Strategies, предпросмотр стратегии, назначение через
  консоль); импорт стратегий файлом — тем же правилом. Список «offers with channel pricing» на Strategies — как запрос фактов базы: Automate
  Pricing (блок) и рамки без значений (цена удержана).
- **Тексты EN/DE/ES/FR:** пометка Offers «Price held: Amazon bounds» с объяснением (решения считаются, новая цена удержана и в бою, что
  сделать); страница пола — «values not read: decisions are calculated, new prices are held»; квитанция — у шага записи одобренного решения пункт
  «Amazon price bounds: … this price is held and not sent — in live too, not only in the shadow».
- **Блок записи — без изменений:** адаптер Amazon перед каждой отправкой читает листинг и с рамками отказывает `CHANNEL_BOUNDS_PRESENT`
  (AMZ_C03) — сценарии `amazon/adapter/*bounds*` стенда прежние и зелёные.
- Каталог мутаций: строка шага 107 «рамки без значений блокируют предложение» снята вместе с самим блоком. Документы: `docs/channels/amazon.md`,
  Р-250, ADR-0077.
