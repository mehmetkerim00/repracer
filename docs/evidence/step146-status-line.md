## Спецификация

### Где

Строка `nav.status-line` (доступное имя «Workspace status») стоит первой в `.world-content` на каждом экране рабочего пространства:
- восемь пунктов меню, кроме Omnibus;
- квитанция, страница предложения, Competition, массовые операции.

Демо-полоса остаётся над раскладкой, как была. Ничего не переезжает и не исчезает: строка — новый элемент над заголовком экрана.

### Что — четыре части слева направо

Каждое число — ссылка ровно на ту выборку, из которой посчитано.

| Часть | Определение | Слова (EN) | Ссылка |
|---|---|---|---|
| Режим цен | Действующая остановка человеком на весь тенант — «stopped». Иначе — по подключённым аккаунтам (`auth_status = ACTIVE`): все в тени — «shadow»; все в бою — «sending»; иначе — «mixed». Подключённых нет — «none» | «Repricing stopped by Jamie Lee since Nov 17, 09:12» / «Shadow mode — prices are not sent» / «Sending prices» / «Sending on 1 of 3 channel accounts; 2 in shadow mode» / «No channel account connected» | stopped → Stop pricing; shadow → Shadow mode; sending и mixed → Channels (там у каждого аккаунта пилюля режима); none → Channels |
| Остановки | Действующие остановки трёх видов — ровно те, что Stop pricing показывает действующими: остановки человеком, системные остановки витрин, недоверие каналу | «2 active stops» / «No active stops» | Stop pricing |
| Свежесть данных | Для каждого аккаунта, у которого есть включённые (`ENGINE`) предложения со стратегией из данных конкурентов: самое давнее последнее принятое чтение конкурентов (`competitor_state.observed_at`) среди них. Уровень: не старше 15 минут — fresh (`STRATEGY_STALENESS_SECONDS`: столько стратегия принимает чтение); не старше часа — ageing (цель круга опроса на пилоте, Р-240); старше — stale. Предложение без единого чтения — stale. Аккаунт без таких предложений в строке не показывается | «amazon.com · oldest reading 4 min» + пилюля «fresh» / «ageing» / «stale»; без чтения — «amazon.com · 3 offers not read yet» | Channels; на карточке аккаунта — та же строка тем же расчётом |
| Требует внимания | Предложения, которые цену не получат или не продаются, по причинам. Причины — одно правило у базы и экрана, у предложения их может быть несколько. Число в строке — предложения с хотя бы одной причиной | «5 offers need attention: 2 no unit cost · 2 Amazon bounds not read · 1 not buyable» / «Nothing needs attention» | Итог → Offers с фильтром «Needs attention: any»; каждая причина → Offers с фильтром этой причины |

### Причины «требует внимания»

| Код | Правило | Слова (EN) |
|---|---|---|
| `NO_UNIT_COST` | Нет себестоимости или действующей оценки комиссии — `cost` строки каталога, то же, что видит Offers (уточнено при правке: курс ЕЦБ — дело платформы, а не продавца, и в причину не входит; `write_scope_cost_ready` его требует). Без этого движок не включается (Р-131), у включённого замерзает цена (Р-244). У предложения в распродаже цена не замерзает (Р-227, шаг 142), но истёкшая комиссия — тоже дело продавца | «no unit cost or fees» |
| `AUTOMATED_PRICING` | Последнее наблюдение ценообразования канала: включён Automate Pricing Amazon (Р-120) | «Amazon repricer on» |
| `CHANNEL_BOUNDS` | Последнее наблюдение: рамки Min/Max Amazon есть, значений в валюте предложения нет (`channelBoundsUnread`, Р-250) | «Amazon bounds not read» |
| `NOT_BUYABLE` | Последний статус листинга Amazon — не BUYABLE (Р-239) или последнее состояние публикации Walmart — снят с публикации (Р-215) | «not buyable» |
| `TURNED_OFF` | Автоцену выключил человек: режим OFF и последняя строка журнала выключения — OFF (Р-242) | «turned off» |

Вне шага — кандидаты, названные поимённо:
- пол выше потолка: нужен расчёт пола по каждому предложению запросом;
- предложение без стратегии;
- остановленные — их считает часть «Остановки».

### Offers

В ряду фильтров — пятое поле «Needs attention» (`select` в `Field`): «All offers» / «Any reason» / пять причин.
- Адрес `#/w/<ws>/products/attention/<ANY|код>` открывает Offers с этим фильтром.
- Фильтр — по всему каталогу, как прочие. На PostgreSQL — запрос `consoleCatalogPage.offers.attention`, без базы — правило экрана; равенство держит тест на всех мирах стенда.
- Выгрузка Offers — по фильтру экрана (шаг 104).

### Поведение

- Строка — отдельный запрос `GET /api/worlds/<ws>/status`, параллельно экрану. Экран её не ждёт; до ответа — скелет высотой строки.
- Повтор — при каждом переходе между экранами.
- Ошибка запроса — строка «Status is not available» без кнопки, экран работает.

## Красный быстрый CI и исправление

Быстрый прогон [44087767726](https://github.com/mehmetkerim00/repracer/actions/runs/44087767726), `fast (2/2)`, step 85: «768px, competition: touch targets lower than 44px» — ссылки строки по 20 px. Правило касания действует ниже 1012 px (как у прочих целей касания), а 44 px у ссылок строки включались только ниже 768. Локально step 85 падал раньше — на известном 375 px `products/bulk` — и до 768 не доходил.

Исправление: 44 px — под тем же медиазапросом, что у прочих целей касания (`width < 63.25rem`); столбцом — по-прежнему только ниже 768. Смоук «step 146» проверяет и 768 px: на прежнем CSS красный («768: the status line links are 44px touch targets»), на новом — зелёный.
