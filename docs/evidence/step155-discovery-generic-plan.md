# Шаг 155: новые предложения с правилом умолчания на общем плане — находка выкладки QA-A

**Найдено при выкладке `fbe1438` на QA-A 2026-11-17.** В демо США не появились две новинки amazon.com («Bamboo cutting board, large», «Pour-over coffee dripper») — на них стоят примеры проверки #27 и строки состояния.

Журнал стенда: `demo US new offers failed: permission denied for table tenant`. Журнал PostgreSQL QA-A — та же ошибка **с 13 ноября**, с первых выкладок. Значит, это не от редизайна:

```
ERROR:  permission denied for table tenant
CONTEXT:  SQL expression "NEW.pricing_mode = 'KAUFLAND_SMART_PRICING'
             AND NOT EXISTS (SELECT 1 FROM tenant_data.tenant
                              WHERE tenant_id = NEW.tenant_id AND kaufland_smart_pricing_opt_in_at IS NOT NULL)"
        PL/pgSQL function tenant_data.write_scope_guard() line 23 at IF
```

## Причина

1. Страж единицы записи `tenant_data.write_scope_guard()` (0005) держал подзапрос к `tenant_data.tenant` в **одном выражении** с проверкой режима Smart Pricing.
2. Правило умолчания (шаг 103, 0199) назначает стратегию новичку узкой ролью `repracer_default_strategy` — UPDATE единицы в транзакции обнаружения. Права на `tenant` у этой роли нет и не нужно.
3. На своём плане PL/pgSQL выражение сворачивается: режим не Smart Pricing — подзапроса нет.
4. На **общем плане** (с шестого исполнения в сессии) подзапрос остаётся, и проверка прав идёт на весь запрос.

Итог: обнаружение отказывает целиком — все предложения страницы обнаружения, одной транзакцией. У продавца, который задал стратегию по умолчанию, новые предложения не появляются никогда, как только сессия пула перешла на общий план. Это путь пилота (Amazon US, умолчание на аккаунте).

Класс шага 61 (0160): там страж количества держал подзапрос к аккаунту одним выражением с проверкой поля. Тогда смоук на общем плане прогнал обнаружение **без** правила умолчания — поэтому этот случай он и не видел.

Локально не воспроизводилось: число исполнений до перехода на общий план зависит от статистики и пула.

## Исправление

**0236:** подзапрос к тенанту — только в ветке Smart Pricing, вложенным `IF`. Поведение стража не меняется: отказ «tenant has not opted in to Kaufland Smart Pricing» — тот же. Его держит смоук `smoke_app.sql`, прошёл.
