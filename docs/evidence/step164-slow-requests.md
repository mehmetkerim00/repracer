# Шаг 164: журнал медленных запросов консоли и стенда

Решение владельца по таймауту Price changes на QA-A: журнал медленных запросов в консоль — да, малым шагом:
- порог около 2 с;
- путь и длительность;
- без тел запросов.

Право токена Cloudflare на аналитику не добавляется.

## Что сделано

- **HTTP-слой** (`createStandServer`) — у стенда (QA-A) и у развёрнутой консоли один. Запрос API дольше порога пишет одну строку JSON:

  ```
  {"level":"WARN","code":"SLOW_REQUEST","details":{"method":"GET","path":"/api/worlds/demo%2Fus/decisions","query":{"period":"7d","kind":"WRITES","q":"…"},"status":200,"ms":2345,"clientLeft":false}}
  ```

  - **Путь** — без строки запроса.
  - **Параметры:**
    - значения — только у параметров выборки без текста продавца: период, вид, исход, страница, порядок, фильтры-перечисления;
    - у остальных (поиск, записка, идентификаторы) — только имя и «…».
  - **`clientLeft`** — клиент ушёл раньше ответа: соединение закрылось до конца ответа, например туннель по своему сроку или закрытая вкладка. Так таймаут Cloudflare отличается от медленного ответа, который дошёл.
  - Время — от прихода запроса до отправки ответа, в том числе у ответа 500.
  - Тела, токена, куки — нет.
- **Порог** — `REPRACER_SLOW_REQUEST_MS`, одним правилом у стенда и консоли (`slowRequestMsOf`):
  - не задано — 2000;
  - `off` — выключено явно;
  - иначе целые миллисекунды от 100 до 600 000;
  - кривое значение — отказ при старте.
- Обращение к часам (`performance.now()`) помечено `real-clock:` с причиной — правило шага 55.

Миграций нет.

## Красное сначала

- Тест консоли «step 164»:
  - на прежнем коде — красный: строк нет;
  - затем 1 из 1:
    - быстрый запрос — без строки;
    - медленный POST с токеном, телом и поиском — строка без них, параметры выборки — значениями;
    - запрос, брошенный клиентом, — `clientLeft: true`.
- Время утверждается только нижней границей — медленная машина её не нарушит. Правило прогонов-замеров её не считает замером.

- Тесты консоли — 50 из 50.
- Правила репозитория — 29 из 29.
- Типы — 0 ошибок.

## Что дальше

После выкладки на QA-A медленные запросы видны в журнале стенда:

```
deploy/qa/compose.sh logs --no-color stand | grep SLOW_REQUEST
```

Если таймаут Price changes повторится, строка покажет:
- дошёл ли запрос до стенда и сколько он шёл;
- ушёл ли клиент раньше ответа.

Если строки нет, а таймаут был — запрос не дошёл до стенда (сеть или туннель).
