# Шаг 165: смоук QA-A — новое предложение заводится при заданной стратегии по умолчанию

Решение владельца по следу бага шага 155:

> добавь в смоук QA-A проверку «новое предложение заводится при заданной стратегии по умолчанию» — красным сначала на коде до 0236. SMOKE GREEN, который пропускает мёртвое заведение предложений, — неполный смоук.

## Что сделано

- **`deploy/qa/new-offers-check.sql`** — два числа:
  - аккаунтов, у которых действующая стратегия по умолчанию задана (последняя строка журнала умолчания, Р-228);
  - сколько из них без единого назначения правилом (`strategy_assignment`: `DEFAULT_RULE`, `ASSIGNED`).
- **`deploy/qa/smoke.sh`** спрашивает базу QA этим файлом после стража P0-09. Красное:
  - умолчания нет ни у одного аккаунта (демо США задаёт его у amazon.com) — проверка иначе была бы пустой;
  - у аккаунта с умолчанием нет ни одного нового предложения — с подсказкой, где смотреть: `compose.sh logs stand | grep 'new offers'`.
- **SMOKE GREEN** называет число аккаунтов с умолчанием.
- На QA-A база собирается заново при каждой выкладке и сбросе. После посева «есть умолчание — есть его новички» — ровно путь демо (шаг 103): умолчание amazon.com, затем обнаружение двух новых листингов.
- README `deploy/qa`, §7 — пункт проверки.

Миграций нет.

## Красное сначала — на коде до 0236

Локальное демо, база собрана без `0236`. Файл миграции отложен только на фазу базы `demo-prepare.sh`, затем возвращён.

**Первые две попытки не воспроизвели отказ QA-A** — новые предложения заводились:
- **Просто без 0236.** На своём плане PL/pgSQL выражение сворачивается. До общего плана сессия пула локально не дошла, а на QA-A — дошла.
- **С `PGOPTIONS=-c plan_cache_mode=force_generic_plan`.** Пул задаёт свои `options` (`-c TimeZone=UTC`), и переменная окружения до сессий не доходит.

**Третья попытка:** общий план — настройкой роли пути решения `svc_app` (`ALTER ROLE … SET plan_cache_mode = force_generic_plan`) на время прогона, затем `RESET`.
- Журнал стенда: `demo US new offers failed: permission denied for table tenant` — ровно журнал QA-A с 13 ноября.
- Проверка — те же строки, что в `smoke.sh`, с локальным `psql` вместо `compose exec`:

  ```
  SMOKE RED: у 1 из 1 аккаунтов со стратегией по умолчанию новые предложения не завелись — журнал стенда: compose.sh logs stand | grep 'new offers'
  ```

**Зелёное — та же настройка роли, база с `0236`.**
- Журнал: `demo US: 2 new amazon.com offers found, default strategy «Beat the lowest by 1 cent»`.
- Проверка: `check GREEN: новые предложения по умолчанию заводятся (1)`.

Настройка роли снята — у `svc_app` строк в `pg_db_role_setting` нет.

## Не сделано

Автоматического теста проверки в CI нет — `smoke.sh` идёт только на сервере QA-A. Его строки проверены прогоном выше, синтаксис — `bash -n`. Первая выкладка с этим шагом покажет строку SMOKE GREEN с числом аккаунтов.
