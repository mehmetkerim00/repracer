# Шаг 166: Inventory — порядок «To publish» только внутри канала — #26 [Р-254]

Решение владельца по вопросу шага 159:

> сортируем только при выбранном фильтре канала: число принадлежит каналу, и сортировка честна только внутри одного канала. Без фильтра заголовок колонки не сортирует и подсказывает «choose a channel to sort». Никаких выдуманных агрегатов (max/сумма по каналам) не вводить.

## Спецификация (до правки)

Порядок Inventory задаёт поле «Sort by» (шаг 159), а не заголовок колонки. Решение применено к нему.

- **Вариант «To publish»** в «Sort by»:
  - без канала — недоступен, подпись поля: «Choose a channel to sort by “To publish”.»;
  - с каналом — доступен.
- **Снятый канал** возвращает порядок по доступному.
- **Ключ товара** — `toPublishKey` (stock-sync): число «to publish» его единственной включённой единицы количества этого канала.
  - Это то же число, что в строке канала («N to publish»): `publishedQuantity` с буфером, потолком и порогом аккаунта.
  - Нет такой единицы (синхронизация не включена, нет предложения) — числа нет.
  - Единиц несколько (два аккаунта или два региона одного канала) — числа тоже нет: максимум или сумма были бы выдуманным числом.
- **Порядок** — `compareStockRows`, одно правило у хранилища в памяти и у теста равенства с PostgreSQL:
  - товары с числом — по убыванию;
  - товары без числа — после, по доступному;
  - затем SKU.
  - Подпись поля при этом порядке: «Products with no single number to publish on this channel come last.»
- **Без канала — отказ, а не тихая подмена другим порядком:**
  - хранилища — ошибка `TO_PUBLISH_NEEDS_CHANNEL`;
  - маршрут экрана и выгрузка — 400 `BAD_PAGE` (один разбор, `stockFilterOf`).
- **PostgreSQL** — ключ коррелированным подзапросом только при этом порядке: единицы количества товара в канале, последняя строка настроек аккаунта, правило `PUBLISHED_SQL`. Без строки настроек — нули, как `channelRow`.
- **Выгрузка** называет порядок в «About this export» (`sort: to_publish`).
- EN/DE/ES/FR. Токены — существующие. Миграций нет.
