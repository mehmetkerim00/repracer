# Шаг 17: мутационная проверка схемы после исправлений [Р-95]

Метод — тот же, что в [step17-mutation-before.md](step17-mutation-before.md): на копии шаблона базы снимается ОДНА защита
(триггер, ограничение, право или условие в теле функции), после чего прогоняются проверки, которые каталог
`tests/db/mutations.mjs` заявляет для этой строки. Мутация считается пойманной, если упала хотя бы одна заявленная
проверка; строка ложна, если хотя бы одна её мутация не поймана. Контрольный прогон без мутаций обязан быть зелёным.

```
REPRACER_PG_URL=postgres://svc_app@127.0.0.1:55432/repracer_eu \
REPRACER_PG_ADMIN_URL=postgres://postgres@127.0.0.1:55432/postgres \
REPRACER_PG_TEMPLATE=repracer_template node scripts/db/mutation-check.mjs --jobs 2 --measure
```

Полный вывод — [step17-mutation-after.log](step17-mutation-after.log).

| Мутаций | 55 | 83 (+3 в перепроверке OQ-151) |
| Не поймано | **24** | **0** |

Первый полный прогон после исправлений дал одну непойманную мутацию: ветка стража
`channel_data.pricing_strategy_undercut_guard` «версия закреплена за единицей записи» (OQ-151). Причина — та же, что у
находок ревьюера: тест проверял следствие (подрез не стал истекающим при появлении новой версии), но никто не пробовал
запустить срок ПРЯМОЙ записью при закреплённой версии. В `undercut-eternal.pg.test.ts` добавлена такая попытка с проверкой
причины (`still pinned by a write scope`); перепроверка строки — 3 мутации из 3 пойманы
([step17-mutation-oq151.log](step17-mutation-oq151.log)).

Строки без мутаций (нечего снимать): 1–11 — свойства каталога (RLS, регистрация, политики, сроки, партиции, FK, BYPASSRLS,
SECURITY DEFINER, представления) проверяются самой проверкой схемы; 15 — данные справочника НДС; 36 — правило проверяло
ОТСУТСТВИЕ объектов входа шага 13.

## Что изменилось в защитах из-за первого замера

- Перекрывающиеся ограничения слепка (`explanation_no_channel_data`, `explanation_derives_no_channel`,
  `explanation_no_column_copies`) по одному не ловились — сняты (0064), поведение держит `explanation_keys_declared`.
- Метки смоук-тестов получили ожидаемую причину отказа [Р-94]; часть проверок оказалась зелёной из-за соседних защит.
- Неизменяемость проверяется попыткой изменения (`smoke_r65.sql`, общий блок по реестру) и свойством триггера (0067),
  а не именем `zz_append_only`.
- Права пути решения сверяются со списком разрешённого в обе стороны (0067) — мутация «выдать лишний GRANT» ловится
  проверкой схемы; смоук-отказ по правам её не ловил (INSERT всё равно падал по другой причине).
