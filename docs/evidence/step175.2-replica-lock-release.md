# Шаг 175.2: блокировка одной реплики консоли снимается до возврата `release()`

## Находка

Полный прогон шага 175 ([45559543482](https://github.com/mehmetkerim00/repracer/actions/runs/45559543482)) покраснел заданием `fast (2/2)`. Упал тест шага 64 «перезапуск консоли на той же базе» (`apps/console/test/demo-us-live.pg.test.ts`):

```
CONSOLE_ALREADY_RUNNING: another console process holds the single-replica lock … holder: not visible to this role
```

Следом каскадом упали остальные 11 тестов файла: консоль не поднялась, и их запросы получили `ECONNREFUSED`. Push-прогон того же SHA (`27196b5`) этот файл прошёл. Правки шагов 174–175 блокировки не касаются.

## Причина

`release()` блокировки одной реплики (шаг 57) закрывал соединение (`client.release(true)`) и возвращался сразу. Он не ждал, пока сервер базы завершит сессию, а сессионная advisory-блокировка уходит только вместе с ней.

Консоль, стартовавшая сразу после `close()` прежней:
1. получала отказ `pg_try_advisory_lock`;
2. к запросу о держателе сессии уже не было — отсюда «not visible to this role».

Гонка жила с шага 57. Проявляется, когда сервер базы под нагрузкой медленнее завершает сессию.

## Правка

`release()` снимает блокировку запросом `pg_advisory_unlock`, ждёт ответа базы и только потом закрывает соединение. Если соединение уже потеряно и запрос не прошёл, сессия и её блокировка уходят с закрытием, как прежде.

## Красное сначала

`apps/console/test/single-replica.test.ts` — журнал обращений к соединению, без гонки.

| Тест | На прежнем коде |
|---|---|
| блокировка снята в базе до возврата `release()`: «снять → закрыть», повторный вызов — ничего | `set → lock → destroyed` — снятия нет |
| снятие не прошло — соединение всё равно закрывается | снятия нет вовсе |

## Проверки

Локально на PostgreSQL:
- `guest-demo-live.pg.test.ts` — 6 из 6 (шаг 57: вторая консоль отказывает, держатель назван);
- `demo-us-live.pg.test.ts`, тесты шага 64 — 3 из 3 (перезапуск консоли на той же базе).

Миграций нет. Полоса — тяжёлая (сервер консоли).
