# Шаг 177: выбор для массовой правки границ — фильтры, «Select all matching», выбор через страницы (#39, часть 1)

Решение владельца 2026-11-25: #39 строится без дополнительного одобрения (собственные просьбы Мердана из «QA-A Testing 2.0»). Р-140 уточнён: выбор переживает страницы и фильтры, но с гарантиями видимости, и они — условие изменения:
- (а) постоянный счётчик «N selected · M outside current view»;
- (б) «Review selection»;
- (в) «Select all matching» — явное действие с бейджем;
- (г) предпросмотр перечисляет все затрагиваемые предложения.

Невидимого выбора нет. Эта часть — Costs & floors и массовая правка границ. Назначение стратегии, массовые операции с Offers и приглушение импорта цвета — шаг 178.

## Что было

- Список выбора правки границ показывал страницу таблицы второй раз, без фильтров и поиска.
- Выбор отдельных строк сбрасывался при листании (прежний Р-140).
- «Все» — только весь каталог галочкой.
- Предпросмотр показывал первые 50 строк из всех.

## Что стало

**Таблица выбора.** Таблица Costs & floors — она же таблица выбора:
- галочка в строке (`RowCheck`: доступное имя называет предложение; правило полей форм знает этот контрол);
- фильтры и поиск Offers — витрина, автоцена, «требует внимания», Setup, Money, поиск — общим компонентом `OfferFilterFields`;
- по всему каталогу той же выборкой сервера, что у Offers (база = правило экрана);
- «Showing N of M offers».

**Выбор** (`packages/console-model/src/selection.ts`) складывается из трёх частей:
- отмеченные строки;
- «все подходящие под фильтр» — бейджами;
- снятые вручную из подходящих.

Его раскрывает сервер, как «весь каталог» с шага 29: перечень каталога в тело запроса не помещается (64 КБ). Поэтому отмеченных и снятых вместе — не больше 1 000; больше — фильтром и «Select all matching», об этом сказано на экране.

**Гарантии видимости:**
- (а) строка «N selected · M outside current view» над таблицей всегда; числа считает сервер (`POST bounds/selection`) теми же выборками, что экран;
- (б) «Review selection» показывает только выбранное, страницами, с галочками; «Show all offers» — назад;
- (в) «Select all N matching» (без фильтра — «Select all N offers») добавляет бейдж «All matching: Storefront: amazon.com» с «Remove»; снятые раньше строки снова выбраны;
- (г) предпросмотр называет «Every offer in this edit (N)» и листает ВСЕ строки:
  - задание плана хранит строки базы в порядке экрана, с пометками первыми (`orderedPlanRows`);
  - `GET bounds/plan/<задание>` отдаёт их страницами;
  - первая страница — те же строки, что вид;
  - клиенту итог задания по-прежнему отдаёт только вид.

**All-or-nothing — прежний:** правка принимает выбор, сервер раскрывает его в перечень, и задание считает ровно его. Неверный выбор — 400 `BAD_SELECTION` словами.
