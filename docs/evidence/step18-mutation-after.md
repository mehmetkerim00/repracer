# Шаг 18: мутационная проверка по правилу «своя проверка» [Р-99]

Мутация поймана, только если упала её СВОЯ проверка (список `own` мутации в `tests/db/mutations.mjs`) с совпавшей причиной.
Проверка теста называет тест и причину — сообщение утверждения; проверка схемы — причину. Причина сверяется только с текстом
провала, без названия теста. Падение проверки соседней мутации той же строки — непойманная мутация.

## Первый полный прогон по Р-99 (каталог шага 17, без исправлений)

[step18-mutation-first.md](step18-mutation-first.md), [лог](step18-mutation-first.log): **98 мутаций, не поймано 17** (заявлялось
«1 из 83»). Разбор 17:

- **9 — формат причины в каталоге, а не дыра в защите.** Своя проверка упала, но причина была записана не в том виде, в каком её
  печатает отчёт теста (например, `'STOPPED' !== 'FORBIDDEN'` вместо `+ 'STOPPED' - 'FORBIDDEN'`), или утверждение не имело
  сообщения («Missing expected rejection.» не отличает одно утверждение от другого). Исправление: сообщения у утверждений.
- **4 — у защиты не было ни одной проверки:** срок выборки проверки остановки (`observed_at <= v_at`), контекст тенанта в
  проверке по выборке, «приглашение перепривязки — только участнику», триггер «одна действующая привязка». Добавлены тесты.
- **4 — ловила только соседняя защита:** копирование столбцов intent в решение (NOT NULL), `accepted < required` (ограничение
  записи проверки), условие «версия закреплена» в замене подреза (страж подреза), блокировка товара при фиксации (другие блокировки).
  Для `accepted < required` добавлен мир с двумя товарами по рынку, где отказ даёт именно эта ветка.

Ещё найдено при прогонах шага 18: имя копии базы в верхнем регистре не открывалось; причина сверялась с текстом, включающим
название теста (ложные совпадения); мутация членства в роли пережила удаление копии базы — роли общие для кластера (отозвано,
такие мутации раннер теперь отклоняет); ожидания проверки схемы указывали на 0067, а не на последнюю 0071.

## Итог шага 18

**Поправка по ревью шага 18 (находки 8, 9):** число ниже — нижняя граница непойманных. Для смоук-проверок раннер засчитывал своей
поимкой и исход «EXPECTED FAILURE HAD ANOTHER REASON» (отказала другая защита), метки сверялись как подстрока, а причина теста
могла совпасть с текстом `expected` в `assert.match`. Настоящее число по Р-99 требует исправленного раннера и нового полного прогона
(шаг 19). Пример: мутация «согласие от своего имени» (Р-101) отмечена пойманной, хотя отказала проверка роли.

[Таблица](step18-mutation-after-table.md), [лог](step18-mutation-after.log): **124 мутации, 41 строка каталога, не поймано своей
проверкой 5** — во всех пяти упала только соседняя проверка:

| Мутация | Что поймало вместо своей проверки | Оценка |
|---|---|---|
| Снят триггер копирования столбцов intent в решение (строка 28, 32, 39, 40) | NOT NULL столбцов решения | Своя проверка недостижима: без триггера решение не вставляется вовсе |
| Функция блокировки товара при фиксации решения — пустая (Р-96) | Тест конкурентного изменения границы остаётся зелёным: итог сериализуют блокировки при вставке решения | Возможно, функция избыточна; не удалялась без отдельного замера |
| Условие «версия закреплена» в замене подреза (OQ-151) | Страж подреза отклоняет запись раньше | Условие нужно, чтобы создание новой версии не падало; итоговый инвариант держит страж |
| Вид поля `$.format` заменён на `code` (находка 6) | Первым падает утверждение «реестр видов в БД равен коду» | Тот же тест, другое утверждение |
| Проверка видов скалярных полей слепка отключена (находка 8 ревью шага 17) | Первыми падают соседние утверждения того же теста | Тот же тест, другое утверждение |

Строки без мутаций: 1–11 и 15 (свойства каталога и данные — проверка схемы), 36 (отсутствие объектов входа). Мутации членства
в ролях в каталог не входят: они меняют кластер, а не копию базы.
