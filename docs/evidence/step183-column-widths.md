# Шаг 183: ширина колонок с памятью — #38, часть 4

Решение владельца 2026-11-25: #38 строится без дополнительного одобрения. Части 1–3 — шаги 180–182; эта — «Resizable columns + width memory» из оценки тикета, последняя.

## Спецификация (до правки)

Таблицы — те же, что у шага 182: Offers, Costs & floors (список границ; он же — список выбранного на Offers), Price changes (записи и все решения).

**1. Ширина колонки меняется.**
- У каждой колонки с подписью — ручка у правого края шапки (экран от 1012 px): тянуть мышью; с клавиатуры — фокус на ручке, ← и → по 16 px, Home и End — наименьшая и наибольшая (образец WAI-ARIA «разделитель окна»); двойной щелчок — ширина по умолчанию.
- Пределы — 64…640 px. Уже содержимого колонка не становится: таблица держит текст читаемым (раскладка таблицы прежняя, ширина — предпочтение).
- Ручка — разделитель окна (`role="separator"`, вертикальный, со значением ширины и доступным именем на четырёх языках «изменить ширину колонки …»).
- Колонка действий без подписи ручки не имеет.

**2. «Reset column widths»** — в шапке рамки, пока у таблицы есть заданная ширина.

**3. Память.** Ширины — выбор браузера по таблице (`localStorage`, `repracer.table-widths:<таблица>`, try/catch): переживают перезагрузку и возврат на экран. Ширина применяется только на экране от 1012 px; на планшете и телефоне — раскладка по умолчанию, правила 375 и 768 прежние.

**4. Таблица шире рамки** после расширения колонок — листается в своей рамке, шапка — у её края (шаг 182); страница вбок не уезжает.

Только существующие токены темы. Ничего не скрывается (Р-254).

Уточнение в ходе шага: клавиатура — по образцу WAI-ARIA «разделитель окна». Home и End — пределы, а не «по умолчанию», как в первой редакции спецификации. По умолчанию — двойной щелчок или «Reset column widths».

## Что было

Ширина колонок — только раскладкой таблицы: менять её было нечем, помнить — нечего.

## Что стало

`apps/console/src/table-frame.tsx`:
- `TableFrame` получил `table` — `offers | bounds | feed | decisions`. У каждой таблицы своя память; список границ на Costs & floors и список выбранного на Offers — одна таблица.
- `ColHead` — подпись колонки: ширина — переменной `--col-w` в `style`, ручка — `role="separator"`, `aria-orientation`, `aria-valuemin`/`aria-valuemax`/`aria-valuenow` (видимая ширина: уже содержимого колонка не становится), доступное имя `resizeColumn(подпись)` на EN/DE/ES/FR.
- Мышь — события указателя с захватом; отпускание ставит ширину по своей точке: последнее движение Chrome сливает с отпусканием, и первая редакция останавливалась на 7/8 пути — поймал смоук.
- `localStorage` `repracer.table-widths:<таблица>`: только числа в пределах, try/catch.

CSS — только от 1012 px:
- `table th[data-col][style] { width: var(--col-w); min-width: var(--col-w) }` — только у колонки, где ширину задали. Первая редакция (`th[data-col]`) проигрывала правилам колонок экранов (`table.products th { min-width: 72px }`), и колонка не росла — поймал смоук.
- Ручка — полоса 8 px у правого края подписи, черта видна при наведении, фокус — общим кольцом.

Подписи четырёх таблиц — `ColHead`: Offers (включая сортируемые колонки Buy Box), список границ, записи и решения Price changes. Колонки галочки и действий — без ручки.

**Найдено попутно — дефект шага 180.** Состояние свёрнутой боковины (`useState`) стояло в `WorldScreen` после раннего `return` «Workspace not found». Переход из пространства по адресу несуществующего ронял страницу целиком: «Rendered fewer hooks than expected», пустой экран. Хук перенесён выше. Тест шага 180 теперь переходит из пространства на несуществующее и ждёт карточку «не найдено» без ошибок страницы — красный на прежнем коде этой самой ошибкой. В main с шага 180 (`8cdcc0f`), на QA-A — с выкладки `78f6515`.
