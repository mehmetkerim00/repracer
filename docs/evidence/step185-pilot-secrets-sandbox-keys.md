# Шаг 185: ключи песочницы в файле боевого приложения — отказ `deploy/pilot/secrets.sh`; файл ключей читается как текст

## Что нашлось

2026-11-26 grantless-обмен LWA (`client_credentials`, scope `sellingpartnerapi::notifications`) повторялся по файлу ключей боевого приложения Amazon (`amazon-production.env`, вне репозитория). Значения при этом сравнивались только на равенство.

- `AMAZON_PRODUCTION_LWA_CLIENT_ID` совпадал с `AMAZON_SANDBOX_LWA_CLIENT_ID` из файла песочного приложения.
- Прежний секрет боевого файла — его отпечаток назвал владелец — совпадал с `AMAZON_SANDBOX_LWA_CLIENT_SECRET`.
- Значит, в файле боевого приложения лежала пара ключей песочного. Обмен 2026-11-15 шёл песочным клиентом и получал `invalid_scope`, и тот же клиент получает его и сейчас. Боевой клиент получает токен: 3 из 3, HTTP 200.

Файл ключей боевого приложения читает `deploy/pilot/secrets.sh` и уносит в пилот App ID, client ID и секрет LWA. С такими ключами пилот подключился бы к песочному приложению молча: формат у ключей обоих приложений одинаковый.

## Правка

`deploy/pilot/secrets.sh`:
- **Ключи двух файлов не совпадают.** App ID, client ID и секрет LWA боевого файла сверяются с теми же ключами файла песочницы (`REPRACER_AMAZON_SANDBOX_ENV`, по умолчанию `amazon-sandbox.env` рядом). Совпал хотя бы один — отказ с именами обеих переменных, и ни одного файла Amazon в каталоге секретов пилота не создаётся. Файла песочницы нет — сверять не с чем, сверка не идёт.
- **Отложенное «134».** Файл ключей больше не исполняется (`set -a; . file`). Строки `KEY=` читаются как текст (`key_line`):
  - строка одна;
  - строк больше одной — отказ;
  - кавычки вокруг значения и `\r` снимаются.

  Прежде значение с `|` в любой строке файла (так начинаются токены LWA, `Atzr|`) bash принимал за конвейер и печатал остаток значения.
- Значения по-прежнему не печатаются и не экспортируются: подоболочка, `printf -v`.
- Работает и на bash 3.2 из macOS (`/bin/bash`): ассоциативных массивов нет.

README пилота (`deploy/pilot/README.md`, «Что делает `secrets.sh`») называет оба свойства.

## Красное сначала

`scripts/test/pilot-secrets.test.ts` — данные синтетические, нужны bash и openssl.

| Тест | Прежний `secrets.sh` | После правки |
|---|---|---|
| Разные ключи двух файлов — в пилот уходит ровно боевое приложение (контроль) | ok | ok |
| Ключ боевого файла равен ключу песочницы (client ID, секрет, App ID) — отказ по имени, файлов Amazon нет | not ok: «LWA_CLIENT_ID: refused» — принят | ok |
| Значение с `\|` в соседней строке ничего не запускает и не печатается | not ok: остаток токена в выводе | ok |
| Две строки одного ключа — отказ | not ok: принято, взята последняя | ok |

## Проверки

Локально: тесты репозитория, затронутые правкой (секреты пилота, развёртывание, путь записи), правила репозитория, полнота сборки — в отчёте шага. Миграций нет.
