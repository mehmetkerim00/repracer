# Шаг 26: проверка периодических работ в живом режиме [Р-128]

Дата: 2026-09-18. Проверка — [tests/contract/src/scheduler-live.pg.test.ts](../../tests/contract/src/scheduler-live.pg.test.ts).
Данные синтетические.

## Как устроен прогон

Настоящий цикл процесса планировщика (`runScheduler`) работает **виртуальные сутки** на отдельной базе PostgreSQL. Наблюдение — запросы,
дошедшие до канала, и строки базы, а не вызовы функций.

| Что | Как |
|---|---|
| Планировщик | `runScheduler` с тактом 30 с; просыпается раньше, если ближайший срок работы ближе |
| Каналы | симулятор Kaufland с состоянием [Р-113] (два аккаунта: без уведомлений и с уведомлениями, которые теряются в 30 % случаев) и модель порта Amazon (40 офферов, потери `ANY_OFFER_CHANGED` 30 %) |
| Остальные процессы | между тактами — приёмник уведомлений и обход диспетчера записей |
| Время | виртуальные часы; сутки заканчиваются «сейчас», чтобы часы базы всегда были позже виртуальных |
| Товары | 26 товаров Kaufland: часто меняющиеся, редко меняющиеся, без движения цены, новые без истории (волатильный, неподвижный, без якоря проверки входов, с нашим Buy Box) и 12 товаров витрины `at` для массового сдвига |

Машинное время прогона — около 3 минут.

## Числа опросов за сутки по ярусам

| Класс товара | Что с ценой конкурента | Опросов за сутки (до исправлений) | Опросов за сутки (после) | Ярус |
|---|---|---|---|---|
| Часто меняющийся | случайное блуждание каждые 5 мин | 721 | **721** | горячий, 120 с |
| Редко меняющийся | 3 изменения за сутки | 25 | **25** | тёплый, 1 час |
| Без движения цены | цена не меняется | 2 | **2** | холодный, 24 часа |
| Новый без истории, волатильный | блуждание каждые 5 мин | **2** | **489** | проба → горячий |
| Новый без истории, неподвижный | цена не меняется | **2** | **25** | проба (сутки) → холодный |
| Новый, Buy Box держим мы | конкурент меняет цену выше нашей | **2** | **489** | проба → горячий |
| Новый без якоря проверки входов | блуждание каждые 5 мин | 2 | 25 | проба; ни один снимок не принят (OQ-186) |

Наибольший разрыв между опросами товара без движения цены — 24 часа: из опроса он не выпадает.

## Что нашёл первый прогон

| № | Находка | Итог |
|---|---|---|
| 1 | **Новый товар остаётся в холодном ярусе навсегда.** Ярус считается по движениям цены, а движения появляются только из опросов: холодный товар опрашивается раз в сутки и набрать их не может. Новый волатильный товар получал 2 опроса в сутки вместо 720 | **Исправлено**: пока наблюдения товара не охватывают сутки, волатильность неизвестна — проба не реже тёплого яруса (`volatilityKnown` в кандидате опроса, оба хранилища) |
| 2 | **Товар, где Buy Box держим мы, выглядит неподвижным.** Движение считалось по Buy Box, включая наше предложение: конкурент менял цену выше нашей — движения нет, товар уходил в холодный ярус и терял Buy Box незамеченным до суток | **Исправлено**: движение — только по ценам конкурентов (Buy Box конкурента, иначе наименьшая цена конкурента); `lastAccepted.buyboxIsSelf` в проверке входов |
| 3 | **Половина офферов Amazon не сверялась ни разу.** Вызов раз в 30 с при лимите 0,033 rps (30,3 с) — каждый второй вызов отклонял ограничитель, а отклонённое окно круга всё равно сдвигалось: 20 из 40 офферов имели 0 сверок за сутки | **Исправлено**: интервал 31 с (округление 1/0,033 вверх), окно, которое канал не отдал целиком, — провал запуска (номер окна не сдвигается), аккаунты Amazon стартуют со сдвигом. После: 1394 сверки у каждого оффера, отклонений ограничителя 0 |
| 4 | **Остановка витрины без ENGINE-товаров не снимается никогда.** Выборка для снятия [Р-52] бралась только из товаров со стратегией по данным конкурентов; на витрине без них — `HALT_REVIEW_NO_SAMPLE` каждые 5 минут и остановка навсегда | **Исправлено**: выборка — сначала товары с ценой из данных конкурентов, затем остальные товары витрины. После: остановка в 6:00, снятие выборкой в 6:30 (окно 30 минут) |
| 5 | **Суточная выгрузка сообщала отставание 17 часов в первом же такте.** Отставание считалось от слота, который был до появления работы | **Исправлено** (0094): отставание не считается раньше момента регистрации работы |
| 6 | **Провалившаяся работа повторялась каждую секунду.** Процесс, который просыпается к ближайшему сроку, видел слот провалившейся работы в прошлом; для вызова с лимитом канала это означало запрос в секунду | **Исправлено**: повтор не раньше min(интервал, 60 с) после провала |
| 7 | **Дефекты модели Amazon**, из-за которых сверка в модели не работала: ограничитель брал жетон на каждый товар пакета (реальный вызов — пакет до 20 товаров одним запросом), а снимок сверки выдавался с источником уведомления — сверка сравнивала уведомление с уведомлением | **Исправлено** в модели порта |

Первые шесть — дефекты продукта, седьмой — дефект модели.

## Что утверждает проверка после исправлений

Каждая из девяти работ каталога `JOB_CATALOG` имеет утверждение о наблюдаемом за сутки (работа без утверждения — красная сборка):

| Работа | Наблюдаемое за сутки |
|---|---|
| `competitor-poll` | числа опросов по ярусам (таблица выше), разрыв товара без движения цены ≤ 24 ч, 2882 запуска без провалов |
| `notification-loss-review` | модель потеряла 77 уведомлений из 246; вердикты «подозрение на потерю» и «задержка» есть, проверок с истёкшим сроком без вердикта не осталось |
| `amazon-reconcile-rotation` | каждый из 40 офферов сверен > 1000 раз, отклонений ограничителя 0, два вызова подряд не ближе 31 с |
| `halt-review` | массовый сдвиг ×1,25 на 12 товарах витрины `at` в 6:00 останавливает витрину, выборка снимает остановку к 6:30 |
| `offer-discovery` | 6 обходов (по два на каждый из трёх аккаунтов), `minimum_price` в кабинете канала найден — `KAUFLAND_SMART_PRICING_ACTIVE` [Р-12] |
| `price-days-close` | сутки цен закрыты в свёртку `price_daily` с числом изменений |
| `partitions` | секция журнала снимков на конец суток + 3 дня создана работой |
| `retention` | движения конкурентов старше двух суток удалены (до прогона они были) |
| `analytics-export-day` | провал выгрузки (ClickHouse в этом прогоне нет) — `ANALYTICS_EXPORT_FAILED` CRITICAL, слот работы продвигается |

## Чего проверка не покрывает

- **Выгрузка в ClickHouse** проверяется отдельно и только в CI: [history-survives-stop.pg.test.ts](../../services/scheduler/test/history-survives-stop.pg.test.ts).
- **Товар без якоря проверки входов** (нет себестоимости, истории и того же EAN на другом канале) не получает ни одного принятого снимка:
  история для якоря строится из принятых снимков, поэтому замкнутый круг не размыкается сам (OQ-186). Живой прогон это наблюдает (числа
  в таблице выше), отдельного утверждения о таком товаре в проверке нет — поведение зафиксировано открытым вопросом, а не тестом.
- **Ошибки модели канала становятся ошибками проверки**: находка 7 — тому пример.
