# Шаг 28: массовый импорт себестоимости [Р-134, Р-135]

Дата: 2026-09-18. Живой прогон — [tests/contract/src/cost-import-live.pg.test.ts](../../tests/contract/src/cost-import-live.pg.test.ts).
Данные синтетические.

## Зачем

Шаг 27 сделал себестоимость условием включения репрайсинга [Р-131] и там же измерил цену этого решения: **76 из 101 оффера** тестовых
данных её не имели. Заводить себестоимость руками по одному офферу — это и есть тот случай, когда продавец до конца настройки не
доходит. Импорт — часть онбординга [Р-134].

## Живой прогон: 10 000 строк, 15 % с ошибками

Выгрузка продавца — немецкий CSV (разделитель `;`, запятая в числах, `Artikelnummer;Einstandspreis;Währung;Provision %`), 10 000
строк по числу офферов плюс одна строка-дубль. Каждая седьмая строка (≈14,3 %) испорчена, вид ошибки чередуется. Путь — тот же, что
у экрана: чтение файла → подсказки колонок → предпросмотр → применение.

| Что наблюдается | Значение |
|---|---|
| Строк в файле | 10 001 |
| Будет применено | 8 571 (к 8 571 офферу) |
| Не сопоставилось | 1 430 |
| Офферов останется без себестоимости | 1 429 |
| Машинное время (чтение, предпросмотр, применение) | 11 секунд |
| Пакетов импорта в базе | 1 |
| Офферов с себестоимостью после импорта | 8 571 |

### Что продавец видит на экране

Заголовок на его языке (немецкий):
«10001 Zeilen in der Datei · 8571 werden auf 8571 Angebote angewendet · 1430 nicht zugeordnet · 1429 Angebote bleiben ohne
Selbstkosten».

Дальше — как прочитан файл («Gelesen als CSV mit dem Trennzeichen „;“»), какие колонки узнаны и почему (совпала заголовок,
заголовок содержит слово, значения похожи на суммы), первые 20 строк, которые применятся, и **список непримененных строк по
причинам** — с числом строк и примерами:

| Причина | Строк | Что это значит |
|---|---|---|
| `COST_MISSING` | 286 | в строке нет себестоимости |
| `COST_NOT_A_NUMBER` | 286 | себестоимость не число («k.A.») |
| `CURRENCY_NOT_OF_OFFER` | 286 | валюта строки не валюта оффера, а импорт не переводит |
| `OFFER_NOT_FOUND` | 285 | оффера с таким ключом нет |
| `OFFER_KEY_EMPTY` | 285 | в строке нет ключа оффера |
| `DUPLICATE_OFFER` | 2 | один оффер двумя строками: не применяется ни одна |

Внизу — три вещи, которые продавец должен знать до нажатия: «1429 Angebote bleiben ohne Selbstkosten — Repricing lässt sich dafür
nicht aktivieren (Р-131)», «Der Import wird vollständig angewendet: entweder alle hier gezeigten Zeilen oder keine» и «Für das
Anwenden eines Imports ist eine Anmeldung mit zweitem Faktor nötig (Р-135)».

## Что проверяет база

| Правило | Как проверяется | Проверка |
|---|---|---|
| Импорт применяется целиком [Р-134] | пакет объявляет число строк, отложенная проверка сверяет принесённое | смоук «a cost import that brings fewer rows than it declared» |
| Строка импорта не живёт без пакета | `CHECK (source = 'IMPORT') = (cost_import_id IS NOT NULL)` | смоук «a cost row of source IMPORT without a batch» |
| Импорт нельзя раздробить на транзакции [Р-135, риск 17] | строка обязана быть в транзакции своего пакета | смоук «a cost import row that belongs to a batch of another transaction» |
| Пакет — только со вторым фактором [Р-135] | страж `cost_import_requires_mfa` | смоук «a cost import without a second factor», тест `cost-import.pg.test.ts` |
| Массовая правка мимо импорта [риск 17] | окно: больше 5 предложений за 10 минут без второго фактора — отказ | смоук «prices of more than five offers changed within ten minutes without a second factor» |
| Правки со вторым фактором окно не считает | признак `created_with_mfa` ставит база, не приложение | тест «правка одного-двух предложений руками проходит без второго фактора» |
| Предпросмотр ничего не меняет | режим PREVIEW только читает | тест «предпросмотр импорта ничего не меняет» |
| Применяется ровно показанное | отпечаток предпросмотра сверяется при применении | тест консоли: устаревший отпечаток — 409 |

## Что нашло ревью шага и что изменилось

Первая редакция импорта проходила живой прогон, но до продавца бы не дошла: тело запроса консоли было ограничено 64 КиБ, то есть
примерно 2 180 строками, а клиент кодировал файл в base64 целиком, раскладывая его в аргументы одного вызова (`RangeError` на файле в
сотни килобайт). Живой прогон этого не замечал, потому что зовёт хранилище напрямую. Обе причины исправлены, и теперь тест консоли
отправляет выгрузку в 4 000 строк через HTTP.

Разбор чисел угадывал там, где угадывать нельзя: `10.505` читалось как 10 505,00 €, а комиссия `0,15` — как 0,15 % вместо 15 %.
Ошибка в тысячу и в сто раз не видна на экране, где показаны первые двадцать строк, зато видна в цене. Теперь это две отдельные
причины в списке непримененных (`COST_AMBIGUOUS_SEPARATOR`, `FEE_AMBIGUOUS_FRACTION`), а не догадка.

Номер строки, ради которого продавец и смотрит список непримененных, не совпадал с номером в его таблице: пустые строки и переводы
строк внутри кавычек сдвигали счёт. Номер теперь берётся из файла (`Sheet.lines`).

Подсказка колонок обещала «и даёт исправить», но выбора на экране не было. Теперь экран показывает колонки файла с заголовком и
примером значения, и выбор продавца сильнее подсказки.

Книга XLSX распаковывалась без предела: архив в 306 КБ разворачивался в 300 МБ. Теперь распаковываются только нужные части книги, с
пределом на часть и на книгу, а смещения из файла проверяются — битый архив отвечает своей причиной, а не исключением Node.

## Чего импорт не делает

- **Не переводит валюты.** Р-61 разрешает себестоимость в валюте возникновения, но перевод по курсу — это пол маржи, посчитанный из
  другого числа. Строка с чужой валютой перечисляется как несопоставленная; пробел назван на экране.
- **Не угадывает, какая из двух строк одного оффера верная**: не применяется ни одна.
- **Не разбирает форматы, кроме CSV и XLSX**: чужой файл — понятный отказ, а не молчание. XLSX читается своим кодом
  (ZIP + XML, `node:zlib`): формулы, стили и даты не интерпретируются — берётся значение, которое продавец видел в таблице.
- **Не переносит составляющие между областями**: импорт пишет себестоимость аккаунта и витрины и переносит прочие составляющие
  (логистику, упаковку, обработку, отгрузку) из прежней версии ТОЙ ЖЕ области. Составляющие, заведённые на уровне товара, остаются
  на уровне товара — а строка канала по порядку выбора пола (0051) сильнее товарной.
- **Не определяет кодировку** (OQ-200) и **не измерен на объявленном пределе в 200 000 строк** (OQ-199): замер есть только на 10 000.
- **Не проверяет правдоподобие себестоимости**: продавец может объявить 1 цент. От неверной себестоимости защищает только пол маржи
  [Р-83] — как и при ручном вводе.
