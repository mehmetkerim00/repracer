## Как воспроизвести

**Находка 1.** В своей базе, засеянной `smoke_app.sql`, от `svc_admin`:

```sql
BEGIN;
SELECT set_config('app.tenant_id','a0000000-…-00000000000a',true),
       set_config('app.user_id','a1000000-…-00000000000a',true);
INSERT INTO tenant_data.cost_profile (tenant_id, product_id, version, valid_from, currency,
                                      purchase_cost_minor, source, created_by_membership_id, created_at)
SELECT …, now() - interval '11 minutes' FROM generate_series(1,6) n;
```

Без `created_at` — `ERROR: prices of 8 offers changed within ten minutes without a second factor (Р-135)`.
С `created_at` задним числом — `INSERT 0 6`. Та же вставка в `min_price` отвергается стражем 0078:
`a bound version is created at the transaction time … backdated versions are not accepted`.

**Находка 2.** `INSERT INTO tenant_data.guardrail (tenant_id, scope_type, version, min_margin_bp, is_active, created_by_membership_id)
VALUES (…, 'TENANT', …, 0, true, …)` без `app.auth_mfa` — `INSERT 0 1`.

**Находки 3, 4.** `parseMoneyMinor('10.505')` → `{ok:true, minor:1050500}`; `parseMoneyMinor('12,3456')` → `{ok:true, minor:12345600}`;
`parseFeeRateBp('0,15')` → `{ok:true, bp:15}`.

**Находка 6.** Выгрузка живого прогона (10 000 строк вида `SKU-n;13,07;EUR;15`) — 228 693 байта, base64 — 304 924 символа против
`MAX_BODY_BYTES = 65 536`. Подсчёт предела: в 64 КиБ тела помещаются 2 183 строки. Через HTTP не проверял — стенд не поднимал.

**Находка 9.** Четыре последовательные транзакции от `svc_admin` без второго фактора: (1) `cost_profile` товара A-11 + `min_price`
уровня `WRITE_SCOPE`, (2) `cost_profile` A-12, (3) `cost_profile` A-13, (4) `cost_profile` A-14 → на четвёртой
`ERROR: prices of 6 offers changed within ten minutes without a second factor`.

**Находка 11.** Собран ZIP с одной записью `xl/worksheets/sheet1.xml` из 300 МБ пробелов: архив 306 246 байт, `parseXlsx` отрабатывает
за 377 мс, RSS процесса — 577 МБ, исключения нет.

**Находка 12.** У корректного XLSX подменено смещение центрального каталога в EOCD →
`RangeError [ERR_OUT_OF_RANGE]: The value of "offset" is out of range…` вместо `TableReadError`.

**Находки 5, 7, 8, 14, 19, 21, 22** — по чтению кода; воспроизведение требует либо браузера (7, 8), либо данных, которых сегодня
никто не пишет (14), либо файла, которого у меня нет (5, 22). В отчёте они помечены как рассуждение, а не как наблюдение.

## Что проверено и оказалось в порядке

- **Р-108, каталог мутаций.** `scripts/db/check-catalog-coverage.mjs` на базе со всеми миграциями шага зелёный: ни одна новая защита
  (шесть триггеров `cost_import`/`cost_profile`, пять CHECK пакета, `scheduled_job_retry_kind_known`) не осталась без строки каталога.
  Строки `STEP28_ROWS` именуют и защиту, и таблицу — то есть засчитываются по правилу находки 6 ревью шага 20.
- **Права и изоляция новой таблицы.** `tenant_data.cost_import`: RLS `ENABLE` + `FORCE`, политики `tenant_isolation`,
  `retention_read`, `retention_delete`; права только у `repracer_admin` (SELECT, INSERT), `repracer_owner` и `repracer_retention`.
  У пути решения прав нет, в `security.decision_path_allowed_privileges()` таблица не появилась [Р-96]. Триггеры
  `a0_admin_write_person_insert` и `zz_admin_write_audit_insert` на месте [Р-97], `zz_append_only` и `zz_no_truncate` — тоже,
  и у обоих есть своя смоук-проверка.
- **Очистка тенанта.** `tenant_data.cost_import` назван в `maintenance.purge_tenant_data` **после** `cost_profile` — порядок внешнего
  ключа соблюдён; у мутации «убрать таблицу из очистки» есть своя проверка схемы.
- **Целостность пакета.** Отложенная проверка «принесено ровно объявленное» действительно отложенная (`CONSTRAINT TRIGGER … INITIALLY
  DEFERRED`), а страж «строка живёт только в транзакции своего пакета» опирается на `row_in_current_transaction`, который со шага 21
  умеет подтранзакции. Тест `cost-import.pg.test.ts` утверждает, что частично применённого пакета в базе не остаётся.
- **Предпросмотр ничего не пишет.** В PostgreSQL режим `PREVIEW` откатывается через `RollbackWith`, и тест утверждает ноль строк
  `cost_profile` после него.
- **Отпечаток не тавтология на уровне консоли.** Применение заново читает файл, заново строит предпросмотр по **текущему** составу
  офферов и сверяет с присланным отпечатком: изменение мира между «посмотрел» и «применил» даёт 409. Тест консоли проверяет и 409,
  и 400 без подтверждения, и 403 `MFA_REQUIRED` при входе только паролем, и 403 для роли `VIEWER`.
- **Полнота списков.** Живой прогон утверждает `apply + skipped = строк в файле` — то есть ни одна строка не теряется молча; то же
  утверждение есть в модульном тесте предпросмотра. У каждой группы непримененных есть код, число строк, текст в DE и EN и примеры.
- **Дубль оффера.** Вторая строка того же оффера снимает и первую: применяется ноль строк вместо «какой-нибудь». Проверено тестом
  и живым прогоном (`hasCost('ws-1') === false`).
- **Валюта.** Строка в чужой валюте не переводится молча, а попадает в несопоставленные с отдельной причиной; пробел назван на экране
  (`IMPORT_NO_FX`) — это согласуется с Р-61 и Р-63.
- **Задача E.** `secretFromEnv` вне режима стенда отвергает значение переменной, и в тексте ошибки значения нет — проверено тестом
  `service-runtime` и тестами развёртываний всех трёх процессов; сами compose передают секреты только через `*_FILE`.
- **Задача C.** Конфигурации диспетчера и приёмника требуют адрес отметки, пока её явно не выключили; адрес обязан быть `https`;
  ошибка отметки не роняет процесс, а считается метрикой и пишется в журнал без адреса.
- **Р-133, арифметика пауз.** `retryDelaySeconds(86_400, f, 'INTERNAL')` = 60, 120, 240, 480 … с потолком в час; у `CHANNEL`
  поведение шага 27 не изменилось. Значение по умолчанию параметра — `'CHANNEL'`, то есть работа неизвестного вида ведёт себя
  консервативно; `retry_kind` в базе тоже по умолчанию `CHANNEL`.
- **Тесты без базы**, которые я запускал (`cost-import` 7/7, `service-runtime` 4/4, `scheduler` 17/17), зелёные; пропущенных нет.
