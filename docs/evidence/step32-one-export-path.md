# Шаг 32. Единый путь выгрузки

Р-145: выгрузка файла имеет ОДИН обязательный путь, и в обход него выгрузку написать нельзя.

## Сколько путей было

**Четыре.** Три живых и один мёртвый — все на момент, когда шаг 31 объявил вопрос закрытым:

| Путь | Как собирал файл | Чем это плохо |
|---|---|---|
| Доказательство Omnibus | частями, через общий помощник | — (его и чинил шаг 31) |
| Выгрузка ленты цен | частями, через общий помощник | — (починена ревью шага 31) |
| **Отчёт об импорте** | **целиком и синхронно, мимо помощника** | 27 МБ занимали бы поток целиком, как у доказательства до шага 31 |
| **`priceFeedCsv`** | **целиком, вторая копия сборки ленты** | не вызывался ниоткуда — мёртвый код, который ждал, когда им воспользуются |

Сверх этого в коде жили **три копии экранирования CSV**: в `exports.ts`, в `compliance.ts` и (до шага 31) в обработчиках.
Правка находки 12 ревью шага 24 («значение, начинающееся с `=`, электронная таблица выполнит как формулу») лежала в двух из
них отдельно друг от друга.

**Стал один.** Обработчик отдаёт имя, заголовок и СТРОКИ; байты из них делает исполнитель.

## Чем это удерживается

Тремя разными способами, потому что каждый закрывает свою дыру:

1. **Тип.** Хранилище, которое видит обработчик, — `Omit<PricingStore, 'saveBulkJobArtifact'>`. Обработчик, решивший
   положить файл сам, **не собирается**. Это сильнее договорённости: помощник `buildCsvInChunks` существовал и на шаге 31 —
   и не помешал написать сборку заново.
2. **Правило** (`apps/console/test/console.test.ts`). Смотрит весь код репозитория — `packages/`, `apps/`, `services/` — и
   ловит обход типа приведением. У правила четыре контроля: два положительных (ровно тот код, который шаг 32 из
   обработчиков убрал) и два отрицательных, отделяющих «объявить выгрузку» от «позвать её мимо пути»: хранилище обязано
   уметь класть файл, а отрисовщик — существовать.
3. **База** (0113). Это выяснилось при попытке назвать «единственный путь»: у таблицы файлов задания **не было ни одной
   защиты**. Кто угодно с правом исполнителя мог положить файл любому заданию, с любой контрольной суммой.

## Что нашли эти три способа

| Нашло | Что именно |
|---|---|
| Правило | Отчёт об импорте собирал файл целиком и синхронно — третий живой путь |
| Правило | `priceFeedCsv` — мёртвая вторая копия сборки ленты |
| **Стражи базы** | **Хранилище не называло базе аренду при записи файла.** До шага 32 это проходило молча; со стражем «файл кладётся только к своему идущему заданию» — отказ. То есть процесс, потерявший аренду, дописывал файл заданию, которое уже взял другой |
| Стражи базы | Проверка формата суммы (`sha256 ~ '^[0-9a-f]{64}$'`) стала недостижимой — удалена как дубль [Р-104] |

Последнее — не теория: страж потребовал аренду, и живой путь записи файла сразу перестал работать, потому что аренду он
базе не называл. Раньше не называл тоже, просто спросить было некому.

## Стражи файла задания (0113)

| Страж | Что запрещает | Своя проверка |
|---|---|---|
| `a_bulk_job_artifact_digest_matches` | контрольная сумма не совпадает с содержимым | `a file whose checksum does not match its content (Р-145)` |
| `b_bulk_job_artifact_own_job` (аренда) | файл заданию, которого этот процесс не держит или которое не идёт | `a file written to a job this process does not lease (Р-145)` |
| `b_bulk_job_artifact_own_job` (вид) | файл виду задания, который файлов не делает | `a file attached to a job kind that gives the seller no file (Р-145)` |
| Правило схемы 14д (0114) | список видов называет вид, которого нет | проверка схемы: `names a bulk job kind that does not exist` |

Контрольная сумма считается по содержимому (`encode(sha256(convert_to(content,'UTF8')),'hex')`), а не принимается на слово.
Причина простая: продавец сверяет по ней скачанный файл [Р-123], а сумма, объявленная тем же кодом, который собрал файл,
подтверждает только саму себя.

**Мутационная проверка строки Р-145: 5 мутаций, не поймано своей проверкой — 0.** Первый прогон дал 1 непойманную: каталог
мутаций смотрел на ПРЕЖНЮЮ проверку схемы (0112), в которой правила 14д ещё нет. Это ровно то, ради чего мутации и нужны —
правило, которое некому применить, работает как отсутствующее.
