# Шаг 34. Онбординг живым прогоном на демо-тенанте

Прогон — `apps/console/test/onboarding-live.pg.test.ts`: настоящий HTTP-сервер стенда, PostgreSQL, фоновый исполнитель
заданий, симулятор Kaufland под планировщиком на виртуальных часах. Тест ходит по серверу как браузер [Р-142]: вход,
токен, второй фактор там, где его требует операция. Данные синтетические.

## Итог

**Онбординг прошёл целиком — от пустого тенанта до первого решения с объяснением.** С первой попытки не прошёл: прогон
споткнулся восемь раз, семь из них — дефекты продукта, а не теста.

| Шаг пути | Что делал прогон | Проверяемое состояние |
|---|---|---|
| Тенант | демо-тенант создан провижинингом, 200 предложений без себестоимости и границ | `TENANT` завершён |
| Канал | аккаунт Kaufland на симуляторе активен; Amazon — «ожидает доступа» | `CHANNEL` завершён, у Amazon два названных препятствия |
| Себестоимость | CSV на 150 из 200: артикул, закупочная цена, валюта, комиссия %, фиксированный сбор; предпросмотр → применение со вторым фактором | 150 из 200; шаг НЕ завершён, пока набор не сужен |
| Сужение | `onboarding/narrow` до предложений с готовой себестоимостью | набор 150, `COSTS` завершён |
| Границы | массовая правка 12,00–30,00 €: экран различий → применение; применение одним паролем — **403** | `BOUNDS` 150 из 150 |
| Стратегия | предпросмотр по набору → назначение | `STRATEGY` 150 из 150 |
| Включение | задание `REPRICING_ENABLE` | `ENABLE` 150 из 150, путь — `DONE` |
| Первое решение | два виртуальных часа работы планировщика | 9000 решений, 756 записей цены применены симулятором; «почему эта цена» — пять шагов, ни одного `UNKNOWN` |

Повторное открытие пути после каждого шага возвращает `resumeAt` на следующий незавершённый — возобновление проверено
на каждом переходе, а не один раз в конце.

## Где споткнулся

| № | Что случилось | Что это было | Исправление |
|---|---|---|---|
| 1 | Включение отказало всем 150: `FEE_ESTIMATE_MISSING`, хотя шаг себестоимости был зелёным | **Дефект пути:** шаг считал «себестоимость есть», включение требует ещё полной оценки комиссии | один критерий на оба — `tenant_data.write_scope_cost_ready` |
| 2 | Задание включения «выполнено», на экране — ничего; 150 отказов видны только в базе | **Дефект экрана:** Р-147 отдаёт наружу только `result.view`, а обработчик его не заполнял | `view` с разбивкой по причинам и примерами; экран называет отказанные предложения |
| 3 | Сужение набора по признаку «есть себестоимость» из модели консоли разошлось с базой | **Два источника правды** | сужение считает база той же функцией |
| 4 | Список решений после двух часов — 5,8 МБ одним ответом | **Экран без страниц** — тот же класс, что семь находок шага 29 | `decisionListView`: страницы на сервере, 87 КБ на страницу |
| 5 | Экран остановки у тенанта без канала — 500 | `live.accounts[0]!` | `409 NO_CHANNEL` с текстом в словаре |
| 6 | Импортированная себестоимость «ещё не действует», решений ноль | Виртуальные часы мира стояли на 4 часа в прошлом, а консоль пишет по часам базы | демо живёт в настоящем; зафиксировано в ADR-0033 |
| 7 | 2710 записей цены отброшены адаптером как `VALIDATION` | Идентификаторы единиц демо с ведущими нулями; адаптер прав — таких у Kaufland не бывает | идентификаторы `340100001…` |
| 8 | Алерты `KAUFLAND_ACCOUNT_UNAVAILABLE` | Планировщик демо обслуживал ВСЕ активные аккаунты базы, а не свой | планировщик мира ограничен своим аккаунтом |

Находки 1–5 — продукта; 6–8 — мира демо, но 6 стала правилом для любого будущего стенда. По находке 7 моя первая
гипотеза («сработала остановка по массовому сдвигу») была неверной — причину показал журнал записей, а не догадка.

## Пустые состояния (задача D)

Новый тенант без единого предложения, свой владелец. Все одиннадцать экранов мира отвечают 200 и отдают осмысленное
пустое состояние; самый тяжёлый ответ — 3 КБ, самый долгий — 46 мс. Экран остановки при отсутствии канала отвечает
`409 NO_CHANNEL`, а не 500. В интерфейсе пустые экраны товаров, границ и стратегий ведут на путь онбординга; спиннер
снимается и на пустом ответе, и на отказе.

Чего проверка НЕ делает: она смотрит ответы сервера и модели экранов, а не пиксели — отрисовку React в браузере живой
прогон не выполняет (так же, как Р-136 на наполненных экранах).

## Чего демо-тенант не может показать из того, что покажет живой канал

1. **Спрос.** В симуляторе нет покупателей: нет продаж, оборота, влияния цены на продажи. Демо показывает, КАК движок
   решает, но не показывает, что решение принесло. Отчёт «пол удержал цену N раз» [Р-117] считается, «вы продали бы на X
   дешевле» — нет.
2. **Настоящее правило Buy Box.** Модель отдаёт Buy Box самой низкой цене. У Kaufland правило не опубликовано (K-вопросы),
   у Amazon оно заведомо сложнее. Стратегии «держать Buy Box» на демо выглядят успешнее, чем будут.
3. **Поведение канала, которого мы не знаем.** Все открытые вопросы K-04…K-17 в демо — параметры модели в положении
   «по документации». Задержка применения цены, нетто `listing_price` (K-12), потеря `buy_box_changed` — на демо
   выключены; на живом канале каждый может оказаться включённым.
4. **Вход и выход продавцов.** Три конкурента у каждого предложения — всегда три. Нет нового продавца, нет ушедшего, нет
   конкурента без остатка.
5. **Amazon и eBay.** Демо — только модель Kaufland по HTTP. Чужой репрайсер [Р-115], недоверие каналу [Р-116],
   асинхронная запись с обратным чтением, бюджет 250 правок eBay — не показываются вовсе.
6. **Подключение канала и регистрацию.** Демо начинается с уже подключённого аккаунта (OQ-213): ввод ключей, проверка
   прав, первый импорт каталога из канала на демо не проходятся.
7. **Лимиты и отказы канала под нагрузкой.** 111 запросов в секунду, 429, частичные отказы `units/bulk` — симулятор их
   умеет, сценарий демо их не включает, чтобы показ не выглядел поломкой.
8. **Историю.** Omnibus [Р-123] на демо честно говорит «видим N дней» — и N мало: мир родился при запуске. Тридцать суток
   истории и скидку против неё демо не покажет, пока не проживёт их.

Общее: демо доказывает, что НАШ путь работает целиком. Оно ничего не доказывает про канал — для этого по-прежнему нужен
доступ.

## Демо для показа

`REPRACER_DEMO=on` при запуске стенда на PostgreSQL добавляет мир `demo/kaufland`: те же 200 предложений, виртуальная
минута идёт за секунду. Метка «демо» — в списке миров и баннером на каждом экране мира, то есть везде, где есть деньги.
