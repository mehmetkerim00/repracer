# Ревью шага 37

Ревьюер — отдельный агент, только чтение, со своей базой `review37` из шаблона (создана и удалена им же). Он разбирал
конфигурации развёртываний тем же окружением, которое даёт compose, ходил запросами по своей копии схемы и прогонял
тесты без базы. Живые прогоны и `*.pg.test.ts` не запускал — сказал это сам.

**Находок — 18: критичных 3, существенных 7, мелких 8.** По правилам скорости исправлены критичные и существенные
(10 из 18); мелкие вынесены списком в отчёт шага для следующего.

## Критичные — исправлены

| № | Находка | Что сделано |
|---|---|---|
| 1 | **В работе консоль ушла бы под одной ролью.** Исполнитель заданий выводил роли подстановкой `svc_app@` → `svc_admin@`; в работе строка подключения несёт пароль (`postgres://svc_app:ПАРОЛЬ@…`), подстроки `svc_app@` в ней НЕТ, замена молча ничего не меняет — и три пула подключаются как `svc_app`. Прогоны и смоук строят строки БЕЗ пароля, поэтому всё зелено, а работа сломана [Р-90] | Роли передаются ЯВНО (`pgUrlsByRole`). Подстановка осталась только там, где строки без пароля, и теперь она падает вслух, если ничего не заменила: молчаливый уход под чужой ролью невозможен |
| 2 | **Развёртывание консоли не стартовало бы по своей же документации**: compose безусловно называет файл секрета внешней отметки, а выключатель по умолчанию пуст — процесс требует файл, которого у проекта нет (OQ-188). Зелено только потому, что надстройка CI выключает отметку, а проверка конфигурации знает ТОЛЬКО связку с надстройкой | Умолчание — `off`, и это названо в примере окружения и README. Главное: проверка конфигурации развёртывания идёт ДВАЖДЫ — с надстройкой CI и БЕЗ неё. Проверка, знающая только надстройку, слепа ровно к тому, что надстройка чинит |
| 3 | **Сухой режим почты (задача D) был недостижим в развёртывании**: «настроено» определялось наличием ИМЕНИ переменной, а compose безусловно называет `REPRACER_MAIL_API_KEY_FILE` — процесс отказывался стартовать и винил оператора в переменной, которую задал сам compose | «Настроено» решают ЗНАЧЕНИЯ (`API_URL` и `FROM`), которые дал оператор. Адрес оператора обязателен только при настоящей отправке: всухую платформенное письмо честно отмечается `NO_OWNER_EMAIL` |

## Мелкие — отложены в следующий шаг

1. Ключ гостевого издателя живёт в памяти процесса: две реплики консоли за прокси дадут гостям случайные 401. Нигде не сказано «консоль — один экземпляр» (у планировщика такая оговорка есть).
2. `static.ts`: символическая ссылка ВНУТРИ каталога сборки отдаёт файл снаружи (`resolve` лексический, `statSync` идёт по ссылке).
3. `static.ts`: адрес с неизвестным расширением (`/robots.txt`) отдаёт `index.html` с кодом 200, хотя правило в шапке файла обещает 404 запросу за файлом.
4. «Гость гостем навсегда» держится унаследованным списком прав, а не названной причиной: снятие признака отказывает как `permission denied for table membership`. Смоука на этот случай нет.
5. Комментарий в `console-service.ts` говорит, что гостевой издатель отличается от настоящего схемой `https` — неправда, поставщик тоже https.
6. `tests/db/smoke_alerts.sql`: два оператора склеены в одну строку — валидный SQL, но читается плохо.
7. `dictionary.test.ts` обходит только `packages/` и `services/`: алерт, поднятый из `apps/`, правило не увидит, и «у каждого события есть текст» окажется ложным молча.
8. Незакоммиченные правки в рабочем дереве на момент ревью (закрыто коммитом того же шага).
