# Шаг 45: клик пользователя агентства — до и после Р-182

Прогон `apps/console/test/agency-click.pg.test.ts`: один пользователь — владелец в 50 тенантах (агентство, Р-9), консоль
с мирами тенантов из базы. Считаются ОБРАЩЕНИЯ к базе всех пулов консоли на один запрос страницы: одиночные запросы и
каждый запрос клиента внутри транзакции (BEGIN с контекстом тенанта, запрос, COMMIT — каждое отдельно: это сетевые
обходы). Три повтора каждого клика после прогрева; разброса нет. Данные синтетические.

| Клик | До Р-182 | После Р-182 | Что осталось |
|---|---|---|---|
| список миров (`GET /api/worlds`) | 452 | **2** | вход (членства пользователя) и одно обращение за счётчиками всех 50 тенантов |
| экран пути в одном мире (`…/onboarding`) | 164 | **16** | вход, аккаунты ОДНОГО мира, сам экран |
| товары в одном мире (`…/products?limit=200`) | 171 | **23** | вход, аккаунты одного мира, состояние экрана |

Откуда было 452: список собирал все 50 миров (аккаунты каждого — транзакция из трёх обращений), затем для каждого —
счётчики и аккаунты ещё раз. Клик в ОДИН мир платил то же за 49 чужих.

Пределы прогон утверждает (список ≤ 3, экран пути ≤ 20, товары ≤ 30) — они не зависят от числа тенантов: вернись сборка
всех миров на запрос, клик снова вырастет на три обращения на тенант.

## Кэш и членства

Список тенантов пользователя кэшируется по ключу «пользователь + отпечаток членств». Отпечаток берётся из principal,
который вход читает из базы при каждом запросе (`security.resolve_external_identity`), поэтому:

- отозванное членство убирает мир из списка СЛЕДУЮЩИМ запросом, и прямой адрес мира отвечает 404;
- новое членство добавляет мир следующим запросом, с ролью из свежего членства;
- на нескольких репликах консоли шина инвалидации не нужна: у каждой реплики ключ меняется сам.

Оба свойства утверждает второй тест того же файла. Срок записи (60 с) — страховка для того, чего членство не меняет:
переименование тенанта и его закрытие (`OFFBOARDING`, `CLOSED`); даже в этот срок роль в мире берётся из свежих
членств, и экраны читают данные тенанта под его контекстом в базе.
