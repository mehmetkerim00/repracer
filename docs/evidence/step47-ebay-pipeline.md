# Шаг 47, A–C и E: eBay в пути решения — сценарии, каталог, заказы

Данные синтетические. Фикстуры eBay — происхождение `RECONSTRUCTED_FROM_SANDBOX` с рецензией: у каждого обмена стоит
пометка `SANDBOX` или `SYNTHETIC`.

## A. Путь решения eBay

Хранилище в памяти принимает канал EBAY. Десять сценариев `pipeline-*` идут через путь решения на памяти
(`ebay.contract.test.ts`) и на PostgreSQL (`ebay.pipeline.pg.test.ts`). Отдельный тест требует, чтобы каждый сценарий
памяти шёл и на PostgreSQL. Набор — обязательный набор Kaufland и Amazon плюс два своих сценария.

| Сценарий | Что показывает |
|---|---|
| `fixed-price-confirmed` | Пересчёт по себестоимости, стратегия FIXED. Цена уходит ровно с двумя знаками, подтверждение — Browse |
| `gate-bounds` | Обе границы вне движка: `BELOW_MIN_PRICE` и `ABOVE_MAX_PRICE` хранятся как `REJECTED_BY_GATE` [Р-43, Р-44] |
| `max-price-missing` | Без `max_price` включение отказывает `MAX_PRICE_MISSING`; после задания границы проходит |
| `tax-regimes-margin-floor` | EBAY_DE — маржа от цены без НДС, пол 19,15. EBAY_US — цена нетто [Р-58] |
| `halt-manual-only` | Системная остановка не держит фиксированную цену [Р-51]; снятия выборкой нет (`MANUAL_ONLY`, 0140) |
| `kill-switch-tenant-stop` | Наблюдатель остановить не может. Остановка тенанта оператором — HELD с `PRICING_STOPPED` |
| `write-queue-second-not-lost` | Обрыв соединения даёт `OUTCOME_UNKNOWN`. Вторая цена ждёт и уходит после сверки [Р-64] |
| `browse-vat-no-distrust` | Browse ×1,19 с `taxes` — цена покупателя отдельно, недоверия нет [Р-186]. Алерт `EBAY_BUYER_PRICE_VAT_ON_TOP` один раз |
| **`budget-exhausted-mid-day`** | Второй слой бюджета: 189 попыток за 5 часов, 190-я уходит, следующая — `BUDGET_EXHAUSTED` с причиной [Р-163] |
| **`unmigrated-write-blocked`** | У листинга нет `offerId` — запись отклоняется до вызова канала. На PostgreSQL единицу записи не принимает база |
| `discovery-catalog` | Две фазы курсора: Inventory API, затем GetMyeBaySelling (EBAY_C16) |

Сценарий `discovery-catalog` идёт только на памяти. Каталог из обнаружения на PostgreSQL проверяется отдельным тестом
(ниже).

Тесты, которые может проверить только PostgreSQL:
- `offer_mapping_check5` не даёт единицу записи цены у листинга с `ebay_migration_status = REQUIRED` [Р-2, Р-164].
- Первый слой бюджета — `edit_budget` в базе. На 191-й попытке он завершает запись `BUDGET_EXHAUSTED`, а решение
  сохраняется. Раньше отказ базы откатывал решение целиком; теперь он идёт через точку сохранения.
- Аккаунт eBay в тени: решение посчитано, запись `SHADOW_HELD`, до канала не дошло ничего [Р-169].
- Стратегию по данным конкурентов база отклоняет, фиксированную и маржинальную принимает [Р-39].
- Обнаружение через путь решения заводит каждый листинг в каталог со своим правом на запись (0140).

## Р-187. Модель eBay в симуляторе

`tests/contract/src/simulator/ebay-channel.ts` отвечает кодами песочницы:

| Код | Когда |
|---|---|
| 25016 | Цена ниже EUR 1.00 |
| 25604 | Чужое предложение или SKU |
| 25709 | Неверное значение — отказ всего запроса |
| 25712 | Больше 25 запросов |
| 25713 | Листинг не мигрирован |
| 25004 | Количество 0 — ошибка при применённой записи, листинг `OUT_OF_STOCK` |
| 207 | Смешанный пакет |

Параметры модели с умолчанием «как песочница»: E-02, E-04, E-06, E-12, E-13, E-15, E-16, E-17. Каждому соответствует
вариант сценария, который переворачивает исход. Тест требует, чтобы каждый параметр был проверен хотя бы одним
вариантом.

## B. Каталог из обнаружения eBay (0140)

| Листинг | `ebay_migration_status` | Сопоставление | Единица записи |
|---|---|---|---|
| Под Inventory API | `NOT_REQUIRED` | `ACTIVE` | цены, режим OFF, ключ бюджета — номер листинга |
| Фиксированная цена не под Inventory API | `REQUIRED` | `MIGRATION_REQUIRED` | нет |
| Аукцион | `INELIGIBLE` | `INELIGIBLE` | нет |
| Без SKU | `REQUIRED`/`INELIGIBLE` | по номеру листинга | нет |

Повторное обнаружение ничего не дублирует. Листинг, мигрированный позже, завершает прежнее сопоставление (`ENDED`) и
получает действующее с единицей записи. У сопоставления eBay номер листинга и формат обязательны
(`offer_mapping_ebay_identity`). Единицу записи без SKU не даёт страж единицы. Строка каталога мутаций Р-164 — 6 из 6.

## C. Заказы eBay

Fulfillment API `getOrders` читается по времени изменения заказа (`lastmodifieddate`, поле — (проверить), E-20),
страницами. Разбирается только белый список полей без данных покупателя (EBAY_C17). Незнакомый статус или неизвестная
витрина — строка пропускается и считается в журнале, а не угадывается. Строки заказа идут в тот же конвейер резерваций,
что у Kaufland и Amazon [Р-25].

Сценарии: `orders-whitelist` и `orders-shipment-before-window` — заказ создан за 72 часа до окна и отгружен сейчас,
строка SHIPPED. Живого заказа нет: согласия продавца с `sell.fulfillment.readonly` и заказа тестового покупателя нет.

## E. Хвосты шага 39

- **Повтор записи после 401 списывается в счётчик правок** (`recordSent`) — повтор тоже попытка правки [Р-19, Р-163].
- **Снимок E-01 не оформлен**: каталога `vendor/ebay/incoming` нет, ячеек [док] у eBay по-прежнему 0.
- Новые вопросы: E-19 (GetMyeBaySelling не называет сайт листинга) и E-20 (поля и статусы `getOrders`).
