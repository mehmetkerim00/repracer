## Что утверждается

- Аккаунт eBay родился в тени, продавец назван Commerce Identity, токен — ссылкой `db:` на свой аккаунт.
- Обнаружение — две фазы (Inventory API и Trading GetMyeBaySelling). Каталог: 8 листингов под Inventory API с единицей
  записи, 1 немигрированный (`MIGRATION_REQUIRED`) и 1 аукцион (`INELIGIBLE`) — оба в каталоге без единицы записи.
- Стратегию по данным конкурентов предпросмотр отклоняет причиной `NO_COMPETITOR_SOURCE` [Р-39]. Фиксированная стратегия
  включается на всех 8 листингах.
- Решения пришли от пересчёта по расписанию (`trigger_type = SCHEDULE`). Каждая запись — `SHADOW_HELD`.
- Запросы к модели eBay: токен 1, `inventory_item` 1, `offer` 8, Trading 1. **Записей 0**: единственный
  `bulk_update_price_quantity` в счётчике — положительный контроль в конце прогона, отданный адаптеру напрямую. Непонятых
  моделью запросов 0.
- Выданные токены не найдены ни в ответах консоли, ни в журнале адаптера.

## Что прогон нашёл

1. **Фиксированные и маржинальные цены не пересчитывал никто.** Решения шли только от событий конкурентов, а у eBay их
   нет. Появилась работа планировщика `scheduled-recompute`: единица без решения за сутки, не больше 1000 за заход.
2. **Экран подключений говорил «нашли 0» для eBay** — число бралось из наблюдений, которых у eBay нет. Теперь считаются
   сопоставления из обнаружения.

## Склейка

Граница суток EBAY_DE в миграциях — `TO_VERIFY` [Р-65], и база отказывает даже теневой записи с бюджетом правок.
Поэтому прогон подтверждает её в своей базе суперпользователем. Это расходится с «без склеек» [Р-179]. Решение —
у владельца (см. [ревью](step47-review.md)).
