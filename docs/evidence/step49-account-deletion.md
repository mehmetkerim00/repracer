# Шаг 49, A: приёмник eBay Marketplace Account Deletion [Р-192, E-18]

До ПЕРВОГО боевого вызова eBay приложение обязано принимать уведомления об удалении аккаунтов пользователей eBay или
оформить исключение «Not persisting eBay data». Требование взято из страницы снимка
(`vendor/ebay/2026-09-28/marketplace-user-account-deletion.html`). Мы данные eBay храним, поэтому исключение не подходит.

## Устройство

- **Процесс** `services/ebay-account-deletion`: HTTP-приёмник, `/healthz` и метрики на своём порту, отметка во внешнем
  сервисе [Р-127]. Роль подключения `svc_ebay_deletion` не имеет прав ни на одну таблицу — только EXECUTE на функцию приёма.
- **Проверка подлинности** — по официальному Node.js SDK eBay, закреплённому коммитом
  ([vendor/ebay/event-notification-sdk/SOURCE.md](../../vendor/ebay/event-notification-sdk/SOURCE.md)):
  - заголовок `x-ebay-signature` — base64 от `{alg, kid, signature, digest}`;
  - открытый ключ — Notification API `public_key/<kid>` токеном приложения, кэш на час;
  - подпись — ECDSA с SHA-1 над `JSON.stringify(message)`.

  Официальные тестовые векторы eBay проходят: VALID — подлинное, INVALID и SIGNATURE_MISMATCH — нет. Зависимостей SDK
  нет — всё делает встроенный `node:crypto`.
- **Удаление** — одна функция базы `security.ebay_account_deletion` (0142), владелец — узкая роль:
  - стираются все версии токенов продавца;
  - аккаунт переходит в `DISCONNECTED` без ссылки на секреты;
  - идентификатор eBay (`userId`) заменяется на `deleted:<id аккаунта>`;
  - владельцу уходит CRITICAL-алерт `EBAY_ACCOUNT_DELETED_BY_USER`;
  - в аудит тенанта пишется `channel.ebay_account_deleted_by_user` — триггером, обойти нельзя.

  Журнал `platform.ebay_account_deletion_notice` хранит SHA-256 от `userId`, а не сам идентификатор, 3 года. Повторная
  доставка того же уведомления исполняется один раз.
- **Страж** не даёт менять `external_account_id` ни на что, кроме `deleted:<id аккаунта>`, и только у отключённого аккаунта
  eBay. Без него административная роль с UPDATE на всю таблицу могла бы переписать идентификатор.
- **Что остаётся:** наша история цен по каналу. Это доказательство Omnibus и §11 PAngV [Р-21], хранение по требованию закона
  страница допускает, и идентификатора eBay в ней нет.
- **Развёртывание:**
  - `deploy/ebay-account-deletion`; production-профиль берёт сервис через `extends`;
  - прокси выставляет только `/ebay/account-deletion` на домене консоли (общий фрагмент `snippets.caddy` — его
    импортируют и сервер, и CI);
  - в CI `deploy-smoke.sh` проверяет challenge ЧЕРЕЗ ПРОКСИ с пересчётом хэша.

## Как отвечает обработчик (живой прогон `services/ebay-account-deletion/test/deletion-live.pg.test.ts`)

Настоящий HTTP-процесс, изолированная база, модель eBay по HTTP (токен приложения и `getPublicKey`) со своей парой ключей
ECDSA P-256.

| Запрос | Ответ |
|---|---|
| `GET /ebay/account-deletion?challenge_code=syn-challenge-49` | **200**, `content-type: application/json`, тело `{"challengeResponse":"f5d7d0a9…41e9"}` — 64 hex, SHA-256 от кода, проверочного токена и адреса; первый байт — `{`, без BOM |
| `POST` уведомление о подключённом продавце, подпись eBay | **204**, пустое тело; обе версии токенов удалены, аккаунт `DISCONNECTED`, идентификатор `deleted:<id>`, алерт владельцу, событие аудита |
| то же уведомление повторно (`publishAttemptCount` 2) | **204**; второго алерта и второй строки журнала нет |
| уведомление о другом продавце, подписанное чужим ключом | **412**; у продавца не изменилось ничего |
| подлинное уведомление с подменённым `userId` | **412** |
| уведомление о пользователе, которого у нас нет | **204**; в журнале хэш, удалено 0 |
| ключ Notification API недоступен | **500** — eBay повторит; ничего не удалено |

- Модель eBay: ключ запрошен **один раз** за процесс (кэш).
- В журнале процесса нет ни одного идентификатора пользователя eBay: ни `userId`, ни `username`, ни `eiasToken`.
- Юнит-тесты `verify.test.ts`, 6 из 6: официальные векторы, отказы разбора заголовка, чужой ключ, хэш challenge, форма
  уведомления, конфигурация. Адрес — только публичный https; проверочный токен — 32–80 символов `[A-Za-z0-9_-]`;
  подмена адреса eBay — только на стенде.

## Защиты в базе

Смоук `tests/db/smoke_ebay_deletion.sql`: удаление подключённого продавца, незнакомый пользователь, идентификатор только в
`deleted:`, отказ приёмнику в прямом чтении и удалении, форма журнала — каждое ограничение своей причиной, `TRUNCATE` и
неизменяемость журнала. Строки каталога мутаций Р-192 — 17 мутаций, все пойманы своей проверкой (вместе с Р-189 — 22).

## Что остаётся

- **Регистрация адреса в портале eBay** — с сервером (шаг 38, ч. 2): адрес должен быть публичным https.
- **Два региона** (OQ-239). У приложения один адрес уведомлений, а продавец региона США живёт в своей базе. Пока адрес
  регистрируется в регионе ЕС, и `region-us.env.example` говорит это прямо.
- **Проверка на настоящем eBay** — кнопкой «Send Test Notification» портала, после регистрации адреса.
