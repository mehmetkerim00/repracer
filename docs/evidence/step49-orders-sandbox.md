# Шаг 49: чтение заказов eBay в песочнице — согласие с `sell.fulfillment.readonly`

2026-09-28 владелец дал тестовым продавцом песочницы новое согласие: прежние scope (`api_scope`, `sell.inventory`,
`sell.account`, `commerce.identity.readonly`) плюс `sell.fulfillment.readonly`.
- Обмен кода — 200, `expires_in` 7200, `refresh_token_expires_in` 47 304 000.
- `state` сверен.
- Refresh-токен — только в файле секретов вне репозитория [Р-177].

Чтение `GET /sell/fulfillment/v1/order` токеном продавца. Печатались только статусы, счётчики и названия полей, без
значений, называющих покупателя.

| Запрос | Ответ |
|---|---|
| `filter=lastmodifieddate:[<90 суток назад>..]` (так читает адаптер, EBAY_C17) | **200**, `total` 0, ошибок нет |
| `filter=creationdate:[…]` | **200**, `total` 0 |
| без фильтра | **200**, `total` 0 |

- **Что это закрывает [песочница]:** scope чтения заказов работает; имя поля фильтра `lastmodifieddate` песочница принимает
  (вопрос E-20 — в части имени фильтра).
- **Что не закрывает:** форму заказа и статусы (`lineItemFulfillmentStatus`, `cancelStatus`, `listingMarketplaceId`). Заказов
  у тестового продавца нет — нужен заказ тестового покупателя песочницы на листинг продавца. После него — резервация и экран
  остатков (задача C шага 48).
