# Шаг 50: заказ тестового покупателя в песочнице eBay — что проверилось, а что нет

2026-09-28 тестовый покупатель песочницы купил мигрированный на шаге 39 листинг тестового продавца (`SYN-SKU-39-LEGACY`,
листинг 110590797453, EBAY_DE, 13,49 €, 1 шт.). Касса песочницы не провела оплату по стране доставки — заказ остался
неоплаченным. Всё печаталось по белому списку: статусы, счётчики, синтетические SKU и номера — без данных покупателя.

## Где виден неоплаченный заказ

| Источник | Результат |
|---|---|
| Fulfillment `getOrders` — `lastmodifieddate`, `creationdate` и без фильтра | **200, `total` 0** |
| Trading `GetOrders` (роль продавца, все статусы) | 1 заказ: `OrderStatus=Active`, `CheckoutStatus=Incomplete`, `eBayPaymentStatus=NoPaymentFailure`, `SYN-SKU-39-LEGACY` × 1, сайт покупки US |
| Trading `GetMyeBaySelling` | SoldList — 0; `QuantityAvailable` листинга по-прежнему **4** |

**[песочница]** Заказ с незавершённой кассой Fulfillment API не отдаёт вовсе, и eBay не уменьшает доступное количество
листинга.

## Настоящий адаптер против песочницы

Одноразовый прогон `createEbayAdapter` (окружение SANDBOX, согласие с `sell.fulfillment.readonly`):
- **`readOrderLines`** — 0 строк, 0 пропусков, без ошибок. Путь чтения заказов на живом канале работает, но этого заказа в
  нём нет.
- **`discoverOffers`** — первая попытка упала: `VALIDATION 25709: Invalid value for header Accept-Language.` Песочница требует
  `Accept-Language` у `GET inventory_item`. Спецификация снимка этот заголовок не объявляет — ещё одно расхождение [док] против
  [песочница] (E-23), и модель стенда тоже его не требовала.
  - Исправлено: REST-вызовы адаптера шлют язык первой витрины аккаунта (`de-DE` проверен песочницей, `en-US` для EBAY_US —
    (проверить)). Модель симулятора отвечает без заголовка так же, как песочница. Юнит-тест утверждает заголовок.
  - Повтор: обе фазы прошли — 2 листинга под Inventory API (`writable`) и аукцион (`INELIGIBLE`) из Trading.
- У мигрированного листинга в предложении нет `availableQuantity` (`null`), хотя Browse показывает 4 шт. Обратное чтение
  количества такого листинга по предложению ничего не подтвердит — вопрос к следующему шагу.

## Что не проверилось из-за неоплаченного статуса

- **Форма строки заказа в Fulfillment API**: `lineItemFulfillmentStatus`, `cancelStatus`, `listingMarketplaceId`, `sku`,
  `quantity`. В ответе нет ни одного заказа, поэтому белый список EBAY_C17 на настоящем заказе не проверен (E-20 остаётся).
- **Резервация и экран остатков**: конвейер «заказ канала → резервация» читает Fulfillment. Строки нет — нет и резервации.
  Это согласуется с тем, что eBay количество не уменьшил: неоплаченный заказ остаток канала пока не занимает.
- **Отгрузка и отмена** — нечего отгружать и отменять.

Чтобы довести проверку до резервации, нужен ОПЛАЧЕННЫЙ заказ. Например, покупатель с адресом доставки в стране витрины
(DE для EBAY_DE), если касса песочницы её пропускает.
