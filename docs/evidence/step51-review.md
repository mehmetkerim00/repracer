## Критичная — исправлена

1. **Со второй страницы заказы Amazon терялись.**
   - Адаптер слал в `searchOrders` один `paginationToken`, а модель требует на странице те же параметры, что у первого запроса («All other parameters must be provided with the same values»). Итог — отказ канала либо ответ без набора FULFILLMENT, и тогда все заказы страницы пропускаются. У продавца больше 100 заказов за окно: резерваций нет, отгрузки не списываются — перепродажа.
   - Стенд прятал дефект трижды: модель по токену восстанавливала исходный запрос, фикстура записывала неверный запрос, проверка запросов страниц не смотрела.
   - Исправлено во всех четырёх местах: модель сверяет параметры страницы и берёт `includedData` из текущего запроса.

## Существенные — исправлены

2. **Отказ формы пакета EBAY_C18 без повтора: количество пробы застревало.**
   - Первая редакция перестала повторять ответ 400 на форму пакета. У записей количества следующей версии нет, пока не изменится остаток.
   - Отказ формы — не отказ значения. Он снова переотправляется по одному SKU, в пределах трёх попыток. Это приспособление к названному ограничению, а не повтор после сбоя.
3. **Любой 4xx eBay навсегда терял запись количества.**
   - Пересчёт остатков сравнивал с последней созданной версией, включая отвергнутую каналом.
   - Теперь версия `DISCARDED_STALE` или `NOT_APPLIED` значением канала не считается, и пересчёт создаёт её снова. Тест на PostgreSQL падает без правки.
4. **Бюджет приложения `searchOrders` был бюджетом одной пары на все аккаунты процесса.**
   - Уже два аккаунта с чтением заказов раз в 5 минут исчерпали бы его за часы.
   - Неизвестный лимит приложения больше не равен лимиту пары: только ведро пары, превышение приложения покажет 429 канала. Тест: два продавца по 20 вызовов.
5. **Правило канала во встроенной отправке пути решения не держал ни один тест.**
   - Сценарий `ebay/pipeline/write-429-not-retried` на памяти и PostgreSQL: запись на 429 — `DISCARDED_STALE`.
   - Проверено подменой: без правила сценарий падает.
6. **FBA при обратном чтении не блокировал единицу.** Сверка час повторяла чтение, потом блокировала с кодом `OUTCOME_UNRESOLVED`. Теперь `PRECONDITION_FAILED` по элементу блокирует сразу со своим кодом, тест перехода. Отказ сервера токенов (уровень аккаунта) по-прежнему сверяется.
7. **Прочитанное количество FBA никто не использовал.** Текст AMZ_C13 и документов исправлен: читается в предложение обнаружения, в базу и на экраны пока не доходит — отложено.
