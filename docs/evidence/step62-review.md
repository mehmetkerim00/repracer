# Ревью шага 62 — отложенный список шага 61 [Р-202]

Ревьюер читал код, ничего не запускал. Найдено **5 находок: 0 критичных, 1 существенная, 4 мелких**. По правилу скорости существенная
исправлена в шаге, мелкие вынесены в отложенный список следующего шага.

Проверено ревьюером, дефектов нет:
- чтение после advisory-блокировки видит зафиксированное состояние (новый снимок на каждый оператор PL/pgSQL в READ COMMITTED);
- новое определение `record_channel_observations` сохраняет владельца, права и тело 0158;
- у роли каталога есть право на `write_scope` и политика;
- проверки блокировки через `pg_locks` не пустые (ключ 202 берут только два стража);
- тест «после отзыва — не внешняя правка» не тавтология;
- все отказы базы разобраны хранилищем;
- код `QUANTITY_WRITE_NOT_SENT` есть в словаре на обоих языках.

## Существенная — исправлена

1. **Блокировку строки аккаунта `FOR UPDATE` снимать было нельзя как дубль.** Она упорядочивала ещё и ответ «обновляет ли другой
   инструмент остатки», а ответ advisory-блокировку не берёт.

   Гонка:
   - транзакция A пишет ответ «остатки», ещё не зафиксирована;
   - транзакция B (подтверждение) читает прежний ответ «нет» и все проверки проходит;
   - применение B ждёт фиксации A и ложится поверх ответа «остатки»;
   - страж аккаунта смотрел только на СМЕНУ ответа, а в применении ответ не меняется.

   Итог — подтверждено и «остатки ведёт другой инструмент» одновременно, то есть два писателя.

   Исправление (0162): страж аккаунта проверяет «подтверждено + остатки ведёт другой» на ИТОГОВОЙ строке при любом изменении любого из
   двух столбцов, в том числе при применении подтверждения журналом. Повторное чтение строки после ожидания (EvalPlanQual) видит чужой
   ответ, и подтверждение отказывает.

   Проверка — смоук `a confirmation applied over another tool managing stock` (`smoke_append_only.sql`): страж журнала выключен на время
   проверки, и отказать обязан страж аккаунта. Строка каталога шага 62: мутация «проверять только при смене ответа» ловится этой проверкой.
   `FOR UPDATE` остаётся снятой: очередь выдачи и отзыва держит advisory-блокировка, а гонку с ответом — проверка итоговой строки.

## Мелкие — отложены

2. Проверки блокировки через `pg_locks` не сверяют ключ (`objid = hashtext(аккаунт)`): мутация ключа (например, хэш тенанта) не
   поймается. Заголовок 0162 обещал «проверку настоящей гонкой двух сессий» — формулировка исправлена в шаге, это ложное утверждение
   о своей же проверке.
3. Гонка отзыва с включением синхронизации: страж единицы читает признак подтверждения без блокировки. Единицы, включённые одновременно
   с отзывом, могут остаться с `quantity_sync_enabled = true`. Отправку держит страж отправки, но записи создаются и снимаются, а внешние
   правки снова считаются. Предложение: разделяемая блокировка 202 и в страже единицы.
4. Для записи количества диспетчер по-прежнему поднимает `PRICE_WRITE_NOT_SENT` и `PRICE_WRITE_SCOPE_BLOCKED` в других случаях (бюджет,
   блокировка единицы): находка 6 шага 61 закрыта только для отзыва. Предложение: имя кода по полю записи.
5. Хранилище берёт исключительную блокировку аккаунта до проверки роли: отказ «не владелец» ненадолго задерживает захваты диспетчера
   на этом аккаунте. Безвредно.
