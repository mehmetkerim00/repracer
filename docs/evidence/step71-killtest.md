# Шаг 71: kill-test — отчёт решений по файлу каталога клиента

Р-206. Первому пилотному клиенту предлагаем прислать файл каталога; мы прогоняем его через тень amazon.com и возвращаем английский
отчёт «вот решения по вашим товарам, каждое с причиной». Как пользоваться — [docs/killtest.md](../killtest.md).

## Что сделано

- `scripts/killtest` → `tests/contract/src/killtest/main.ts`: файл клиента (CSV, TXT с табуляцией, XLSX) → каталог → одноразовый мир →
  отчёт. Синтетический каталог для показа без клиента — `--make-sample simple|listings|business`.
- `killtest/catalog.ts` — колонки по ТАБЛИЦЕ названий (`COLUMN_ALIASES`), неизвестные игнорируются и перечисляются в отчёте; чтение
  байтов, кодировка и суммы — тем же `readTable` и `parseMoneyMinor`, что у импорта себестоимости [Р-134]; негодная строка — своей
  причиной и номером строки файла.
- `killtest/world.ts` — база из шаблона, посев `seedPricingWorld` с аккаунтом в тени [Р-169], модель порта Amazon с одним конкурентом на
  товар, настоящий путь решения (`createPricingPipeline`) на виртуальных часах. Без себестоимости товар сеется выключенным [Р-131].
- `killtest/report.ts` — сводка, топ-15 решений с «почему эта цена» словами словаря консоли, «что мы НЕ сделали и почему», товары без
  себестоимости, негодные строки, чем прогон отличается от боя, как прогон устроен.

## Проверка

`tests/contract/src/killtest-catalog.test.ts` (без базы) и `tests/contract/src/killtest.pg.test.ts` (PostgreSQL), обе в быстрой области.

| Тест | Что утверждает |
|---|---|
| три варианта колонок | один и тот же синтетический каталог 300 строк читается из трёх выгрузок одинаково: «простой шаблон» (запятая), отчёт о листингах (табуляция, лишние колонки, без себестоимости), «Business Report» (кавычки, `$1,234.56`, лишние колонки, пять негодных строк — каждая своей причиной и номером строки) |
| файл без колонок | отказ `MISSING_COLUMNS` с принятыми названиями; нечитаемые себестоимость и остаток — пометка строки, а не отказ |
| от файла до отчёта «как руки» | `scripts/killtest` дочерним процессом, `--keep`; числа сводки = ПЕРЕСЧЁТ по базе прогона своими запросами (решения, изменения, «встала на пол», удержанные тенью, отказы ниже пола маржи); ни одного боевого решения, ни одной записи со временем отправки, ни одного вызова записи модели порта; разделы отчёта; разбивка удержаний «допущенный минимум / пол маржи» сходится с целым; товары ниже пола маржи — по своей себестоимости клиента; отказ показан как отказ; период продаж — из заголовка; ни одного внутреннего имени из СВОЕГО списка теста; ни одного внешнего ресурса; база удалена командой, которую напечатал прогон |
| уборка баз | прогон удаляет свою базу; база прогона старше суток удаляется следующим запуском, моложе суток — нет |
| прерывание | SIGTERM после посева: код 143, база удалена, отчёта нет |
| приватность | путь внутри репозитория — отказ до чтения; ссылка снаружи внутрь репозитория (на файл и на каталог, в том числе ещё не созданные подкаталоги) — отказ; другой регистр букв на macOS — отказ; игнорируемый git путь и путь вне репозитория — принимаются |
| утечки | восемь видов внутреннего кода находит каждый своим правилом; заголовок клиента «price» не прячет наш `min_price` (прежняя редакция прятала); строки клиента с подчёркиванием утечкой не считаются |

Локально (машина разработчика, PostgreSQL 16): 2 из 2 и 5 из 5; первый тест — 17 с (4 виртуальных часа, 300 строк). Проверка типов — 0
ошибок, полнота сборки — 144 файла, правила репозитория — 21 из 21.

Своих защит шаг 71 в базе не заводит (миграций нет), поэтому каталог мутаций не расширяется [Р-108]. Защиты команды проверены мутациями
руками — каждая поймана СВОИМ утверждением:

| Мутация | Поймана |
|---|---|
| сравнение текста пути вместо настоящего | «a report through a link into the repository» |
| без учёта регистра на macOS | «another letter case on a case-insensitive file system» |
| прерывание не удаляет базу | «the interrupted run left no database» |
| уборка старых баз выключена | строка журнала об удалённых базах не напечатана |
| уборка удаляет и свежие базы | «a database of a run younger than a day is left alone» |

## Что нашёл прогон

**Цена ниже пола маржи не поднимается до пола — она отклоняется.** Синтетика получила товары с себестоимостью 80 % цены (каждый 25-й),
чтобы проверить фразу отчёта «движок поднял бы их цену». Прогон показал обратное: стратегия при цели ниже границы встаёт на `min_price`
(CAP), а пол маржи держит итоговая проверка ОТКАЗОМ [Р-44] — `BELOW_MARGIN_FLOOR`, цена остаётся прежней, хотя она уже ниже пола маржи.
Первая редакция отчёта обещала клиенту подъём, которого движок не делает. Отчёт теперь говорит: «движок отказывает любой цене ниже пола
для них и двигает цену, только когда конкурент даёт место на полу или выше; сам он цену не поднимает». Поднимать ли цену до пола маржи
самой стратегией — вопрос владельцу OQ-250.

## Пример отчёта на синтетике

`scripts/killtest --make-sample business --out .killtest/out/sample-business.csv`, затем
`scripts/killtest --in .killtest/out/sample-business.csv --out .killtest/out/sample-report.html` (12 виртуальных часов, умолчания):

| | |
|---|---|
| строк в файле | 300 (5 негодны) |
| в движке | 266 (29 без себестоимости — движок для них не запускается) |
| решений | 2926 |
| изменили бы цену | 2434 |
| цена встала на пол | 283 — все на допущенном минимуме |
| отказано ниже пола маржи | 61 (6 товаров с ценой ниже пола маржи уже сейчас) |
| удержано тенью | 2434 |
| отправлено в Amazon | 0 (записей со временем отправки — 0, вызовов записи модели порта — 0) |
| время | 96 с на машине разработчика под нагрузкой |

Сам отчёт и файл — в `.killtest/out/` (игнорируется git): в репозиторий не попадают ни файл клиента, ни отчёт, даже синтетические.

## Ограничения

- Только amazon.com и доллары; цена в евро — строка «не годится» с причиной.
- Конкуренты — модель: один на товар, ступени одной формы. Числа о поле — свойства симуляции, отчёт так их и подписывает.
- Границы, комиссия и маржа допущены; в пол не входят сборы FBA, минимальная комиссия, closing fee, доставка.
- Отчёт — решения, а не прогноз выручки.
- Названия колонок Seller Central не подтверждены снимком — (проверить) на первом настоящем файле.
- Отложенные находки ревью — [step71-review.md](step71-review.md).
