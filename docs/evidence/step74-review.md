# Ревью шага 74

Два ревьюера параллельно: запрос по любому входу пола [Р-211]; пауза лестницы, уведомление о её старте, ручная поправка суток и правка
теста хаоса [Р-212]. Код читали по `git diff`, тестов с базой не запускали. **23 находки: 0 критичных, 7 существенных, 16 мелких.**
Существенные исправлены, у каждой своя проверка; одна из них (граница роли доставки) — решение, записанное в ADR-0052; мелкие — дешёвые
исправлены, остальные отложены.

## Р-211: любой вход пола (9: 4 существенные, 5 мелких)

| № | Важность | Находка | Итог |
|---|---|---|---|
| 1 | существенная | Рост `max_price` запроса не ставил, хотя пол маржи действует, только пока он не выше `max_price`: продавец, поднявший максимум после отказа «пол маржи выше максимума», ждал наблюдения конкурента | **Исправлено**: триггер на `max_price`, повод `BOUNDS_UPDATE` у обеих границ («after your min_price or max_price changed»); тест и мутация |
| 2 | существенная | «Почему эта цена» называла повод оценки «cost changed» при любом входе | **Исправлено**: «себестоимость» только у себестоимости, прочие входы — плановая проверка, а вход называет объяснение подъёма |
| 3 | существенная | Ветка курса выбирала себестоимость без витрины — не как контекст решения | **Исправлено**: своя себестоимость аккаунта — с витриной предложения |
| 4 | существенная | Ежедневный курс ЕЦБ ставил запрос всему каталогу с себестоимостью в другой валюте, и продолжения лестниц стояли за этой очередью; функция обходила все единицы и без новых курсов | **Исправлено**: курс — запрос только у единиц, чей пол он поднял (отношение курсов валюты цены и себестоимости); продолжения лестниц — первыми в выборке захода; заход без новых курсов и ставок единиц не обходит. Тест: курс, опустивший пол предложения с себестоимостью в долларах, запроса не дал; мутация направления поймана |
| 5 | мелкая (для НДС существенная) | Отметка по времени действия строки: ставка, вставленная задним числом, и курс, загруженный транзакцией, открытой во время захода, пропадали | **Исправлено**: отметка — по ключам (действующий курс каждой валюты, дата действующей ставки каждой страны), как их выбирает контекст решения |
| 6 | мелкая | Повод называет вход, который разбудил переоценку; НДС товара ставил запрос предложениям другой страны | **частично**: НДС товара — только витринам страны ставки; прочее отложено |
| 7 | мелкая | Сбой функции платформенных входов ронял весь заход пересчёта | **исправлено**: журнал предупреждения, заход продолжается |
| 8 | мелкая | Не покрыты ветки `min_price` товара, гардрейлы тенанта, аккаунта и товара | отложено |
| 9 | мелкая | Словарь поводов не типизирован; первый заход после выкатки не видит курсов между последней оценкой и выкаткой | **частично**: словарь типизирован перечнем поводов; первый заход — отложено |

## Р-212: пауза, уведомление, поправка суток, хаос (14: 3 существенные, 11 мелких)

| № | Важность | Находка | Итог |
|---|---|---|---|
| 1 | существенная | Каждая оценка внутри паузы поднимала WARNING «текущая цена вне границ» с советом проверить правку в кабинете — десятки алертов на лестницу | **Исправлено**: пауза лестницы этот алерт не поднимает (Gate); тест Gate и утверждение на PostgreSQL |
| 2 | существенная | «Один раз на лестницу» не выполнялось: теневая ступень гасила уведомление первой боевой, вторая лестница тех же суток не уведомляла | **Исправлено**: учитываются только боевые ступени; старт — ступень не от цены, до которой дошла прошлая ступень. Тест: вторая лестница тех же суток — второе уведомление |
| 3 | существенная | Роль доставки писем читает в событии цену и пол предложения, хотя 0120 говорит «не видит цен» | **Решение, записанное в ADR-0052**: суммы — требование текста уведомления владельца; таблиц цен и решений роль не читает; 0120 в main не правится |
| 4 | мелкая | Подзапрос последней ступени без отсечения секций | **исправлено**: фильтр по времени намерения |
| 5 | мелкая | Допуск в минуту действовал и для наблюдений конкурента | **исправлено**: только для оценки пересчёта; тест движка |
| 6 | мелкая | Период 15 минут — в трёх местах без связи (описание канала, планировщик, текст kill-test) | отложено |
| 7 | мелкая | Пауза снимала запрос базы — следующая ступень теряла повод | **исправлено**: запрос ждёт паузы |
| 8 | мелкая | Письмо называет предложение кодом единицы канала, а не подписью K10 | отложено |
| 9 | мелкая | Правило словаря не проверяет подробность в обоих языках | не нужно: форма словаря одна у обоих языков, тип проверяет |
| 10 | мелкая | Зеркало в памяти: последняя ступень без окна суток | **исправлено** |
| 11 | мелкая | Уведомление при исчерпанном бюджете; вне транзакции фиксации | **частично**: при исчерпанном бюджете не поднимается; вне транзакции — отложено |
| 12 | мелкая | Тест поправки суток мог не отличить поправку от свёртки (скрытый вход «время суток») | **исправлено**: число ступеней поправки заведомо не число ступеней суток |
| 13 | мелкая | Хаос: готовым засчитывался умерший процесс с любой причиной; строка готовности искалась в кольце вывода | **исправлено**: только убитый SIGKILL после строки готовности; флаг процесса |
| 14 | мелкая | `ladder_steps` ручной поправки ничем не ограничено | отложено |

Проверено ревьюерами без находок: безопасность функции платформенных входов (SECURITY DEFINER, `search_path`, владелец, EXECUTE только
у пути решения, 0183), граница тенанта и права, отметка (регистрация, удаление с тенантом, гонка заходов), вставка запросов; подстановка
`$2` во всех трёх местах `SCOPE_COLUMNS`; пауза не останавливает лестницу навсегда и не обходится; представление итога суток совпадает с
0101; тесты краснеют без своих защит; типы.
