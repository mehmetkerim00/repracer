# Шаг 76: предполётный прогон демо перед первым живым показом

Задание: прогнать `scripts/demo-prepare.sh` начисто, пройти [docs/demo-script.md](../demo-script.md) как показ — каждый шаг, экран,
время — и чинить всё, что царапает; чеклист дня показа — [docs/demo-preflight.md](../demo-preflight.md) (там же вопросы зрителя по
экранам).

**Как проходили.** До этого шага сценарий сверялся через HTTP API стенда, а React не исполнял никто. Теперь — настоящим браузером:
безголовый Chrome по протоколу отладки открывает `http://127.0.0.1:5173`, нажимает те же кнопки, что ведущий (вход, карточка мира,
меню, «Stop…», заметка, «Yes, stop», «Resume…», «Yes — stock», «Switch on live writes»), снимает каждый экран и его текст, меряет время
до готовности. Скрипт прохода — вне репозитория (одноразовая репетиция); то, что из прохода стоит держать всегда, стало правилом и
проверками подготовки.

## Что осталось и почему не чинилось

- У товаров Kaufland демо минимальная маржа не задана: пол = min_price €12.00 при себестоимости €10.75, и экран границ честно
  показывает маржу на полу −€2.47. Это свойство демо-мира шага 34, а не дефект экрана; менять экономику демо за два дня до показа —
  риск для прогонов суток демо и тени. Вопрос «ниже себестоимости» показывается на amazon.com (минимальная маржа 12 %), а если зритель
  откроет Kaufland — это ответ: без минимальной маржи пол — только min_price, и экран видит убыток до цента. В [deferred.md](../deferred.md).
- Строки товаров США на экране остатков — с нулями: источник остатков демо ведёт каталог Kaufland. Обход — флажок «Only products with
  reservations». В [deferred.md](../deferred.md).
- Аккаунт Amazon ЕС, ожидающий доступа, на экране тени стоит с полем «Switch on live writes», а не с пометкой «waiting for access».
  В [deferred.md](../deferred.md).
- Журнал стенда предупреждает `client.query() when the client is already executing a query` (pg 8): где-то запросы одного соединения
  идут одновременно. На экранах не видно; разбор — в [deferred.md](../deferred.md).
