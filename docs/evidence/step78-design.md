# Шаг 78: дизайн, второй заход — полировка по скриншотам и отложенное шага 77

Логика не тронута, кроме названного в задании (группа ленты «удержано тенью» — п. 16). Снимки «до» — снимки «после» шага 77
([step77-design/after-en/](step77-design/after-en/), [step77-design/after-de/](step77-design/after-de/)); «после» шага 78 — каталог
[step78-design/](step78-design/): `after-en/` (19 экранов), `after-de/` (9 экранов сценария показа), `dialogs-en/` (окна подтверждения и
предпросмотр стратегии). Проход — безголовым Chrome на демо-стенде после перезапуска на коде шага, окно 1440 × 1600 (окна — 1440 × 900).

## Что сделано

**Strategies (п. 1–4).** Карточка стратегии: заголовок — имя для человека («Buy Box»; посев мира Kaufland давал стратегии имя
сценария `st-buybox` — у посева теперь необязательное `strategyName`), тип — приглушённо и только если имя другое; вместо стены
подписей через запятую — сводка «200 offers · kaufland.de» (несколько витрин — «kaufland.de 120 · kaufland.at 80») и ссылка «Show
offers», раскрывающая примеры списком с «and 190 more — see Products». Число по витринам считает база одним запросом вместе с
использованием стратегии (`consoleCatalogFacts.strategyUsage.storefronts`), путь без фактов — тем же правилом по каталогу мира; равенство
путей держит прежний тест (`console-screens-targeted.pg.test.ts`). Кнопки — «New version», «Assign»; строка версий — «v1 · active · you ·
Oct 11, 04:45». Заголовок предпросмотра не повторяет имя («Buy Box · Buy Box» → «Buy Box»).

**Products (п. 5–9).** Одна колонка действий: основная «Why this price →», под ней мелкая «Bounds»; номер товара канала — приглушённо,
состояние — отдельной пилюлей; пол — «€12.00» и одной вторичной строкой «from your minimum price»; стратегия — пилюля источника и
короткое имя, подробности — подсказкой; лёгкая зебра строк.

**Вход (п. 10, 11, 18).** У каждой роли свой знак (Ow, Ad, Op, PM, Vw), карточки по три в ряд, неполный ряд — по центру (3 + 2);
подписи ролей — словарём на языке экрана: «Anmelden als Inhaber / Administrator / Operator / Preismanager / Betrachter».

**Общее (п. 12, 13).** В шапке — только адрес, «Signed in:» — подсказкой. Вступление экрана — подзаголовок в одно предложение, остальное
по «Learn more» (Shadow mode, Channel accounts, Stock, Setup, Omnibus): тексты прежние и целиком в разметке, вступление Omnibus,
важное юридически, сворачивается, а не сокращается.

**Отложенное шага 77 (п. 14–19).**

- **Сырые коды и идентификаторы** (п. 14): `min_price` / `max_price` — словами во всех текстах обоих словарей («your minimum price»,
  «Minimum price», «Ihr Mindestpreis», «Höchstpreis» — с падежами по строкам), «record 9c6b…» → «your setting», «cost profile …» → «as
  you declared it», «decision {UUID}» убран из строки «почему эта цена», «rule set r49.1» убран из заголовка шага, `ANY_OFFER_CHANGED` и
  `buy_box_changed` — словами («notification of a competitor price change»). Заголовки CSV-файлов (`min_price,max_price,…`) — данные
  файла, не тронуты. Правило «путь только остатков не говорит о ценах» (`stock-only-live.pg.test.ts`) держит теперь и новые слова
  («Mindestpreis», «minimum price»), иначе оно ослабло бы молча. Отчёт kill-test, где минимальная цена — допущение прогона, говорит
  «the minimum price», а не «your».
- **Даты внутри фраз** (п. 15): `m.when` — «Oct 11, 2026, 04:45 UTC−7» / «11. Okt. 2026, 04:45 UTC−7», `m.date` — «Oct 4, 2026» /
  «4. Okt. 2026»; без секунд, с годом (год не выводится из «сейчас» — строка разбирается без часов системы); таблицы показывают её без года
  и с «·», строка версии — без года и пояса. Письма алертов и дайджеста — тем же форматом.
- **Счётчики ленты** (п. 16): удержанное тенью — своя группа `SHADOW_HELD` в правиле групп (`feedGroupOf`), в памяти и в запросе базы
  (`feedPage`): «Held by shadow mode 513 · applied 0 · in progress 0 · not sent 0 · replaced 0», фильтр «held by shadow mode».
  Утверждение — в прогоне демо США на PostgreSQL (счётчик, фильтр ровно по счётчику, в «replaced» удержанного нет), отрицательный
  контроль — без группы в запросе базы прогон краснеет «superseded 513».
- **Поле даты Omnibus** (п. 17): своё поле даты и времени на языке экрана (EN «mm/dd/yyyy hh:mm», DE «TT.MM.JJJJ hh:mm») вместо
  родного `datetime-local`, который говорил на языке браузера; значение наружу — тот же вид, логика формы прежняя; неверный ввод
  называет формат. Так же — даты выгрузки доказательства.
- **Роли стенда на немецком** (п. 18) — см. «Вход».
- **Снимки окон** (п. 19): `dialogs-en/` — раскрытый список предложений стратегии, предпросмотр стратегии на 50 предложениях, окно
  «Save and assign to 50 offers?», окно остановки аккаунта, набранное имя для перевода в бой (кнопка становится основной), экран
  различий массовой правки границ, проверка скидки Omnibus с датой в формате языка. Окна открыты и отменены — ничего не применено;
  предпросмотр и экран различий — задания без записи.

Попутно: полоса хода задания — цвета акцента, а не системная; колонка предложения в предпросмотре стратегии — своей ширины; пилюля
глубины истории Omnibus — знаком без точки.

  в поясе тенанта), демо США 5 из 5 (с новыми утверждениями ленты), kill-test 7 из 7;

  «record …» в тексте ни одного экрана нет.
