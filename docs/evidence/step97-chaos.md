## Механизм

Задание `STOCK_IMPORT` (`packages/bulk-jobs/src/handlers.ts`) делает две **разные транзакции**: инвентаризацию пула (`importStock`) и пересчёт
публикуемого количества (`recalculate`), который и создаёт запись в канал. Пересчёт шёл только по товарам, у которых остаток ИЗМЕНИЛСЯ.
Исполнитель, убитый между транзакциями, оставляет пул изменённым без пересчёта; после истечения аренды задание повторяется тем же файлом,
но тот же файл уже ничего не меняет — «изменившихся» нет, пересчёт не зовётся никогда. Цель стала 14, в канале 22, записи нет. Inbound API
это правило знал давно: при каждом вызове пересчитываются все узнанные товары; заказы — с шага 57 (товары всех сопоставленных строк).
