# Шаг 98: мутационная проверка затронутых строк каталога

Шаг 98 [Р-222] переписал стражи «только владелец» (теперь «владелец или менеджер»), убрал наблюдателя из набора ролей, заменил страж смены
роли гостя ограничением `membership_guest_role` и переименовал смоук-проверки, где наблюдатель служил участником без права. Прогнаны
все строки каталога, которые шаг задел (16 строк), — `node scripts/db/mutation-check.mjs --only '…'`, локально, на базе из
`scripts/db/prepare.sh` с миграциями 0191 и 0192. Полный каталог — полному прогону CI.

## Первый прогон — 150 мутаций, не поймана своей проверкой одна (Р-98)

Мутация «перепривязку входа делает любой участник» (снять `m.role IN ('OWNER', 'MANAGER')` в `security.invite_relink`) ловилась только
другой причиной: проверка `identity.pg.test.ts` «only an active owner or manager relinks» целилась во вход ВЛАДЕЛЬЦА, и отказывала новая
ветка «вход владельца перепривязывает только владелец». Проверка перенацелена на вход обычного участника (менеджер цен) — ветка владельца
проверяется своей строкой «шаг 98 (Р-222)» в `roles-step98.pg.test.ts`.

## Повтор строки Р-98 — 10 из 10

Итог по затронутым строкам — **150 из 150 своей проверкой**. Новые защиты шага в каталоге:

- `membership_role_check` (наблюдателя нет) — смоук «an owner invites a member as a viewer (Р-222)»;
- `membership_guest_role` (техническая роль гостя — только у гостевого членства) — смоуки повышения гостя и приглашения человека гостем
  (строка Р-160, вместо удалённого стража-дубля `b_membership_guest_stays_guest`);
- ветка «вход владельца перепривязывает только владелец» — `roles-step98.pg.test.ts`.
