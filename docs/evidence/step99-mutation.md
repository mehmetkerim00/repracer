# Шаг 99: строки каталога мутаций (миграции 0193–0194, Р-224, Р-225)

Прогон `node scripts/db/mutation-check.mjs --only 'шаг 99 (Р-224, журнал);шаг 99 (Р-224, значения);шаг 99 (Р-135, Р-143, Р-145);Р-145;Р-143 (шаг 32, D);Р-139'`

(`security.read_only_job_kinds()`, `security.file_producing_job_kinds()`, `security.bulk_job_cancel_action(text)`, ограничения
и сумма файла `tenant_data.bulk_job_artifact`). **68 из 68 мутаций пойманы своей проверкой**, ложных строк 0.

**Первый прогон нашёл дыру** (67 мутаций, 1 поймана не своей причиной). Мутация «снять условие `AND j.params ? 'checkJobId'`» —
строку «применено» пишет задание правки границ каталога, у которого нет примерки, — краснила тест, но не значением «строка принята»,
которое и означает «защиты нет» [Р-99]. Разбор показал, что страж журнала сравнивал вид строки с видом задания выражением, которое у задания чужого вида
(не примерка и не применение импорта: `CASE` без ветки) давало NULL, а `IF NOT NULL` в PL/pgSQL не срабатывает: задание выгрузки
доказательства (`PRICE_EVIDENCE`) с параметром `checkJobId` записало бы строку журнала «применено». Условие обёрнуто в
`coalesce(…, false)`, рядом — тест «a job of another kind writes no run even if it names a check» и своя мутация
(`coalesce(…, false)` → `coalesce(…, NULL)`), которая теперь краснеет. Второй прогон — 68 из 68.
