# До живого пилота — чеклист

Состояние на шаг 59. Пилот — первый продавец на боевом канале: оператор заводит тенанта и приглашение в панели [Р-167], продавец
подключает канал сам [Р-175], аккаунт живёт в тени [Р-170], в бой его переводит владелец.

**Код, блокирующий пилот, — не известен.** Шаг 58 заявлял «пуст» — ревью шага 58 это опровергло: продолжение чтения заказов после паузы
теряло заказы (исправлено в шаге 59), а неверные числа остатка при источнике Inbound API и возвратах числились «решениями владельца»
(решены и реализованы в шаге 59: Р-199, Р-200). Это утверждение держится до следующего ревью, а не навсегда. Раздел 1 — внешние ходы:
регистрации, доступы, ответы, которых в репозитории быть не может. Раздел 2 — решения владельца. Раздел 3 называет код, который
остаётся, но пилот не блокирует.

## 2. Решения владельца

Приняты в шаге 59 и реализованы: возвраты — Р-199 (OQ-218), отгрузка при источнике Inbound API — Р-200 (OQ-223), закрытие тенанта —
Р-201 (OQ-22). Открытых решений владельца, блокирующих пилот, нет.

## 3. Код, который остаётся и пилот не блокирует — назван явно

| Что | Почему не блокирует |
|---|---|
| OQ-225, OQ-226 — пересеянные демо-тенанты копятся; гость пересеянного демо не получает объяснения | касается публичного демо, не пилота; тридцать демо-тенантов за месяц — объём, а не отказ |
| OQ-222 — включение синхронизации 10 000 предложений идёт минуты в построчных триггерах | включение — фоновое задание [Р-139], продавец видит ход; время, а не ошибка |
| Мелкие ревью шага 57 (4–8, [step57-review.md](evidence/step57-review.md)) — старт консоли при потере блокировки, пометки часов, формулировка границы Р-198, комментарий `test-all` | ни одна не меняет поведения пилота; п. 4 — окно секунд при старте |
