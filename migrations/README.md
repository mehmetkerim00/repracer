# migrations/

DDL-миграции горячего слоя — PostgreSQL. Только схема и служебные функции; ни прикладного кода, ни seed-данных.
Аналитический слой — [schemas/clickhouse/](../schemas/clickhouse/). Слои — [ADR-0004](../docs/adr/0004-storage-tiering.md).

## Требования

- PostgreSQL **16+** (набор проверен на 16 во временном кластере, см. отчёты шагов 3 и 4).
- Расширения не требуются.
- Отдельная база на регион: `repracer_eu`, `repracer_us` [Р-16]. Для каждой задаётся регион:
  `ALTER DATABASE repracer_eu SET repracer.region = 'EU';` — без него тенанта создать нельзя.

## Роли

| Роль | LOGIN | Назначение |
|---|---|---|
| `repracer_owner` | нет | Владелец объектов; DDL, создание и удаление партиций |
| `repracer_app` | нет | Рантайм приложения; видит только строки текущего тенанта |
| `repracer_resolver` | нет | Функции резолва тенанта для входящих событий, ключей Inbound API и входа |
| `repracer_retention` | нет | Удаление по сроку, закрытие тенанта, истечение резерваций; единственная роль с DELETE в append-only таблицах |
| `repracer_exporter` | нет | Чтение транзитных партиций всех тенантов для выгрузки в ClickHouse, архив и брокер; отметки в `maintenance.partition_export` |
| `repracer_dispatcher` | нет | Обход ждущих записей всех тенантов: только идентификаторы, статусы и сроки (`maintenance.due_write_scopes`), без сумм [Р-64] |
| `repracer_relay` | нет | Ретранслятор outbox → брокер: чтение `outbox_event` всех тенантов и свой водяной знак, без бизнес-таблиц [Р-34] |
| `repracer_fx_loader` | нет | Загрузка дневных курсов ЕЦБ в `platform.fx_rate`; курс дня неизменяем [Р-61] |
| мигратор (создаёт ops) | да | Член всех ролей; запускает миграции |

`BYPASSRLS` не используется ни одной ролью.

## Контекст тенанта

```sql
SET LOCAL app.tenant_id = '<uuid>';
SET LOCAL app.user_id   = '<uuid>';   -- если действие пользовательское
```

Без `app.tenant_id` политики не пропускают ни одной строки. Транзакции, меняющие режим цены и `min_price`, — READ COMMITTED
или SERIALIZABLE (см. `0006`).

## Правила для новых миграций

1. Каждая таблица: `tenant_id uuid NOT NULL`, `security.register_table(...)`, строка в `maintenance.retention_policy`,
   `security.grant_retention(...)`; для транзитных таблиц — `security.grant_export(...)`.
2. Ссылки между тенантными таблицами — составные FK `(tenant_id, …_id)`.
3. Нет FK из `tenant_data` в `channel_data`, `audit`, `legal`.
4. Партиционированная таблица ⇔ политика `DROP_PARTITION`. Данные тенанта удаляются по времени только с `requires_export`.
5. Таблицы аналитического слоя (`channel_observation`, `competitor_snapshot`, `channel_write_response`, `fee_actual`)
   в PostgreSQL не возвращаются — проверка схемы (`0023`, `0029`, `0031`, `0033`, `0035`, `0039`, `0041`, `0043`, `0047`, `0050`, `0056`, `0061`).
6. Индекс — только вместе с запросом, который его использует (комментарий над индексом).
7. Последняя миграция набора — проверка схемы; при добавлении таблиц копия проверки переносится в конец (сейчас `0076`).
8. Представление — только `WITH (security_invoker = true)`: RLS применяется от имени читающего (проверка `0029`).
9. Новая защита — строка в каталоге мутационной проверки `tests/db/mutations.mjs` [Р-95]: снятие защиты обязано ронять
   СВОЮ проверку этой мутации с её причиной [Р-99]; падение соседней проверки — непойманная мутация. Каждая append-only таблица
   имеет строку в смоук-мире [Р-103]; новая таблица с записью административной роли объявляет действие в `security.admin_write_action` [Р-100]. Тест защиты сверяет ПРИЧИНУ отказа [Р-94]: `pg_temp.expect_fail(метка, запрос, причина)` в смоук-тестах,
   `assert.match` по тексту отказа в тестах TypeScript. Новое право роли пути решения — только через
   `security.decision_path_allowed_privileges()` [Р-96]; новая таблица с записью административной роли автоматически получает
   стража «действие человека» и аудит [Р-97] (триггеры вешает 0066 по правам; для таблиц, добавленных позже, — повторить DO-блок).
10. Правило проверки схемы проверяет поведение либо не существует [Р-93]: не сверять имена триггеров, ограничений и ключей и текст функций
   (`position(... IN pg_get_functiondef(...))`). Допустимы свойства каталога, которые и есть поведение (RLS, привилегии, реестр, сроки),
   данные справочников и действие в откатываемой подтранзакции с ожидаемым отказом и контрольным успехом (образец — 0061).

## Р-95: мутационная проверка схемы

`scripts/db/mutation-check.mjs` снимает по одной защите (триггер, ограничение, право, условие в теле функции) на копии
шаблона базы и требует, чтобы упала ровно заявленная проверка — с заявленной причиной. Контрольный прогон без мутаций
обязан быть зелёным. Каталог — `tests/db/mutations.mjs`: строки таблицы Р-93 и защиты шага 17.

```
REPRACER_PG_URL=postgres://svc_app@127.0.0.1:55432/repracer_eu \
REPRACER_PG_ADMIN_URL=postgres://postgres@127.0.0.1:55432/postgres \
REPRACER_PG_TEMPLATE=repracer_template node scripts/db/mutation-check.mjs [--only 12,16] [--jobs 2] [--measure]
```

Первый замер (до исправлений шага 17) — [docs/evidence/step17-mutation-before.md](../docs/evidence/step17-mutation-before.md):
ложными оказались 12 строк таблицы Р-93 из 25 с мутациями, не поймано 24 мутации из 55. Итог после исправлений —
[docs/evidence/step17-mutation-after.md](../docs/evidence/step17-mutation-after.md).

## Р-96: права пути решения

Единственный источник прав `repracer_app` — `security.decision_path_allowed_privileges()` (0062): таблица, привилегия,
столбец. Новое право добавляется в эту функцию и нигде больше; проверка схемы `0067` сверяет права в обе стороны
(включая столбцовые) и отдельно — короткий список функций SECURITY DEFINER, доступных пути решения.

## Р-97: административная запись

Таблица, запись в которую есть у административной роли и нет в списке разрешённого, получает страж
`security.require_person_for_admin_write()` (нужен пользователь сессии и его действующее членство в тенанте строки)
и аудит `security.audit_admin_write()` (событие `admin_change.<операция>`). Список таких таблиц вычисляется из прав
функцией `security.admin_only_writes()`; проверка схемы требует, чтобы у каждой строки этого списка были оба триггера.
