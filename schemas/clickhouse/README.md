# schemas/clickhouse/

DDL аналитического слоя [Р-20, Р-22, Р-23]. ClickHouse — только для аналитики, симулятора и бэктеста;
решение о цене его не читает.

## Порядок применения

| Файл | Содержание |
|---|---|
| `001_roles_and_profiles.sql` | База, роли, профили настроек |
| `010_tables.sql` | Таблицы: ключ сортировки с `tenant_id`, месячные партиции, TTL ≤ 18 месяцев |
| `020_row_policies.sql` | Политики строк: изоляция тенантов через `SQL_tenant_id` |
| `030_step6.sql` | Шаг 6: классы intent и NO_OP 7 дней + почасовой агрегат [Р-27, Р-38]; источники и полнота конкурентов Kaufland [Р-36, ADR-0007] |
| `040_step7.sql` | Шаг 7: причина отклонения и источники `max_price` в решениях, запрет округления до границы [Р-43, Р-44] |
| `050_step10.sql` | Шаги 9–10: параметры причины и проверки решения (OQ-98), курс ЕЦБ в решении [Р-61], причина завершения записи [Р-64], валюта и база снимка конкурентов [Р-57]; окно дедупликации вставок экспортёра |
| `060_step14.sql` | Шаг 14: код причины NO_OP в сырье и в ключе почасового агрегата — агрегат пересоздаётся [Р-81] |
| `070_step20.sql` | Шаг 20: почасовой агрегат NO_OP выполняется правами пользователя-определителя (без входа) — роль записи без чтения вставляет NO_OP |
| `080_step23.sql` | Шаг 23: причины отклонения `PRICING_STOPPED` и `CHANNEL_DISTRUSTED` [Р-69, Р-118] — список равен PostgreSQL и коду |
| `090_step24.sql` | Шаг 24 [Р-122, Р-121]: вердикт проверки входов (и `RECONCILIATION` — снимок только для сверки) и доставка снимка (`PUSH`, `PUSH_FETCH`, `POLL`, `SAMPLE`; до шага 24 — `UNKNOWN`) у снимка конкурентов — писатель переносит в `competitor_snapshot` все снимки журнала пути решения |
| `099_verify.sql` | Проверки: каждый запрос должен вернуть 0 строк |

Файлы применяются по порядку администратором кластера региона (EU, US). Скрипты идемпотентны (`IF NOT EXISTS`).
DDL подготовлен к прогону на ClickHouse 26.8.4.11 (`node infra/local/apply-clickhouse.mjs`), **с шага 20 применяется в CI** на ClickHouse 26.8.4.11 вместе с `099_verify.sql` (первый прогон нашёл дефекты: порядок `CODEC`/`DEFAULT` в 050, не применявшийся 060, права вставки через материализованное представление — 070).

## Таблицы

| Таблица | Источник | Класс | TTL |
|---|---|---|---|
| `channel_observation` | брокер (`scope.observation.*`) | данные канала | 18 мес − 14 дней от месяца `received_at` |
| `competitor_snapshot` | брокер (`raw.competitor-snapshot.*`) | данные канала | то же |
| `channel_write_response` | брокер (`raw.write-response.*`) | данные канала | то же |
| `fee_actual` | брокер (`raw.fee-actual.*`) | данные канала | то же, от `posted_at` |
| `price_intent`, `price_decision` | дневные партиции PostgreSQL (экспортёр); только `CHANGED` и `REJECTED_BY_GATE` [Р-27] | данные канала | то же; ядро intent вечно — `tenant_data.price_intent_core` → архив [Р-38] |
| `price_intent_noop` | дневные партиции PostgreSQL (экспортёр), класс `NO_OP` | данные канала | 8 дней от дня `created_at` (сырьё ≥ 7 дней) [Р-27] |
| `price_intent_noop_hourly` | материализованное представление из `price_intent_noop`, ключ — код причины, правило, триггер [Р-81] | данные канала | 18 мес − 14 дней от месяца `hour` |
| `channel_write_completed` | дневные партиции `channel_write_history` (экспортёр) | данные тенанта, аналитическая копия | то же; бессрочно — только архив |

## Правила запросов

- Дубли возможны до слияния частей (`ReplacingMergeTree`, доставка at-least-once): где важна точность — `FINAL`
  или `argMax(..., ingested_at)`.
- Каждый запрос шлюза содержит `WHERE tenant_id = {tenant}` в дополнение к политике строк.
- Табличные функции (`s3`, `url`, `remote`, `file`) и `INTO OUTFILE` для ролей шлюза недоступны.

Изоляция тенантов — [docs/tenant-isolation-analytics.md](../../docs/tenant-isolation-analytics.md).
